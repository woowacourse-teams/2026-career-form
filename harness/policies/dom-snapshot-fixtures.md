# 비식별 DOM 스냅샷 픽스처 수집

## 목적과 경계

실사이트에서 관찰한 자동 기입 실패에 필요한 최소 DOM 구조를 보존하고, 실제 계정과
사이트 서버 없이 재현한다. 공통 양식의 라벨·설명·선택지는 검토 후 보존하지만 실제
지원서 값, 개인화 문구, 계정과 세션 정보는 보존하지 않는다.

이 절차는 개발용 픽스처에만 적용한다. 제품의 서버·LLM 전송 정책과 실사이트 평가
보고서의 기록 범위를 넓히지 않는다. `평가 시작해줘`는 수집 승인이 아니다.
자동 수집 도구 개발, 제품 버그 수정, browser mode 전환은 별도 작업이다.

## 시작 조건

1. 사람이 수집 대상 회사·플랫폼, 실패 영역, 현재 상태와 이번 수집 의사를 지정한다.
   계정·지원서 URL이나 입력값을 요청하지 않는다. 사람이 해당 화면을 직접 준비한다.
2. 작업자는 공개 회사·플랫폼 기반 `site_id`와 익명 필드 ID로 실패 단계, 기대 결과,
   관찰 결과를 적는다. 실제 오류 문구가 값을 포함하면 복사하지 않고 원인을 요약한다.
3. 작업자는 실패에 필요한 최소 컨트롤과 라벨, 반복 행, 소유 컨테이너를 선정한다.
   전체 페이지 수집부터 시작하지 않는다. 상태 전환이 필요하면 사람이 수행한다.
4. 아래 출력 경계를 보장하는 도구인지 확인한다. 보장하지 못하면 다른 수단을
   임의로 우회하지 않고 `수집 중단`과 비식별 사유만 기록한다.

원본 지원서 DOM, 입력값과 선택 상태는 수집 과정에서 변경하지 않는다. 제출·저장·
임시저장·미리보기·페이지 이동·파일 첨부·동의, 계정·시크릿·브라우저 저장소 접근은
수집 절차에 포함하지 않는다.

## 첫 출력 전에 정제

원본은 브라우저 안에만 둔다. 원본 HTML을 내려받아 파일에서 정제하거나, 도구로
반환받은 뒤 답변에서 지우는 방식은 사용하지 않는다. 도구 응답, 대화, Console,
클립보드, 임시 파일, trace, 스크린샷도 영속화 경계에 포함한다.

- 원본 페이지의 DOM/접근성 snapshot, `outerHTML` 반환, 전체 화면 캡처, 페이지 저장,
  HAR와 자동 네트워크·Console 수집은 끈다. 차단할 수 없는 도구에는 페이지를 연결하지 않는다.
- 사람은 페이지 안에서 필요한 공통 텍스트와 구조를 검토한다. 에이전트에게 검토를
  맡기려고 원본을 먼저 전송하지 않는다. 개인화 여부를 확정할 수 없으면 제외한다.
- 브라우저 내부에서 선정 범위의 노드를 순회해 **새 비활성 문서**를 만든다. 원본
  DOM 전체의 복사본을 출력하거나 원본의 속성을 지우지 않는다.
- 노드 종류·속성·텍스트를 각각 검토한 허용 목록으로 옮긴다. 식별자 치환표는
  브라우저 메모리에만 유지하고, 노드 간 참조는 함께 치환한다.
- 실제 control property는 읽어서 반환하지 않는다. 값과 선택 상태는 빈 상태로
  만들고, 재현에 필요한 비어 있지 않음·선택됨 상태는 명시한 합성 상태로 새로 넣는다.
- 정제 후 금지 속성·실행 코드·외부 참조·미검토 텍스트가 남지 않았는지 다시 확인한다.
  검증 실패 시 원본이나 문제 문자열을 출력하지 않고 실패 종류만 반환한다.
- 통과한 결과만 직렬화해 출력한다. 오류 처리도 원본 노드·문자열·예외 객체를
  덤프하지 않는다. 정규식 개인정보 검사만 통과한 결과를 안전하다고 선언하지 않는다.

이 순서는 수집 대상별로 검토하는 일회성 추출 작업의 계약이지 범용 정제기의
명세가 아니다. 추출에 필요한 코드·도구 동작은 실행 전에 사람이 검토한다.
실제 출력 여부를 확인할 수 없거나 필요한 구조를 안전하게 옮길 수 없으면 중단한다.

## 보존 및 제거 표

| 대상 | 처리 |
| --- | --- |
| 일반 태그와 부모·형제·반복 행 관계 | 필요한 최소 부분을 유지한다. 실행성 요소나 사용자 정의 요소는 직접 재실행하지 않는다. |
| 라벨·설명·placeholder·공통 선택지 | 개인화 정보가 아닌 공통 양식임을 사람이 검토한 텍스트만 보존한다. 안내문 안의 이름·지원 건 정보도 제거 대상이다. |
| `input`/`textarea`/`select`/`contenteditable` | value 속성, 현재 value property, 기본값, textarea 본문, 선택·체크 상태와 편집 본문을 비운다. 필요한 상태는 합성으로 명시한다. |
| 선택지의 label/value | 공통 목록의 의미와 연결을 검토한다. 개인화된 검색 결과는 보존하지 않는다. value 코드도 식별자가 될 수 있으므로 필요한 경우 합성 코드로 일관되게 치환한다. |
| `id`, `name`, `class` | 개인 식별자가 없는 필요한 토큰만 보존한다. 불명확한 토큰은 익명 ID로 치환하거나 제외한다. |
| `for`, ARIA ID 참조, 그룹·행 연결 | 익명 ID로 함께 치환하고 대상 존재와 유일성을 확인한다. 원본에 없던 소유 관계를 보강하지 않는다. |
| `type`, `role`, `readonly`, `disabled`, `required`, `hidden`, `inert`, 제약 속성 | 재현에 필요한 공통 구조인지 검토한다. 실제 사용자 상태를 나타내는 값은 합성으로 대체하고 변경을 기록한다. |
| `aria-label`, `title`, `alt` 및 기타 텍스트 속성 | 본문 텍스트와 같은 검토를 적용한다. 속성이라는 이유로 자동 허용하지 않는다. |
| 숨김 input, `data-*`, 주석, 내장 JSON | 기본 제외한다. 숨김 노드의 구조가 필요하면 값 없는 노드나 명시적 합성 상태만 보존한다. |
| URL, query, fragment, form action, 파일 경로 | 원본을 제거한다. 필요한 참조는 로컬 합성 대상으로 대체하고 원본 대응표는 저장하지 않는다. |
| `script`, inline event, `javascript:` URL, `iframe srcdoc` | 제거한다. 원본 callback·스크립트를 실행하지 않는다. |
| `style`, CSS, link/import, 이미지·폰트·미디어·object/embed | 원본 실행·외부 로드 경로를 제거한다. `url()`, `@import`, `srcset`도 포함한다. 표시용 스타일이 필요하면 검토된 로컬 합성 CSS를 별도로 작성한다. |
| iframe, Shadow DOM, canvas, 동적 위젯 | 수집 가능 범위와 누락을 기록한다. 접근 불가 영역을 채워 넣거나 인증 경계를 우회하지 않는다. 그림 픽셀과 전체 캡처를 대신 저장하지 않는다. |

## 구조 보존 검사

정제 전후의 원본 전문을 저장해 diff하지 않는다. 브라우저 안에서 확인한 관계와
정제 결과의 다음 관계를 대조하고 결과만 기록한다.

- 대상 control 수, 종류, 반복 행 수와 순서
- 라벨 연결과 필요한 주변 문맥
- 참조 ID의 대상 존재·유일성, 팝업/행 소유 관계
- 실패에 영향을 주는 숨김·읽기 전용·비활성 상태
- 필요한 공통 선택지의 개수와 순서

정제 때문에 필요한 관계나 표현이 사라져 실패 조건을 재현할 수 없으면 `재현 불가`로
남긴다. 테스트를 통과시키려고 원본에 없던 ARIA 연결, 완료 marker, 이벤트를 추가한
것을 실제 구조라고 기록하지 않는다. 합성 동작이 필요하면 별도 파일로 분리하고
그 동작을 실제 사이트에서 검증한 것으로 주장하지 않는다.

## 로컬 검토와 등록

1. 정제 결과만 Git 비추적 임시 위치에서 검토한다. 저장 전 허용 검토를 통과했더라도
   등록 전 사람의 개인정보 검사와 구조 보존 검토를 각각 수행한다.
2. [검토 양식](../templates/dom-snapshot-review.md)을 사용한다. 양식은 수집 완료
   근거가 아니며 미확인 항목은 미확인으로 남긴다.
3. 후보 HTML을 네트워크가 차단된 로컬 브라우저에서 연다. 원본 코드·외부 리소스가
   없는지 확인하고 외부 요청 시도가 한 건이라도 있으면 등록을 보류한다. 로컬 재현
   코드를 실행할 경우에도 대상 사이트와 LLM으로 통신하지 않는다.
4. 실제 실패 단계의 기존 함수/테스트를 사용해 오프라인 재현을 검증한다. 테스트는
   구조와 관찰 결과를 검증하며 HTML 전체나 문서 문구를 고정하지 않는다.
5. 재현에 필요한 구조를 제거하거나 변경했을 때 테스트가 실패하는지도 확인한다.
   관찰된 실패와 기대 동작을 나누며, 제품 버그를 이 수집 작업에서 수정하지 않는다.
6. 사람 검토와 재현이 모두 통과하면 `frontend/fixtures/dom-snapshots/<fixture-id>/`에
   정제 HTML, 메타데이터와 검토 결과를 등록하고 관련 테스트에서 사용한다.
7. 일회성 추출 코드의 원본 대응표와 페이지 내부 임시 참조를 폐기하고 작업 소유
   브라우저·서버를 종료한다. 검토용 임시 파일을 정리한 결과만 기록한다.

원본이 잘못 출력됐음을 알게 되면 작업을 중단하고 사람이 노출 경로를 처리하도록
알린다. 원본을 재인용하거나 사람이 만든 파일·Git 이력을 임의로 삭제하지 않는다.

## 메타데이터 계약

HTML과 같은 디렉터리의 `metadata.json`에 다음 키를 기록한다. 실제 값이 없는
검토 양식으로 먼저 준비하고, 수집과 검토를 마친 뒤 JSON을 작성한다.

| 키 | 내용 |
| --- | --- |
| `fixture_id`, `site_id`, `issue_number`, `collected_on` | 비식별 식별자, 공개 회사·플랫폼 식별자, 연결 Issue 번호, 수집일 |
| `provenance` | 직접 정제한 경우 `SANITIZED_SNAPSHOT`, 관찰 후 재작성한 경우 `SYNTHETIC_REPRODUCTION` |
| `installed_revision` | 확인된 설치본 전체 SHA 또는 `UNVERIFIED` |
| `revision_evidence` | 평가 절차의 설치본 확인 방법·상태·비식별 근거. 작업 HEAD로 대신하지 않음 |
| `scope` | 익명 대상과 수집 범위, 포함된 컨트롤·행 개수 |
| `failure` | 관찰한 단계, 기대 결과, 실제 결과, 재현에 필요한 조건 |
| `sanitization` | 제거·치환한 종류와 보존한 공통 텍스트의 검토 결과. 원본값·대응표 없음 |
| `synthetic_behavior` | 추가한 합성 상태·동작. 없으면 빈 목록 |
| `limitations` | 누락 영역, 정제 영향, 동적/서버 동작 등 미재현 범위 |
| `review` | 개인정보 검토와 구조 검토 각각의 결과, 사람 검토 여부와 검토일 |
| `reproduction` | 실행 명령, 제품 코드 revision, 관찰 결과, 변이 검사 결과와 근거 경로 |

합성 예제의 형식 검증은 실제 수집을 입증하지 않는다. `SANITIZED_SNAPSHOT`은
직접 수집과 검토 근거가 있을 때만 사용한다. 아직 대상이 없으면 메타데이터와
HTML을 수집 완료 형태로 만들지 않는다.

## 결과의 의미

샘플 검증은 정제된 범위에서 기록한 실패 조건의 재현 근거다. 실제 설치 확장,
현재 사이트의 이벤트·서버 동작, 저장·제출 호환성이나 성공률을 입증하지 않는다.
평가 기준선의 `FIXTURE`와 `LIVE_SITE`는 분리하며 결과를 합산하지 않는다.

수집 승인, 저장 전 공통 텍스트 검토, 등록 전 사람 검토, Wiki 지식 후보 digest
승인은 서로 다른 결정이다. 어느 하나를 다른 승인의 대체 근거로 사용하지 않는다.
