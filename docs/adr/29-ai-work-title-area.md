# AI 작업 영역 prefix 도입

## 상태

승인됨

## 날짜

2026-08-18

## 관련 Issue

- #29

## 배경

현행 Issue와 PR 제목은 `FE`, `BE`, `Infra`, `Harness`, `Plan` 영역만 허용한다. 제품의 LLM, 모델, 프롬프트, 에이전트 기능 작업은 독립된 작업 영역으로 분류할 수 없어 Harness 등 다른 영역과 의미가 섞일 수 있다.

## 검토한 대안

- 제품 AI 작업을 Harness로 분류하면 제품 기능과 개발 하네스의 경계가 흐려진다.
- `[AI][Harness]`처럼 복수 prefix를 허용하면 단일 영역 제목과 Issue 및 PR 제목 일치 계약이 복잡해진다.
- 기존 단일 영역 목록에 `AI`를 추가하면 현재 제목 구조를 유지하면서 제품 AI 작업을 구분할 수 있다.

## 결정

1. 작업 Issue와 연결 PR의 허용 영역에 `AI`를 추가한다.
2. 허용 목록은 `FE`, `BE`, `AI`, `Infra`, `Harness`, `Plan`이다.
3. `FE`, `BE`, `AI`는 전체를 대문자로 작성한다.
4. `AI`는 제품의 LLM, 모델, 프롬프트, 에이전트 기능 작업에 사용한다.
5. `Harness`는 개발 하네스, 개발 에이전트 운영 규칙과 공용 워크플로우 변경에 사용한다.
6. 하나의 제목에는 영역 prefix 하나만 사용한다.
7. `Release` 시스템 PR과 기존 제목 기록은 변경하지 않는다.

## 결과

제품 AI 기능과 개발 하네스 작업을 제목에서 구분할 수 있다. 제목 검증기, 정책, 스킬과 사용 안내의 허용 목록을 함께 유지해야 한다. 여러 영역에 걸친 작업은 주된 작업 영역을 사용하고 독립 구현이 필요하면 별도 Project draft 후보로 분리한다.
