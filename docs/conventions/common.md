# 공통 개발 컨벤션

## 변경 원칙

- 입력과 외부 응답은 경계에서 검증하고 실패 이유를 드러낸다.
- 기존 객체를 직접 바꾸지 않고 새 값을 만들어 반환한다.
- 함수는 한 책임에 집중하고 50줄 이내를 목표로 한다.
- 파일은 한 도메인에 집중하고 800줄을 넘기지 않는다.
- 개인정보와 시크릿을 코드, 로그, Fixture에 넣지 않는다.

## 테스트

- 동작 변경 전 실패하는 테스트를 먼저 추가한다.
- 정상 흐름, 실패 흐름, 경계값을 검증한다.
- 전체 테스트 커버리지는 80% 이상을 유지한다.
- 실제 브라우저나 서버 검증이 필요하면 자동 검증과 구분해 PR에 기록한다.
- 실제 채용 지원서의 제출, 임시저장, 페이지 이동, 미리보기는 자동화하지 않는다.

## 파일 이름

- Python 소스와 진입점은 `.py` 확장자를 사용한다. 확장자 없는 Python 파일을 만들지 않는다.

## 완료 기준

- Issue의 인수 조건별 구현 근거가 있다.
- 관련 테스트와 운영체제에 맞는 가상환경 Python으로 실행한 `harness/scripts/verify.py`가 통과한다.
- 범위 밖 변경과 후속 작업이 PR에 기록되어 있다.
- 오류 처리, 보안, 개인정보 노출 여부를 검토했다.
