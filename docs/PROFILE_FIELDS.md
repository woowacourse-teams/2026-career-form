# 프로필 입력 정보 정의

> 사용자가 브라우저에 저장할 취업 정보와 채용 지원서에 자동 입력할 수 있는 범위를 정의한다.

## 문서 목적

이 문서는 `PRODUCT_CONCEPT.md`에서 정한 MVP의 핵심 열 종류 정보를 구체적인 입력 항목으로 나눈 제품 기준서다. 프로필 입력 화면, 로컬 저장 구조, 지원서 필드 매핑, 전용 어댑터와 범용 탐지를 설계할 때 이 문서를 기준으로 사용한다.

입력 항목은 `resume-copy-helper-prototype`의 현재 프로필에서 확인한 12개 섹션과 72개 필드, 이전 자동 입력 프로토타입에서 확인한 주소·병역·보훈·장애 필드를 출발점으로 삼았다. 다만 프로토타입의 모든 필드를 MVP로 가져오지 않고, 현재 제품 범위에 맞춰 다음과 같이 분류한다.

- **MVP 입력 정보:** 기본 인적사항, 연락처와 주소, 학력, 어학, 자격증, 프로젝트, 병역, 보훈, 장애, 건강
- **후속 지원 후보:** 논문, 경력, 해외경험, 수상이력
- **저장하지 않는 정보:** 자기소개서, 제출서류 파일, 동의 항목 등 반복 재사용에 적합하지 않거나 위험한 정보

## 공통 입력 정책

### 필수 여부

- 프로필을 저장하기 위한 필수 항목은 두지 않는다.
- 사용자는 자신에게 필요한 정보만 선택해 등록할 수 있다.
- 비어 있는 값은 자동 입력 후보에 포함하지 않는다.
- 채용 사이트가 요구하는 필수 항목과 프로필의 필수 항목은 서로 다르다. 지원서의 필수 여부는 페이지 분석 결과에서 별도로 표시한다.

### 입력 형식

- 날짜는 가능한 경우 날짜 입력 형식을 사용한다.
- 이메일과 연락처는 각각 이메일, 전화번호 입력 형식을 사용한다.
- 담당 역할이나 활동 상세내역처럼 긴 내용은 여러 줄 텍스트를 사용한다.
- 성별, 국적, 학위구분처럼 사이트마다 선택지가 다른 값은 프로필에 표준 문자열로 저장하고, 자동 입력 시 대상 사이트의 선택지와 매핑한다.
- 사용자가 입력한 문자열의 앞뒤 공백은 제거한다.
- 여러 건을 등록할 수 있는 범주에서는 값이 모두 비어 있는 항목을 저장하지 않는다.

### 자동 입력 허용 상태

- `허용`: 적용 전 미리보기와 사용자 승인을 거쳐 지원서에 입력할 수 있다.
- `조건부`: 사이트의 선택지 또는 입력 형식과 안전하게 매핑된 경우에만 입력할 수 있다. 확신할 수 없으면 `확인 필요`로 표시한다.
- `민감 확인`: 로컬 저장은 허용하지만 일괄 적용 대상으로 기본 선택하지 않는다. 지원 건마다 항목과 값을 공개하고 사용자가 해당 항목을 개별 승인한 경우에만 입력한다.
- `미입력`: 프로필 관리나 자료 탐색을 위해 저장하지만 지원서에는 자동 입력하지 않는다.

모든 `허용` 및 `조건부` 항목에도 `PRODUCT_CONCEPT.md`의 기존 값 보호와 사용자 승인 원칙을 적용한다.

## MVP 입력 정보

### 1. 기본 인적사항

한 사람당 한 세트만 저장한다.

| 필드 ID | 사용자 표시명 | 형식 | 자동 입력 | 설명 |
|---|---|---|---|---|
| `koreanFamilyName` | 국문 성 | 짧은 텍스트 | 허용 | 지원서에 사용할 국문 성 |
| `koreanGivenName` | 국문 이름 | 짧은 텍스트 | 허용 | 지원서에 사용할 국문 이름 |
| `hanjaFamilyName` | 한자 성 | 짧은 텍스트 | 허용 | 지원서에 사용할 한자 성 |
| `hanjaGivenName` | 한자 이름 | 짧은 텍스트 | 허용 | 지원서에 사용할 한자 이름 |
| `englishFamilyName` | 영문 성 | 짧은 텍스트 | 허용 | 지원서에 사용할 영문 성 |
| `englishGivenName` | 영문 이름 | 짧은 텍스트 | 허용 | 지원서에 사용할 영문 이름 |
| `gender` | 성별 | 선택 의미의 텍스트 | 조건부 | 대상 사이트의 선택지와 일치할 때만 적용 |
| `birthDate` | 생년월일 | 날짜 | 허용 | 사이트 형식에 맞게 표시 형식 변환 가능 |
| `nationality` | 국적 | 선택 의미의 텍스트 | 조건부 | 국가명 또는 국가 코드와 안전하게 매핑할 때만 적용 |

모든 이름 필드는 선택 입력이며 사용자가 입력한 원문을 보존한다. 분리형 지원서에는 대응하는 성과 이름을 직접 매핑한다. 전체 국문·한자 이름은 각각 `성+이름` 순서로 공백 없이 조합한다. 전체 영문 이름은 대상 사이트가 요구하는 순서와 구분자를 확인할 수 있을 때만 조합하고, 불명확하면 `확인 필요`로 표시한다.

전체 이름을 별도 필드로 저장하지 않으며, 전체 이름만 발견되거나 저장된 경우 이를 성과 이름으로 추측해 분리하지 않는다. 영문 이름의 대소문자와 한자 표기도 임의로 변환하지 않는다.

주민등록번호, 여권번호, 운전면허번호, 계좌번호는 기본 인적사항에 포함하지 않는다.

| 필드 ID | 사용자 표시명 | 형식 | 자동 입력 | 설명 |
|---|---|---|---|---|

비상연락처와 SNS 계정 정보는 MVP에서 저장하지 않는다.

### 8. 보훈

### 9. 장애

### 10. 건강

건강정보는 여러 건을 저장할 수 있다. 채용 사이트마다 요구하는 의미가 다르므로 고정된 질병 목록이나 진단 선택지를 제공하지 않고 사용자가 항목을 직접 작성한다.

| 필드 ID | 사용자 표시명 | 형식 | 자동 입력 | 설명 |
|---|---|---|---|---|
| `healthItemName` | 건강정보 항목 | 짧은 텍스트 | 민감 확인 | 질환, 치료, 신체 상태 등 사용자가 관리할 항목명 |
| `healthStatusOrValue` | 상태·값 | 짧은 텍스트 | 민감 확인 | 해당 항목의 상태, 수치 또는 지원서에 사용할 표현 |

건강정보는 필드명이 정확히 대응하고 사용자가 값을 직접 확인한 경우에만 입력한다. 범용 탐지는 비슷한 표현만으로 건강정보를 자동 연결하지 않는다.

## 후속 지원 후보

프로토타입에는 다음 정보가 있었지만 `PRODUCT_CONCEPT.md`의 MVP 범위에는 포함되지 않는다. 별도 기획 결정 전에는 프로필 화면이나 저장 구조에 추가하지 않는다.

| 범주 | 프로토타입에서 확인한 필드 | 제외 이유 |
|---|---|---|
| 논문 | 논문구분, 논문명 | 핵심 10종 범위를 넘어가며 대상 사용자가 제한적임 |
| 경력 | 고용형태, 회사명, 입사일, 퇴사일, 재직 여부, 직급, 담당업무, 연봉, 퇴직사유 | MVP가 신입 취업 준비생의 반복 정보에 우선 집중함 |
| 해외경험 | 목적, 국가, 시작일, 종료일, 내용 | 어학 정보와 구분되는 별도 활동 모델이 필요함 |
| 수상이력 | 수상내용, 시상단체, 수상일자, 상세설명, 상훈명 | 프로젝트·자격증과 구분되는 별도 반복 모델이 필요함 |

후속 범위로 채택할 때는 사용 빈도, 여러 기업에서의 공통성, 자동 입력 가능성, 개인정보 위험을 다시 검토한다.

## 저장하지 않는 정보

다음 정보는 자동 입력 편의보다 개인정보 위험 또는 오입력 위험이 크거나, 반복 재사용 정보라는 제품 목적에 맞지 않으므로 저장 대상에서 제외한다.

- 주민등록번호와 외국인등록번호
- 여권번호
- 계좌번호와 급여계좌 정보
- 가족관계와 가족 구성원의 개인정보
- 증명사진 원본 및 각종 증빙 파일
- 자기소개서와 지원 동기
- 채용 지원 경로 등 지원 건마다 달라지는 지원정보
- 개인정보 수집·이용 동의와 법적 확인 항목
- 지원서 계정, 비밀번호와 인증 정보

이 목록의 항목을 향후 지원하려면 단순한 필드 추가가 아니라 저장 필요성, 보안 수준, 자동 입력 허용 범위를 별도로 승인해야 한다.

## 프로필과 지원서의 관계

- 프로필은 사용자가 여러 지원서에서 재사용할 수 있는 원본 정보다.
- 주소, 병역, 보훈, 장애, 건강 정보도 외부 서버가 아닌 확장 프로그램 전용 로컬 저장소에만 보관한다.
- 채용 사이트의 필수 항목, 글자 수, 날짜 형식, 선택지는 사이트마다 다를 수 있다.
- 어댑터는 프로필 값을 임의로 바꾸지 않고 대상 필드와 형식의 호환성을 판단한다.
- 하나의 프로필 값이 여러 지원서 필드 후보와 연결되거나 선택지 매핑이 불확실하면 `확인 필요`로 표시한다.
- 프로필에 값이 없거나 안전한 변환을 할 수 없으면 `입력 불가`로 표시한다.
- 증빙 서류 위치처럼 `미입력`으로 정의한 값은 지원서에서 유사한 필드가 발견되어도 자동 입력하지 않는다.
- `민감 확인` 항목은 일반 항목의 일괄 적용 선택에 포함하지 않고 지원 건마다 개별 승인을 다시 받는다.

## AI와 후속 작업자를 위한 해석 기준

- 이 문서의 MVP 표에 있는 항목만 초기 프로필 입력 대상으로 간주한다.
- 표의 필드 ID는 개념적 식별자다. 실제 저장 스키마나 API 형식을 확정하는 문서는 아니다.
- 사람 이름은 국문·한자·영문의 성과 이름을 각각 독립된 값으로 취급하며, 하나의 전체 이름 필드로 대체하지 않는다.
- 모든 프로필 필드는 선택 입력이며, 채용 사이트의 필수 여부를 프로필 검증 규칙으로 옮기지 않는다.
- `조건부`는 자동 입력 금지가 아니라 안전한 선택지 매핑 또는 사용자 확인이 필요하다는 뜻이다.
- `민감 확인`은 저장 금지가 아니라 매 지원 건마다 항목별 명시적 승인이 필요하다는 뜻이다.
- 프로토타입에 존재한다는 이유만으로 후속 지원 후보를 MVP에 포함하지 않는다.
- 저장하지 않는 정보는 범용 탐지에서 발견해도 프로필 저장을 권유하거나 자동 입력하지 않는다.
- 민감정보는 화면 상태, 분석 로그, 오류 메시지, 원격 측정 데이터에 실제 값을 남기지 않는다.
- 새로운 필드를 추가할 때는 MVP 범주, 반복 여부, 입력 형식, 자동 입력 허용 상태, 개인정보 위험을 함께 정의한다.

## 아직 결정하지 않은 사항

- 날짜를 연·월까지만 아는 경우를 위한 부분 날짜 표현 방식
- 대학교와 대학원의 추가 전공 유형을 프로필에서 별도 필드로 확장할지 여부
- 점수와 등급을 하나의 문자열로 유지할지 시험별 구조로 분리할지 여부
- 프로젝트 상세내역의 글자 수가 사이트 제한을 초과할 때의 처리 방식
- 로컬 파일 경로 메모를 MVP UI에 실제로 노출할지 여부
- 건강정보의 사용자 정의 항목을 회사별 필드와 연결하는 최소 신뢰 기준
- 필드별 검증 규칙과 실제 로컬 저장 스키마

이 항목들은 구현 과정에서 임의로 결정하지 않고 후속 제품 또는 기술 설계에서 확정한다.
