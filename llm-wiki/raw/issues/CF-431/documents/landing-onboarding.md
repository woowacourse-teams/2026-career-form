# 확장 첫 설치 온보딩 여섯 단계

> Issue: [CF-431](https://github.com/woowacourse-teams/2026-career-form/issues/431)
> Collected: 2026-11-06
> Approval-Digest: 85cc2205e1bd8d944112de84ef4e184451b0db59582f1e65b8c9442accc63cb7
> Source-Revision: c9429500

확장을 처음 설치했을 때 열리는 `onboarding.html`의 구성과 검증 방법이다. [승인 후보 스냅샷](approved-candidates.md)의 후보 2와 3을 적는다. 웹 랜딩, 체험, 기술 소개, 정책 페이지와 웹 `/onboarding/`의 4단계 사용 안내는 CF-427 payload의 내용이 그대로 유효하며 여기서는 확장 온보딩에서 바뀐 부분만 더한다. 실제 지원값, 계정, 세션, 대화 전문은 기록하지 않는다.

## 흐름 (후보 2)

`onboarding.html`의 기본 경로는 "설치 완료" 선택 화면 없이 이름, 이메일, 직무 선택, 알림 안내, Greeting, 사용법 순서의 한 줄 흐름이다(`frontend/entrypoints/onboarding/flow`). 입력 영역 위 진행 바가 여섯 단계와 현재 위치를 보이고 720px 이하에서는 `n / 6 단계 이름`으로 보인다. `?page=`로 여는 소개, 체험, 기술 소개, 정책 페이지는 계속 `SiteApp`이 그린다.

- 이름과 이메일은 기존 `useProfileEditor` 저장 경로로 자동 저장한다. 넘어가는 버튼은 하나이고 칸이 비면 "건너뛰기", 값이 있으면 "다음"이다.
- 현재 단계 이름만 `careerForm.onboarding.step`에 저장한다. 다시 열면 그 단계에서 시작하고, 사용법 단계에 닿지 않았으면 관리 페이지 머리글에 "시작 안내 이어하기" 링크가 보인다. 프로필 저장 키와 형식은 바꾸지 않는다.
- 직무 선택 단계는 "모든 직무의 공고 받기"(기본)와 "직무를 골라 받기" 두 가지이고 알림 상태, 테스트 알림, 끄기와 켜기를 함께 둔다. 알림은 설치 때 이미 켜져 있으므로 이 단계는 켜는 화면이 아니다.
- 알림 안내 단계는 세 안내 사이를 옆의 번호나 글로 옮긴다.
- Greeting 단계는 가져오기를 실행하지 않는다. 지원서 탭의 패널에서 가져오기가 저장되면 프로필 저장 키의 변경을 감지해 알리고 다음으로 넘어가게 한다. 예시 회사는 표시용 상수이며 지원 보장이 아니다.
- 사용법 단계는 자동 기입 장면을 계속 반복한다. Greeting과 사용법의 장면은 화면 컴포넌트 애니메이션이고 영상 파일을 쓰지 않으며, 일시정지 버튼을 두고 동작 줄이기 설정에서는 재생하지 않는다.
- 단계형 등록(`QuickStart`)은 사용법 단계의 "추가 정보 더 등록하기"가 "저장한 정보" 화면으로 연다. 왼쪽 "등록 묶음" 목록과 자동 기입 안내 화면은 없앴고, 질문의 넘어가는 버튼은 하나이며, 날짜는 숫자를 입력하는 동안 대시를 넣는다. 덜 입력한 날짜가 있으면 넘어가지 않는다.
- 온보딩 페이지가 백그라운드에 보낼 수 있는 구독 메시지는 `status`, `enable`, `disable`, `test`, `record`, `categories`, `roles`이고 `inbox`, `later`는 차단한다.
- 여섯 단계는 랜딩의 하늘색 값을 `Flow.module.css` 범위에 literal로 두고, 단계형 등록에는 같은 범위에서 `--color-*` 토큰을 다시 정한다. `theme.css`와 `extension-theme.css`는 바꾸지 않는다.
- "설치 완료" 선택 화면, 알림 타일, 공고 저장 3단계 안내와 `SiteApp`의 확장 전용 속성은 없앴다.

## 검증 방법과 함정 (후보 3)

빌드한 확장을 Playwright Chromium에 `--load-extension`으로 새로 설치하면 `onInstalled`가 `onboarding.html`을 스스로 열어 여섯 단계를 실제로 조작할 수 있다. 직무 분류는 `VITE_API_BASE_URL`을 로컬 대역 서버로 두고 빌드해 받는다. 헤드리스에서는 OS 알림이 뜨는지 확인할 수 없다.

조작 확인과, 설계를 모르는 독립 검토자가 처음 설치한 사용자 역할로 화면을 순서대로 보는 점검에서 다음을 찾았다.

- CSS 모듈에서 상태 문구의 수식 클래스가 반복 장면의 클래스 이름과 같으면 장면 애니메이션이 문구까지 숨긴다. 글자가 있는지만 보는 테스트는 이를 잡지 못한다.
- 범위 루트의 `.flow p { padding: 0 }` 같은 reset은 컴포넌트 클래스보다 특이도가 높아 안쪽 여백을 지운다. reset은 margin만 둔다.
- 사용자가 헷갈린 것은 설명 없는 Greeting, 패널과 톱니라는 낱말, "새 탭"과 "새 공고 탭"의 혼용, 지금 해야 하는 일로 읽히는 명령형 제목, 이동 버튼 줄에 섞인 "알림 끄기"였다.
