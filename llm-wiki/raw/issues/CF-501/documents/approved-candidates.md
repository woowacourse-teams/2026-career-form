worktree 체크포인트에 기록한 후보 세 개의 원문이다. 사람이 2026-11-19 "llm wiki 앞으로 잘 동작하는지 확인하고, 사람 승인 안받아도 되니 너가 알아서 기입해"라고 말해 에이전트가 자동 승인했다. 후보 3은 [ADR 501](adr/501-certificate-issuer-lock.md) 전문을 한 줄로 옮긴 것이다.

1. 카탈로그 자격증 발급기관 정규명과 잠금(#501, commit 3b346f5): 새 모듈 profile/certificate-issuer.ts의 canonicalIssuerName은 detail 첫 조각에서 법인 표기 (사)·(재)·(주)·사단법인·재단법인·주식회사를 떼고 구분 기호(·, ㆍ, /) 주변 공백과 연속 공백을 정리한다. 원래 글자는 바꾸지 않는다(NFKC는 비교 키에만). catalogCertificateIssuer가 이 정규명을 돌려준다. 카탈로그 선택 중이면 편집 화면의 발급기관은 readOnly이고 라벨 옆에 '카탈로그'가 보이며, 선택할 때 저장 값을 정규명으로 바꾼다. 이름 수정·직접 입력으로 연결이 풀리면 값은 남고 편집할 수 있다. CF-458의 세션 채움 기억(filledIssuers)은 잠금으로 필요 없어져 지웠다.
2. 발급기관 같은 기관 판정과 범용 자동 기입(#501): sameIssuer는 정규명에서 공백·문장부호를 뺀 NFKC 소문자 비교 키가 같거나 공식 약칭 묶음(HRDK·산업인력공단, KCCI·상공회의소, K-DATA·데이터산업진흥원, KPC, KBI, ICQA, KAIT)에 함께 있을 때만 참이다. 카탈로그 기관 사이 겹침 0을 테스트로 고정했다. 범용 경로(LLM_SUGGESTED)에서만 review-plan hasConflict, native-executor hasGenericConflict는 같은 기관 기존 값을 충돌로 보지 않고 writeGeneric은 덮어쓰지 않고 ALREADY_MATCHED를 돌려준다. 사이트 발급기관 선택지는 resolveChoiceOption(범용 호출만)에서 같은 기관 선택지가 하나일 때만 고르고 둘 이상이면 고르지 않는다. 값 연결은 선택된 자격증의 발급기관으로 정규명을 쓰고 저장 값은 바꾸지 않는다. 정적 경로는 그대로다.
3. ADR 501 전문(#501): # 카탈로그 자격증 발급기관 정규명 고정과 사이트 표기 차이 일치 ## 상태 승인됨 ## 날짜 2026-11-21 ## 관련 Issue - #501 ## 배경 카탈로그에서 자격증을 고르면 발급기관이 비었을 때만 카탈로그 detail 첫 조각으로 채웠고(CF-368), 사용자가 고친 값과 직접 쓴 값은 보호했다(CF-458). 발급기관은 계속 자유롭게 고칠 수 있었다. 카탈로그 안에서도 같은 기관이 두 표기로 있고(`한국데이터산업진흥원`, `(재)한국데이터산업진흥원`), 일부 지원서는 자격증을 고르면 사이트가 자기 표기로 발급기관을 채운다. 표기가 프로필과 다르면 범용 자동 기입은 그 칸을 기존 값 충돌(CONFLICT)로 멈추고, 줄 저장이 필요한 화면에서는 줄 저장도 진행되지 않았다. 사용자는 발급기관을 고정하고, 사이트의 같은 기관 다른 표기는 일치로 보기로 정했다. ## 검토한 대안 - 편집 화면 잠금만: 프로필 표기는 하나로 모이지만 사이트 표기와의 충돌은 그대로 남는다. 기각한다. - 사이트 표기 일치만: 충돌은 줄지만 프로필 발급기관이 계속 제각각이다. 기각한다. - 발급기관을 정해진 기관 목록에서만 고르기: 직접 입력 자격증까지 묶여 카탈로그 밖 기관을 적을 수 없다. 기각한다. - 저장된 프로필의 발급기관 일괄 변경: 사용자 데이터를 덮어쓰고 되돌릴 수 없다. 기각한다. 선택된 자격증은 읽을 때 정규명을 쓴다. - 카탈로그 데이터 파일 수정: 사이트 표기 차이 때문에 카탈로그 데이터와 정규화를 바꾸지 않는다는 기존 결정(profile-catalog-identity)과 어긋난다. 기각한다. ## 결정 1. 카탈로그 발급기관의 정규명은 detail 첫 조각에서 법인 표기 `(사)`, `(재)`, `(주)`, `사단법인`, `재단법인`, `주식회사`를 떼고 공백과 구분 기호 주변 공백을 정리한 이름이다. 원래 글자는 바꾸지 않는다. 2. 자격증명이 카탈로그 선택 상태이면 발급기관은 정규명이고 편집 화면에서 읽기 전용이다. 선택할 때 저장 값도 정규명으로 바꾼다. 이름을 고치거나 직접 입력해 연결이 풀리면 값은 남고 다시 편집할 수 있다. CF-458의 "사용자가 고친 발급기관 보호"는 카탈로그 선택 중에는 적용하지 않는다. 3. 자동 기입 값 연결은 선택된 자격증의 발급기관으로 저장 값 대신 정규명을 쓴다. 저장 데이터는 일괄 변경하지 않는다. 4. 같은 기관 판정은 정규명에서 공백·문장부호를 뺀 비교 키가 같거나, 검증된 공식 약칭 묶음(한국산업인력공단=HRDK=산업인력공단, 대한상공회의소=KCCI=상공회의소, 한국데이터산업진흥원=K-DATA=데이터산업진흥원, 한국생산성본부=KPC, 한국금융연수원=KBI, 한국정보통신자격협회=ICQA, 한국정보통신진흥협회=KAIT)에 함께 있을 때만 참이다. 카탈로그 기관 사이 겹침은 0이어야 한다. 5. 범용 경로에서만, 발급기관 칸의 기존 값이 같은 기관이면 충돌이 아니고 덮어쓰지 않는다(ALREADY_MATCHED). 다른 기관이면 지금처럼 충돌이다. 사이트 발급기관 선택지는 같은 기관 선택지가 정확히 하나일 때만 고른다. 정적 경로는 바꾸지 않는다. ## 결과 - 카탈로그 자격증의 발급기관이 한 표기로 모이고, 사이트가 같은 기관을 다르게 채워도 범용 경로가 멈추지 않는다. - 카탈로그 자격증에 사용자가 따로 적은 발급기관은 선택 중에는 쓰이지 않는다. 연결을 풀면 다시 적을 수 있다. - 별칭 목록에 없는 약칭은 여전히 충돌이다. 별칭을 넣을 때는 공식 근거와 겹침 0 테스트가 필요하다. - 공동 발급기관(`케이티ㆍ한국경제신문` 등)은 하나의 정규명으로 다룬다.
