# CF-453 승인 후보 스냅샷

> Issue: [CF-453](https://github.com/woowacourse-teams/2026-career-form/issues/453)
> Collected: 2026-11-16
> Approval-Digest: 6cb4d5596bfdff6146303f2c7287eee610fa49effaf21b17b7a155be7e39bef4

worktree 체크포인트에 기록한 후보 여섯 개의 원문이다. 사람이 2026-11-16 "승인"으로 확정했다.

1. 저장 공고 수명: 지원 예정이면서 마감이 지난 공고(`isExpiredPlan`: `status === "planned"`이고 `deadline <= now`)는 확장 저장소 `careerForm.jobPostings`에서 되돌릴 수 없게 지운다. 지원 완료 공고는 마감이 지나도 남는다. 지우는 시점은 관리 페이지의 목록 조회(`PostingService.list`)와 백그라운드 점검(`recover`: 마감 시각 알람, 서비스워커 시작, 브라우저 시작, 설치·업데이트, 알림 권한 변경, 알림 다시 시도)이고, 이전 버전이 '마감 지남' 탭에 남긴 공고는 업데이트 뒤 첫 점검에서 지워진다. '지원 공고' 화면의 탭은 새 공고·지원 예정·지원 완료 셋이다.
2. 점검 예약: 다음 알람(`careerForm.jobPostings.next`)은 남은 알림 시각과 지원 예정 공고의 마감 시각(이미 지난 것 포함) 가운데 가장 이른 때이고, 그 시각이 지났으면 1분 뒤다. 그래서 화면을 열지 않아도 마감 시각에 저장소에서 지워진다. 지원 완료 공고의 마감은 넣지 않는다. 넣으면 마감 지난 지원 완료 공고 때문에 1분마다 깨어난다.
3. 쓰기와 실패 처리: `list()`는 지울 공고가 있을 때만 저장소에 써서 `storage.onChanged`로 화면이 다시 읽기를 반복하지 않는다. 정리 저장이 실패해도 목록 조회와 다른 공고의 알림은 막지 않고, 남은 지난 마감 때문에 1분 뒤 다시 점검한다. 알림 루프의 마감 경과 분기는 루프 도중 마감이 지난 공고에 늦은 알림을 보내지 않으려고 남겼다. `save`·`setCompleted`·`remove`는 정리하지 않으므로 마감 직후 정리 전에 누른 '지원 완료'는 남는다.
4. 되돌리기 제한과 알림: 마감이 지난 지원 완료 공고는 지원 예정으로 되돌릴 수 없다. 되돌리면 곧바로 지워지기 때문이다. 서비스가 '마감이 지난 공고는 지원 예정으로 되돌릴 수 없습니다.'로 거부하고 화면은 그 행에 삭제만 둔다. 정리는 이미 뜬 OS 알림을 닫지 않고, 지운 공고의 알림을 누르면 탭 없이 알림만 닫힌다.
5. 화면 시각 규칙: 새 공고 탭은 서버 목록을 다시 받지 않고 30초 시각 갱신과 화면 복귀 때 마감이 지난 행(`closesAt <= now`)을 숨긴다. 목록을 다시 읽거나 공고를 바꾼 뒤에는 시각도 함께 맞춰, 백그라운드 정리 직후 '✓ 저장됨'이 '저장' 버튼으로 돌아가지 않게 한다. 시각 갱신 전에 마감된 새 공고의 저장 클릭은 요청 없이 행을 숨긴다. 시작 탭은 새 공고 목록이 처음 정해질 때 한 번만 고르며 함수형 갱신으로 이미 고른 탭을 덮어쓰지 않는다(늦게 도는 React 패시브 이펙트가 클릭 뒤 선택을 되돌리던 경합). 화면 테스트는 `setInterval`만 가짜 타이머로 바꿔 30초 갱신을 진행시키고, Testing Library 대기는 DOM 변경 감지로 계속 동작한다.
6. 변경 이유와 남은 위험: 2026-11-12 사용자 의견('마감된 공고는 삭제 처리해 주면 좋겠다')으로 바꿨다. 남은 위험은 세 가지다. 마감 뒤에는 지원 완료로 표시할 수 없다(예전에는 '마감 지남' 탭에서 가능했다). 삭제 기준이 이 기기의 시계라 시계가 앞서면 일찍 지워진다. 자동 삭제를 알리는 사용자 안내 문구가 없다(후속 후보).
