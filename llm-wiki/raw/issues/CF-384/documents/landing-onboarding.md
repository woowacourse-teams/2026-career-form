## 결정

랜딩은 히어로와 AI 자동 기입 4단계(칸 읽기, 칸 의미 판단, 프로필 값 채우기, 애매한 칸 확인 요청)를 화면 고정 스크롤 장면으로 보여주고, 바로 아래 직접 체험, 마감 알림 장면, 안심 포인트·설치 버튼·FAQ 순서로 둔다. 헤더는 로고와 `Chrome에 추가`만 둔다. 기술 소개와 개인정보처리방침·이용약관도 같은 디자인(`site/pages/`)으로 바꾸고 문구 내용은 유지한다. `/onboarding/`(확장 설치 직후에도 열림)과 `/try/`는 기존 화면과 헤더·푸터를 유지한다. 새 페이지는 기존 `.site` 요소 규칙(버튼 배경, svg 크기)과 충돌해 그 밖에서 렌더한다.

랜딩 체험은 실제 사이드패널(`Trial`) 대신 AI 장면과 같은 10칸 가상 지원서(윤티모, 커리어 테크)와 간이 패널을 쓴다. 장면과 체험의 데이터와 모양을 맞추는 것을 실제 패널 재현보다 우선한 사람 결정이다. 자동 기입을 누르기 전까지 휠·터치·키보드의 아래 스크롤을 붙잡고, 위로 스크롤과 `건너뛰고 계속 보기`는 허용한다. 700px 이하에서는 붙잡지 않고 `PC로 링크 보내기`(공유 시트, 없으면 링크 복사)와 설치 버튼을 둔다. 체험 시작과 완료는 기존 `trial_started`, `trial_completed`에 `surface`만 기록한다.

정책 문서의 문의 이메일은 운영하는 주소가 없어 `개설 후 기재`로 두고 mailto 링크를 두지 않는다. 모든 사이트 페이지는 앵커가 없으면 맨 위에서 열린다(스크롤 복원 끔).

## 스크롤 연출 방식과 근거

toss.im(framer-motion, 미리 렌더한 영상·이미지)과 about.daangn.com(GSAP ScrollTrigger, 이미지)의 공개 번들을 확인한 결과 둘 다 WebGL 없이 미리 만든 입체 이미지에 transform/opacity만 스크롤로 연결한다. 그래서 클레이 질감은 미리 렌더한 webp(카피바라 5종, 오브젝트 6종)로 내고, sticky 무대와 스크롤 진행률로 transform/opacity만 직접 쓰며 스크롤 중 React를 다시 그리지 않는다. 영상 스크러빙과 Three.js는 끊김과 제작 비용 때문에 쓰지 않는다. 동작 줄이기 설정에서는 각 변화가 구간 중간에서 움직임 없이 바뀐다.

## 유지되는 경계

CF-363의 `/try/` 실제 패널 체험과 `trial_viewed` 기록, CF-193의 단계형 온보딩, CF-96의 독립 웹 빌드와 가상 데이터 경계는 그대로다. 체험은 프로필을 저장하거나 서버에 요청하지 않는다. 링크 공유 썸네일(og:image)은 정식 도메인이 정해진 뒤 다루고, 사이트 배포는 이 작업에 포함하지 않는다. 정책 문서는 미시행 초안을 유지한다.
