# 분석과 품질 관측의 메모리 기반 비동기 분리

## 상태

승인됨

## 날짜

2026-10-19.

## 관련 Issue

- #288

## 배경

품질 기록과 집계 완료를 분석 응답이 기다리고 Receipt 전달도 이 작업에 결합돼 있다. 품질 데이터 일부 유실은 허용하지만 분석/입력 지연과 다른 실행으로의 오반영은 허용하지 않는다.

## 검토한 대안

집계만 분리하면 원본 저장과 Receipt 대기가 남는다. 기존 get만 제거하면 번호/토큰과 후속 보고 연결이 깨진다. 영속 브로커/별도 서버는 복구성과 격리를 강화하지만 접수 지연과 운영 비용이 늘어난다. 같은 백엔드의 제한된 메모리 등록/큐는 일부 유실을 허용하는 조건에서 작은 접수 비용으로 사용자 흐름을 분리할 수 있다.

## 결정

같은 백엔드에서 별도 메모리 실행 등록과 번호/토큰 응답, 제한된 비동기 원본 저장, 30초 프론트 등록 대기, 비동기 보고 접수, 약 1분 주기의 변경 대상 집계를 사용한다. 선행 정보 처리와 중복 방지를 보장하며 실패, 포화는 품질 경로 안에서 제외/계수한다. 접수 응답과 버전 호환은 포함 범위의 API 계약을 따르고, 용량, 수명과 DB 제한시간은 초기 시험값으로 두며 연결된 관측 계약에 근거와 함께 명시한다.

## 결과

분석/입력 완료에서 품질 DB 대기를 제거하지만 자원 사용 자체는 남는다. 프로세스 재시작과 큐 포화 시 유실 및 통계 지연이 가능하다. 전량성이나 정확히 한 번 처리를 보장하지 않는다. 메모리와 DB의 실행 상태, 클라이언트 호환성, 실패 계수와 집계 보정이 새 설계 책임이다. 성능 절감량은 같은 조건의 실제 전후 측정으로 판정한다.

구체 접수 계약과 초기 시험값은 [관측 계약](../async-quality-observation.md)을 따른다.
