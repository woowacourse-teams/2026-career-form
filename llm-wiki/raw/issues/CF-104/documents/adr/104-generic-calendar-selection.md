# DOM 검증 기반 범용 달력 실행과 로컬 선택 경계

## 상태

승인됨 (CF-104 지식 후보 승인)

## 날짜

2026-09-24

## 관련 Issue

- #104
- #101
- #98

## 배경
읽기 전용 달력은 텍스트 형식 변환과 별도의 UI 상태 전이를 요구한다. 회사별 DOM 고정과 임의 에이전트 실행 사이에서 개인정보와 사용자 승인을 유지하는 반복 가능한 실행 경계가 필요하다.
## 검토한 대안
1. 회사별 selector/adapter: 초기 구현은 쉽지만 구조 변경과 회사 확장에 취약하다.
2. readonly 해제 또는 private framework 상태/직접 값 주입: 표시는 바뀌어도 사이트 내부 상태 반영과 안전성을 증명하지 못한다.
3. LLM에 목표 날짜와 전체 DOM을 보내 클릭 계획 실행: 개인정보·프롬프트 주입·범위 밖 조작 위험이 크다.
4. 후보 역할 판별과 로컬 상태 머신 분리: 지원 범위는 명시적으로 제한되지만 선택·중단 조건을 테스트할 수 있다.
## 결정
대안 4를 채택한다. SELECT_DATE와 calendarApproval을 분리하고 FE가 후보 수집·유효 날짜·목표 연월·실행·결과 검증을 소유한다. 모델은 비식별 후보 역할 ID만 선택한다. 회사가 아니라 증명 가능한 연월 달력 동작 유형을 지원 단위로 삼고, 기존 직접 입력/검색 계약은 유지한다.
## 결과
새 유형은 fixture와 안전 조건을 추가해 확장할 수 있다. 비용은 capability·DTO·역할 계약과 FE 실행 경로를 함께 검증해야 한다는 점이다. 일 단위·가상화·화살표 전용 탐색은 자동 추정하지 않고 별도 후속 범위로 남긴다.
