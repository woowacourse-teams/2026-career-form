# 버전 고정 입력 기반 모델 평가와 비동기 실행

## 상태

제안됨

## 날짜

2026-10-30

## 관련 Issue

#356

## 배경

범용 자동기입의 모델 정확도와 처리 성능을 제품 변경마다 같은 기준으로 비교해야 한다. 실사이트 반복 실행은 공고 마감과 화면 변경의 영향을 받는다. 복제 사이트는 동작 검증 비용이 크다. 개인 로컬 스크립트는 팀이 공유하기 어렵다. 동기 API는 장시간 실행과 중단 처리가 어렵다.

## 검토한 대안

- 실사이트 반복 측정: 공고가 마감되거나 화면이 바뀌면 같은 입력으로 다시 잴 수 없다.
- 사이트 복제: 원본과 같은 동작인지 검증하는 비용이 크다.
- 개인 로컬 스크립트: 실행 환경과 결과를 팀이 공유하기 어렵다.
- 동기 평가 API: 호출이 길어지면 요청이 끊기고, 중단된 실행을 이어받기 어렵다.

## 결정

1. 사람이 검토한 비식별 화면과, 제품 코드가 그 화면에서 만든 요청·정답을 버전 고정 데이터셋으로 둔다. 데이터셋은 저장소 파일이고 파일마다 sha256을 기록한다.
2. 비동기 실행 API가 실행을 등록하고, Mongo 임대 작업자가 제품 서비스를 그대로 호출해 평가한다.
3. 채점 단위는 제품 API 호출 1건이다. 채점할 수 없는 호출은 정확도에 섞지 않고 실패 지표로 분리한다.
4. 실행 결과와 재채점은 추가만 하고 덮어쓰지 않는다.

## 결과

공고가 마감된 뒤에도 같은 입력으로 다시 잴 수 있고, 모델·프롬프트·배치 설정을 같은 분모로 비교한다. 대신 정답 검토와 데이터셋 관리 비용이 든다. 이 평가는 실제 기입 성공, 검색 팝업 동작, 설치된 확장이 보낸 요청과의 동일성을 입증하지 않는다.
