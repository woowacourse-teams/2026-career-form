# 현대 프론트 어댑터

## 구현 경계

`frontend/src/autofill/adapters/hyundai/collection.ts`는 현대 전용 섹션, 추가 제어 식별, 반복 행과 버튼형 입력 수집을 담당한다. 회사가 식별한 전용 반복 영역에만 가시성 예외를 적용한다. 일반 반복 영역으로 처리된 행에는 기존 일반 개수 계산을 유지한다.

`frontend/src/autofill/adapters/hyundai/write.ts`는 기존 버튼 선택 명령과 text 입력 후 라벨 보정을 담당한다. 검증된 코드와 표시명이 유일하게 일치해야 선택하고, 실패하면 일반 입력으로 우회하지 않는다. 승인되지 않았거나 stale인 후보는 공통 writer가 실행 전에 차단한다. 성공한 text 입력만 라벨 보정 대상이다.

## 확인된 자동 검증 범위

- 회사 밖에서 전용 버튼·추가 제어·반복 행 규칙 미적용.
- 회사 전용 반복 행의 독립 index/count 및 일반 반복 영역 개수 유지.
- 버튼 후보 0개·복수 후보에서 선택 실패와 기존 표시값 보존.
- 미승인·stale 후보의 메뉴 미실행.
- 성공 text 입력의 회사 한정 라벨 보정.

이 기록의 입력 동작은 비식별 자동 테스트와 코드 조사에 근거한다. 사용자가 자동 기입을 마친 현재 페이지는 읽기 전용으로 점검했다. 수정 코드로 실제 채용 페이지에 재기입하거나 저장·이동·미리보기·제출하지 않았다.

## 제한

회사 버튼 선택은 같은 select-wrap 메뉴로 한정하고 최종 표시명과 숨은 코드까지 확인한다. 어학 선행 선택은 완료 후 재실행하지 않으며 후속 메뉴 준비를 제한 시간 안에 확인한다. 학교 등 별도 검색 팝업의 비동기 검색·취소 계약을 새로 제공하는 것은 아니다.


## 같은 이름의 취득일 구분

현대의 어학 취득일과 자격증 취득일은 같은 DOM 이름을 사용한다. 이름만 연결하던 기존 정책에서는 어학 날짜가 자격증 취득일 규칙으로 연결될 수 있었다.

로컬 현대 정책 v3은 두 취득일에 `FieldRule.requiredDomName`을 명시한다. 이 조건이 있는 규칙은 반복 접미사를 제거한 DOM ID가 `structuralName`과 같고 DOM 이름이 `requiredDomName`과 정확히 같을 때만 후보가 된다. element/control 검증도 유지한다. 알려진 ID나 이름 중 일부만 맞으면 기존 이름 매핑으로 우회하지 않고 `NO_MATCH`로 남긴다. 이 속성이 없는 기존 정책은 기존 생성자와 저장 문서 역직렬화에서 null로 처리해 호환성을 유지한다.

두 날짜는 각각 어학·자격증 프로필의 취득일을 `DIRECT`로 연결한다. 회사 fingerprint와 API schemaVersion 2는 변경하지 않는다. 로컬 빌드와 서버를 갱신해 수정 정책을 적용했고 비식별 API 응답으로 확인했다. 실제 지원 페이지 재기입 검증과는 구분한다.

자동 회귀는 같은 이름의 어학·자격증 날짜 분리, 잘못된 ID/이름/제어 타입, 잘못된 반복 접미사, ID/이름 누락, 기존 문서 호환성을 확인한다. 프론트 회귀는 별도 반복 영역의 각 프로필 항목을 수집·리뷰·입력까지 연결하고, 프로필 값이 있어도 미매핑 후보는 입력하지 않는지 확인한다.

## 미입력 점검의 해석

현재 화면의 빈칸에는 서로 다른 원인이 섞여 있다. 국적·직장명 등은 현대 정책에 매핑이 없고, 기본주소와 우편번호는 읽기 전용이며 매핑도 없다. 프로젝트 기관과 해외경험 날짜는 대응 프로필 필드가 없다. 지원경로·자기소개서 등은 재사용 프로필 범위 밖이다. 병역·보훈·장애는 개별 확인 정책을 따른다.

자격증 날짜·등록번호·발급기관처럼 매핑이 있는 필드도 빈 화면만으로 로컬 값 부재나 입력 버그를 단정할 수 없다. 실행 당시 분석 결과와 반복 행 대응을 확인해야 한다. 검색 선택이나 필수 모델이 없는 항목을 텍스트 입력으로 우회하지 않는다. 수정 후 실제 재기입 결과는 아직 미검증이다.

## 반복 행 준비와 자격증명 보완

실제 페이지의 프로젝트·논문 영역에는 article ID가 없다. 기존 수집기는 ID로만 추가 버튼을 식별하여 두 동작을 누락했고, 필수 준비 fingerprint가 불일치해 자격증을 포함한 모든 반복 추가 계획이 차단됐다. 비식별 API 재현에서 누락 구조는 BLOCKED/0 plans, 완전한 구조는 COMPLETE/6 plans를 반환했다.

현대 어댑터는 같은 직접 반복 행의 검증된 프로젝트 또는 논문 제어 구조로 추가 동작 식별자를 복원한다. 불완전하거나 모호한 구조는 인식하지 않고 다른 사이트·해외경험에 규칙을 적용하지 않는다. fingerprint 자체는 약화하지 않는다.

준비 실행은 지원 섹션의 로컬 프로필 개수에서 현재 행 수를 뺀 만큼만 추가하고 매번 증가를 확인한다. 외국어시험은 languageTest, 외국어 활용능력은 languageSkill 개수를 각각 사용한다. 현재 정책의 추가 대상은 직장경력·프로젝트·외국어시험·외국어 활용능력·자격·논문/특허이며, 학력과 해외경험의 자동 추가는 미지원이다.

자격증명은 nationLicNm의 반복 접미사를 제외한 ID, 정확한 이름과 text 제어 검증 뒤 certifications.certificate.name에 DIRECT 연결한다. 기존 반복 리뷰는 화면 행 수와 프로필 개수가 다르면 입력을 차단한다. 비식별 통합 회귀에서 프로필 3개/화면 1행의 차단, 정확히 2회 추가, 서로 다른 3개 항목 입력, 재실행 시 중복 추가 없음을 확인했다. 수정 코드의 실제 채용 페이지 재기입은 여전히 미검증이다.

## 첫 실행 버튼 재탐색 보완

행 추가 후 임시 후보 번호가 바뀌면 제공된 DOM ID/이름을 정확히 확인해 같은 동작을 다시 찾는다. ID 없는 다른 영역의 동일 표시명 버튼으로 우회하지 않는다. 마지막 추가도 기존 필드가 보인다는 이유로 동작 재식별·행수 검증을 생략하지 않는다. 행 안의 버튼, footer 추가 버튼, 타 영역 추가 버튼을 포함한 비식별 구조로 첫 실행 회귀를 보강했다.

## 외국어시험·활용능력

현대 정책 v3에 확인된 시험 언어 13개, 영어 시험 11개, OPIc 계열 등급, 활용 언어 11개와 회화수준 4개를 BUTTON_OPTION으로 연결했다. 시험명·회화수준의 명확한 별칭은 같은 표시명으로 정규화한다. 미검증 시험·등급, 코드가 모호한 선택지는 추정하지 않는다. 활용능력의 작문·독해는 현재 대응 프로필 필드가 없으므로 회화수준으로 대신 채우지 않는다.

실제 버튼에는 name이 없고 숨은 입력이 같은 필드의 코드를 보관한다. 현대 워크플로는 버튼의 반복 접미사를 제외한 ID와 프로필 연결로 언어→시험 단계를 구분한다. 언어 선택 뒤 시험 메뉴, 시험 선택 뒤 등급 메뉴와 직접입력 상태를 같은 반복 행에서 제한 시간 안에 확인한 뒤 재수집·재분석한다. 정상 직접입력 버튼만 사용하며 성적 불러오기나 disabled 강제 해제는 실행하지 않는다. 선행 선택을 완료하면 최종 입력에서 다시 누르지 않고, 선택·준비 실패 시 후속 쓰기를 중단한다.

메뉴 선택은 같은 select-wrap의 유일한 표시명·코드에 한정한다. 선택 후 버튼 표시와 숨은 코드가 모두 맞아야 성공이다. 비식별 자동 회귀·로컬 서버 적용은 실제 페이지 재기입 검증과 구분한다.

구조·상태 전환 근거는 공개 사이트 스크립트 [common.js](https://talent.hyundai.com/static/js/common.js), [apply.js](https://talent.hyundai.com/static/js/apply.js), [common.api.js](https://talent.hyundai.com/static/js/common.api.js)와 비식별 UI 옵션 확인이다. 개인 입력값·계정·세션은 저장하지 않았다.
