# 프론트 회사 어댑터 경계

## 결정

회사별 프론트 코드는 DOM 수집·조건부 동작·특수 입력을 소유한다. 백엔드는 프로필 매핑과 허용 명령을 결정한다. 공통 프론트는 snapshot과 후보 registry, API 통신, 브라우저 로컬 값 결합, 승인과 실행 검사를 유지한다. 초기 분리의 schemaVersion 2와 기존 클라이언트 응답은 유지한다. 후속 SK 주소 검색은 기존 preparation API에서 address-search-v1 지원을 명시한 클라이언트에만 새 명령을 반환한다.

`frontend/src/autofill/adapters/company.ts`에서 host를 소문자로 정규화한 뒤 정확히 비교한다. 미등록 회사에는 일반 처리를 적용하고, 등록 회사의 전용 DOM 예외를 다른 사이트에 적용하지 않는다. 서버 회사 정책의 host/path 및 fingerprint 검증은 별도로 유지된다.

## 실행 책임

| 코드 | 책임 |
| --- | --- |
| `adapters/collection.ts` | 회사별 수집 규칙 선택 |
| `adapters/workflow.ts` | 선행 선택과 재분석 대상 규칙 선택 |
| `adapters/write.ts` | 회사 특수 입력과 입력 후 보정 선택 |
| `dom/collect.ts` | 구조 수집과 snapshot/registry 구성 |
| `workflow/AutofillWorkflow.tsx` | API·로컬 프로필·실행 순서 조정 |
| `write/executor.ts` | 승인·후보 유효성 확인과 표준 입력 |

회사 특수 입력이 `handled: true, written: false`를 반환하면 입력 실패로 종료한다. 일반 writer로 우회하지 않는다. SK 후속 전공 입력도 서버의 `interactionStatus: READY`를 확인한다. 진단 정보는 프로필 값 없이 코드와 개수만 남긴다.

## 새 회사 도입

현재 Issue 계약과 회사 구조 근거를 먼저 확정한다. 확인된 host를 등록하고 표준 수집·입력으로 처리할 수 없는 기능만 회사 모듈로 구현한다. 백엔드 회사 경로, fingerprint, 준비 규칙과 프로필 매핑도 별도로 준비한다. 프론트 어댑터 등록만으로 서버 정책이나 실제 지원 검증이 완료되지 않는다.

어댑터 기준이 없거나 구조를 검증할 수 없으면 추정하지 않고 계약 공백 또는 입력 불가로 처리한다. 코드·비식별 자동화 테스트·회사 문서·지원 현황을 함께 관리한다. 실제 지원서 저장·이동·제출은 사람이 수행한다.

## LG 검색의 후속 경계

이번 변경은 LG 학교 검색을 구현하거나 검증하지 않았다. 후속 구현에는 취소 가능한 비동기 검색, 동일 학력 행의 대상 식별, 후보의 유일성 및 최종 선택 반영 검증이 필요하다. 학교명이 같다는 이유로 첫 결과를 선택하거나 검색 실패를 text 입력으로 우회하지 않는다.

기존 자동 승인 경로, SK 첫 라디오 탐색, 현대 메뉴 탐색 범위와 성공 항목 재실행은 이번 분리로 해결된 것으로 기록하지 않는다. 회사별 실행 경계의 분리와 향후 검색 위젯의 안전성 완성은 별개의 작업이다.
