# 현대 버튼형 선택지 코드의 읽기 전용 수집, trigger 식별 규칙, 정책 v25 경력·자격 매핑

> Issue: CF-335

이 문서는 2026-10-24 CF-335(현대 경력 날짜·종료사유·자격 등급 수정)에서 승인된 후보 1·2·3을 현대 어댑터 관점에서 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 바꾸지 않은 내용(작성 화면 재진입 불가, 페이지의 Map·Set 재정의 등)은 Supersedes가 가리키는 CF-333 근거와 그 앞의 CF-310 근거를 따른다. 실제 지원값·계정·세션은 포함하지 않는다.

## 승인 후보

1. 버튼형 선택지 코드는 레이어를 열지 않아도 DOM에 있어 읽기 전용으로 수집할 수 있다(CF-310 관측 정정).
2. 버튼형 trigger에는 name이 없어 요청에 domName이 오지 않으므로 버튼 규칙은 trigger id의 구조 이름으로만 구분한다.
3. 정책 v25: 경력 입사·퇴사연월일 일자 보존, 종료사유 select 매핑과 자유입력 자동 기입 중단, 자격 등급 매핑.

## 버튼형 선택지 코드의 읽기 전용 수집

- 현대 작성 화면의 버튼형 선택은 `.select-wrap` 안에 표시용 `input.btn-select`(id `<이름>_<n>`, name 없음), 값을 가진 `input.js-field`(hidden, name `<이름>`), 선택지 `.select-option button[data-code]`로 이루어진다. 선택지 버튼은 레이어가 닫혀 있어도 DOM에 있고 `data-code`·`data-attr2`·`data-direct`·`data-enabled`·`data-disabled`·`data-valid` 속성을 가진다. CF-310은 "선택지는 레이어를 열 때만 그려진다"고 적었으나 2026-10-24 작성 화면 두 곳에서 닫힌 상태로 모두 읽혔다(두 화면의 코드 동일). 외국어 등급(`gradeForeLang_<n>`)처럼 선행 선택에 따라 채워지는 메뉴는 그 전까지 "선택하세요."만 있다.
- 수집은 평가 브라우저에 CDP로 붙어 `querySelectorAll`만 실행하는 읽기 전용 스크립트로 했다(클릭·입력·이동 없음). 하네스 census는 같은 선택지의 문구만 `selectOptions`에 40개까지 담으므로 등급 83개 중 40개만 보였었다.

## trigger 식별 규칙

- 요청 후보는 trigger 요소에서 만들어지며 domName은 요소 자신의 `name` 속성에서만 온다(합성 domName은 Greeting components 전용). 현대 버튼형 trigger에는 name이 없어 후보에 domName이 없고, 구조 이름은 id에서 `_<n>`을 뗀 값이다(`StoredPolicyFieldMappingResolver`).
- 따라서 버튼 규칙에 `requiredDomName`을 두면 실제 요청에서는 매칭되지 않고, 만약 FE가 hidden 이름을 보내게 되면 같은 hidden 이름을 가진 다른 칸을 가로챌 수 있다. 자격 등급(`grade_<n>`, hidden `grade`)과 외국어 등급(`gradeForeLang_<n>`, hidden `grade`)은 구조 이름 `grade`·`gradeForeLang`으로만 구분하며 `HyundaiCompanyFormPolicyFactoryTest`가 두 trigger를 함께 넣어 각각의 프로필 키로 매핑되는지 고정한다.
- FE 실행기(`policy/hidden-code/write.ts`)는 일반 버튼형 칸에서 라벨로 선택지를 찾아 클릭한 뒤 trigger 표시값과 hidden 값이 선택지의 `data-code`와 같은지 검증한다. 정책의 `optionCodeMap`은 BE 계약상 비어 있을 수 없고 교차 확인용이며, 계약에 등록된 exact/coded 칸(병역 등)에서만 정책 코드와 선택지 코드의 일치를 요구한다.

## 정책 v25의 경력·자격 매핑

- 입사·퇴사연월일(`tranStartDt`·`tranEndDt`, `maxLength 10`)은 v24까지 `YEAR_MONTH` 조합 바인딩이라 프로필 날짜(YYYY-MM-DD)에서 일자를 잘라냈다. 프로필 경력 날짜는 `date` 입력으로 일자까지 저장되므로(CF-333 근거의 "연월 단위" 전제는 틀렸다) v25는 자격 취득일과 같은 직접 바인딩을 쓴다. 보정 정책은 필요 없다.
- 종료사유는 v24까지 자유입력(`retResEtcCont`)에만 직접 바인딩이 있어 select를 비운 채 원문이 자유입력에 들어갔다. v25는 자유입력 규칙을 빼고 `retResCd` 버튼 규칙(선택지 16개, 별칭 `계약기간 만료`·`계약기간만료`·`계약 만료`→`계약만료`)을 둔다. 선택지에 없는 사유는 매핑되지 않아 결과 패널에 "확인 필요"로 남고, "기타" 자유입력은 사람이 쓴다.
- 자격 등급은 v24에 규칙이 없었다. v25는 `grade` 버튼 규칙(선택지 82개, 별칭 `단일등급`·`등급 없음`→`등급없음`)을 둔다.
- 로컬 factory는 v15로 같은 내용을 반영했고, `StartupPolicySeedHyundaiV25Test`가 v24 대비 차이가 위 세 가지뿐임을 고정한다. 실사이트 재측정은 dev 배포 뒤 #336 수정과 같은 하네스 세션에서 한다.
