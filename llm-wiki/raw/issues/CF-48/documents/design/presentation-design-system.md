# 발표 디자인 시스템

## 목적

이 문서는 원본 발표 자료를 열지 않고도 같은 시각 언어의 새 HTML/CSS 발표 화면을 만드는
생성 규칙이다. 발표 내용과 슬라이드 순서는 자유롭게 구성한다. 필요한 레이아웃을
독립적으로 선택하고 문구, 이미지, 발표명과 브랜딩을 슬롯에 넣는다.

이 시스템은 정적 슬라이드만 다룬다. 점진적 빌드업, 전환과 애니메이션은 사용하지
않는다. 같은 장면에 요소가 하나씩 늘어나는 원본의 연속 페이지는 하나의 완성된
레이아웃을 관찰하기 위한 근거일 뿐, 복제해야 할 순서가 아니다.

## 좌표계와 단위

모든 수치는 1920 × 1080 CSS px 캔버스를 기준으로 한다. 원점은 슬라이드 왼쪽 위이며
X는 오른쪽, Y는 아래로 증가한다. 위치, 크기, 글자와 선 굵기는 문서 값을 CSS px로
그대로 사용한다.

화면 표시 배율은 `min(viewportWidth / 1920, viewportHeight / 1080)`이다. 캔버스를
화면 가운데에 고정하고 왼쪽 위를 변환 원점으로 삼아 이 배율로 축소한다. 내부 요소의
좌표와 글자 크기를 개별적으로 다시 계산하지 않는다.

```css
:root {
  --slide-width: 1920px;
  --slide-height: 1080px;
  --slide-scale: 1;
}

*, *::before, *::after { box-sizing: border-box; }

.slide-stage {
  position: fixed;
  left: 50%;
  top: 50%;
  width: var(--slide-width);
  height: var(--slide-height);
  transform: translate(-50%, -50%) scale(var(--slide-scale));
  transform-origin: center;
}

.slide {
  position: relative;
  width: var(--slide-width);
  height: var(--slide-height);
  overflow: hidden;
}
```

```js
const scale = Math.min(window.innerWidth / 1920, window.innerHeight / 1080);
document.documentElement.style.setProperty("--slide-scale", String(scale));
```

## 시각 토큰

### 색상

| 의미 이름 | 값 | 용도 |
| --- | --- | --- |
| `surface-canvas` | `#1A1A1A` | 모든 슬라이드 배경 |
| `text-primary` | `#FFF9F9` | 제목, 본문과 핵심 도형 선 |
| `text-secondary` | `#8A8787` | 읽어야 하는 보조 설명과 라벨 |
| `text-muted` | `#4C4C4C` | 비활성 보조 텍스트, 원, 구분선과 장식 |
| `watermark` | `#232323` | 큰 배경 단어와 저대비 장식 |
| `accent-ai` | `#FF5C00` | AI 개념, 핵심 어절과 활성 원 |
| `accent-cs` | `#00FF8C` | CS 개념, 시스템 원인과 활성 원 |

배경은 항상 `surface-canvas`다. 흰색을 강조색 대신 남용하지 않고 기본 정보에만
사용한다. 한 슬라이드의 주 강조색은 `accent-ai` 또는 `accent-cs` 중 하나다. 두
강조색을 같은 위계로 함께 쓰지 않는다. 둘의 관계를 설명해야 하면 각각 한 개의
명시된 요소에만 적용하고 흰색을 중립 연결색으로 쓴다.

`text-muted`는 작은 본문에 사용하지 않는다. 읽어야 하는 보조 문구는 최소
`text-secondary`를 사용한다. 워터마크는 배경과 낮은 대비를 유지하고 본문보다 앞으로
나오지 않게 한다.

### 서체

기본 서체는 `Noto Sans KR`이다. 실행 환경에 설치되지 않았으면 전체 덱을
`Pretendard`로 바꾼다. 한 덱 안에서 두 서체를 섞지 않는다. 영문과 코드에도 같은
서체를 사용해 좁고 기하학적인 인상을 유지한다. 코드의 열 정렬이 반드시 필요할 때만
`D2Coding`을 보조 서체로 허용한다.

| 역할 | 크기 | 굵기 | 행간 | 자간 | 최대 분량 |
| --- | ---: | ---: | ---: | ---: | --- |
| `display-max` | 160 px | 700 | 0.92 | -0.04 em | 영문 12자 또는 한글 7자, 1줄 |
| `display` | 120 px | 300 또는 700 | 0.98 | -0.04 em | 18자, 최대 2줄 |
| `hero-title` | 96 px | 700 | 1.00 | -0.03 em | 줄당 12자, 최대 2줄 |
| `section-title` | 80 px | 300 | 1.05 | -0.03 em | 22자, 최대 2줄 |
| `heading` | 56 px | 700 | 1.10 | -0.025 em | 28자, 최대 2줄 |
| `body-large` | 44 px | 400 | 1.28 | -0.02 em | 줄당 32자, 최대 4줄 |
| `body` | 32 px | 400 | 1.42 | -0.015 em | 줄당 46자, 최대 7줄 |
| `caption` | 22 px | 400 | 1.35 | 0 | 한 줄 권장 |
| `meta` | 16 px | 500 | 1.20 | 0 | 한 줄 |
| `code` | 24 px | 400 | 1.35 | 0 | 줄당 62자, 최대 13줄 |

`display`와 `section-title`은 얇은 굵기 300을 기본으로 사용한다. 개념 이름, 결론과
표지 제목처럼 짧고 단단한 문구는 700을 사용한다. 한 텍스트 상자에서 크기는 바꾸지
않고 강조 어절의 색과 굵기만 바꾼다. 제목을 축소해 억지로 맞추지 말고 문구를
줄이거나 두 줄로 나눈다.

## 공통 프레임

### 안전 영역

기본 안전 영역은 `x=67..1853`, `y=44..1036`이다. 텍스트와 의미 있는 도형은 이
영역 안에 둔다. 워터마크와 화면 밖으로 이어지는 대형 장식만 안전 영역을 넘을 수
있다.

권장 간격은 8 px 배수다. 가장 많이 쓰는 값은 16, 24, 32, 48, 64, 96과 128 px다.
관련 요소 내부에는 16 또는 24 px, 제목과 본문 사이에는 32 또는 48 px, 독립된
영역 사이에는 64 px 이상을 사용한다.

정렬축은 다음 네 개만 사용한다.

| 이름 | 좌표 | 용도 |
| --- | ---: | --- |
| 왼쪽 안전축 | X 67 | 메타와 화면 가득한 장식 |
| 본문 왼쪽축 | X 216 | 설명형 슬라이드의 제목과 본문 |
| 중앙축 | X 960 | 질문, 개념과 섹션 전환 |
| 오른쪽 안전축 | X 1853 | 브랜딩과 오른쪽 정렬 요소 |

### 좌상단 메타 슬롯

메타 슬롯은 `x=67, y=44, w=360, h=32`다. `meta` 스타일을 사용하고 왼쪽 정렬한다.
내용은 발표명 또는 섹션명 한 줄이다. 발표 진행에 필요하지 않으면 슬롯 전체를
생략할 수 있지만 다른 위치로 옮기지는 않는다.

### 우상단 브랜딩 슬롯

브랜딩 슬롯은 `x=1784, y=44, w=91, h=91`이다. 마스코트, 팀 심볼 또는 발표자
브랜드를 담는다. 이미지는 투명 배경 PNG나 SVG를 사용하고 `contain` 방식으로 맞춘다.
슬롯 비율을 바꾸거나 원본 자산을 늘려 채우지 않는다. 자산이 없으면 슬롯 전체를
생략하며 빈 플레이스홀더를 남기지 않는다.

### 선과 도형

- 기본 선은 2 px `text-muted`다.
- 강조 원과 강조 구분선은 8 px이며 주 강조색을 사용한다.
- 패널 테두리는 2 px `text-muted`이며 채우기는 투명이다.
- 모서리는 기본적으로 각지게 둔다. 코드 패널만 12 px 반경을 허용한다.
- 그림자는 사용하지 않는다.
- 그라데이션과 입체 효과는 사용하지 않는다.
- 원형 개념은 정확한 원을 사용하고 타원으로 늘리지 않는다.

### 이미지와 스크린샷

사진과 화면 이미지는 의미 영역을 먼저 정하고 `cover` 방식으로 자른다. 제품 UI,
코드 결과와 터미널처럼 전체 맥락이 필요한 이미지는 `contain` 방식으로 맞춘다.
이미지 비율을 변형하지 않는다. 자른 뒤 핵심 피사체와 읽어야 하는 UI가 안전 영역
밖으로 나가면 안 된다.

스크린샷은 어두운 패널 위에 두고 2 px `text-muted` 테두리를 적용한다. 캡션은
이미지 아래 24 px 간격에 `caption`으로 둔다. 출처가 필요하면 캡션 마지막에 짧게
표시한다.

### 코드

코드는 배경 `#111111`, 테두리 `#2C2C2C`, 12 px 모서리 반경의 패널 안에 둔다.
본문은 `code` 스타일을 사용한다. 기본 텍스트는 `text-primary`, 주석은
`text-muted`, 핵심 한두 줄은 현재 슬라이드의 주 강조색으로 표시한다. 문법 색상을
여러 색으로 꾸미지 않는다. 13줄을 넘으면 코드 일부를 생략하거나 슬라이드를
분리한다. 글자를 24 px 아래로 줄이지 않는다.

## 교체 가능한 슬롯 계약

| 슬롯 | 필수 여부 | 교체 규칙 |
| --- | --- | --- |
| `presentation-meta` | 선택 | 발표명 또는 섹션명 한 줄, 좌상단 고정 |
| `brand-mark` | 선택 | 마스코트나 로고 한 개, 우상단 고정, `contain` |
| `headline` | 레이아웃별 필수 | 레이아웃의 줄 수와 글자 수 한계 준수 |
| `supporting-copy` | 선택 | 제목보다 한 단계 이상 낮은 위계 사용 |
| `accent-phrase` | 선택 | 핵심 어절 한 곳만 색상 변경 |
| `primary-image` | 이미지 레이아웃에서 필수 | `cover` 또는 `contain`을 명시하고 비율 유지 |
| `code-sample` | 코드 레이아웃에서 필수 | 13줄 이하, 비식별 예시 사용 |
| `concept-labels` | 개념 레이아웃에서 필수 | 원 하나당 짧은 명사구 하나 |

슬롯을 채우지 않을 때는 플레이스홀더, 빈 테두리와 안내 문구를 모두 제거한다. 새
콘텐츠가 한계를 넘으면 글자 크기를 줄이지 않고 더 짧게 편집하거나 다른 레이아웃을
선택한다.

## 독립 레이아웃

아래 레이아웃은 발표 순서와 관계없이 한 장씩 선택한다. 모든 좌표는 논리 px다.
공통 메타와 브랜딩 슬롯은 각 레이아웃의 선택 요소다.

### L01 표지

짧은 발표 제목과 한 줄 설명으로 시작할 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 제목 | `x=67, y=640, w=760, h=240` | `hero-title`, 왼쪽 및 아래 정렬 |
| 설명 | `x=835, y=760, w=500, h=100` | `body`, 왼쪽 정렬 |
| 작성자 | `x=1470, y=904, w=360, h=32` | `meta`, 오른쪽 정렬, 이름만 강조색 |

제목은 두 줄 이하이며 한 줄에 한 의미 덩어리를 둔다. 제목, 설명과 작성자 외의 본문을
추가하지 않는다. 표지 이미지는 사용하지 않는 것이 기본이다.

### L02 빈 호흡

발표자가 말로 장면을 전환하거나 앞 문장의 여운을 남길 때 사용한다. 배경과 선택적인
공통 슬롯 외에는 아무 요소도 두지 않는다. 빈 슬라이드에 안내 문구나 페이지 번호를
추가하지 않는다.

### L03 원형 개념 지도

하나의 중심 개념과 주변 개념의 관계를 보여줄 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 중심 원 | `x=711, y=293, w=498, h=498` | 8 px 주 강조색 선, 투명 채우기 |
| 중심 라벨 | 중심 원 내부 | `heading`, 주 강조색, 중앙 정렬 |
| 주변 원 | 지름 208 또는 244 | 2 px `text-muted`, 투명 채우기 |
| 주변 라벨 | 각 원 안쪽 24 px | `caption`, 중앙 정렬 |

주변 원은 3개부터 8개까지 사용하며 중심 원과 24 px 이상 겹치게 하거나 48 px 이상
떨어뜨린다. 어중간하게 닿게 두지 않는다. 활성 관계만 주 강조색으로 바꾸고 나머지는
`text-muted`로 남긴다. 선으로 모든 원을 연결하지 않는다. 점진적으로 원을
추가하는 복제 슬라이드는 만들지 않는다.

### L04 워터마크 질문 또는 선언

질문, 반전과 결론처럼 한 문장을 강하게 전달할 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 워터마크 | `x=960, y=365, w=600, h=380` | `display-max`, `watermark`, 중앙 정렬 |
| 주 문장 | `x=360, y=444, w=1200, h=192` | `heading`, 중앙 정렬 |

워터마크는 영문 단어 또는 한 글자이며 주 문장 뒤에 놓는다. 주 문장은 두 줄 이하,
줄당 28자 이하다. 핵심 어절 하나만 강조색을 쓸 수 있다. 설명 문단과 이미지를 함께
놓지 않는다.

### L05 섹션 전환

새로운 개념군을 여는 데 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 섹션 제목 | `x=430, y=380, w=1060, h=230` | `section-title`, 중앙 정렬 |
| 짧은 설명 | `x=560, y=625, w=800, h=60` | `body`, 중앙 정렬 |

제목은 최대 두 줄이며 얇은 굵기를 기본으로 한다. 설명은 한 줄만 허용한다. 배경
이미지, 패널과 목록은 사용하지 않는다.

### L06 대형 키워드

짧은 개념 이름과 한 문장 정의를 기억시키는 데 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 키워드 | `x=280, y=360, w=1360, h=180` | `display-max`, 중앙 정렬 |
| 정의 | `x=360, y=570, w=1200, h=100` | `body-large`, 중앙 정렬 |

키워드는 한 줄, 정의는 두 줄 이하다. 핵심 어절 하나를 주 강조색으로 표시할 수 있다.
키워드가 길면 `display`로 한 단계만 낮출 수 있으며 그보다 작게 줄이지 않는다.

개념의 상태 변화를 보여줄 때는 측면 단어 변형을 사용할 수 있다. 측면 단어는
`x=-24, y=170, w=320, h=760`에서 90도 회전한 `display-max`와
`text-muted`로 표시한다. 핵심 단어는 `x=300, y=300, w=800, h=180`, 설명은
`x=1120, y=390, w=660, h=260`에 둔다. 측면 단어는 한 단어, 설명은 네 줄 이하다.
이 변형의 완성 전 상태를 별도 슬라이드로 만들지 않는다.

### L07 분할 비교

두 대상의 구조, 책임 또는 속성을 같은 기준으로 비교할 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 왼쪽 영역 | `x=216, y=250, w=650, h=600` | 왼쪽 대상 |
| 구분선 | `x=960, y=245, w=2, h=610` | 2 px `text-muted` |
| 오른쪽 영역 | `x=1054, y=250, w=650, h=600` | 오른쪽 대상 |
| 영역 제목 | 각 영역 상단 72 px | `heading`, 중앙 정렬 |

양쪽은 같은 수의 항목과 같은 시각 문법을 사용한다. 항목은 영역당 3개 이하, 항목
라벨은 두 줄 이하다. 우열을 말하지 않는 비교에서는 한쪽만 강조색으로 칠하지 않는다.

### L08 코드

실제 구문이나 터미널 결과를 설명할 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 제목 | `x=216, y=185, w=1450, h=100` | `heading`, 왼쪽 정렬 |
| 코드 패널 | `x=216, y=330, w=1040, h=560` | 코드 규칙 |
| 설명 | `x=1320, y=410, w=430, h=360` | `body`, 왼쪽 정렬 |

코드가 핵심이면 패널을 `x=216..1704`까지 넓히고 설명을 제목 아래 한 줄로 옮길 수
있다. 한 패널에는 한 파일이나 한 실행 결과만 넣는다.

### L09 스크린샷

제품 UI, 도구 화면이나 시각 결과를 근거로 보여줄 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 제목 | `x=216, y=185, w=1450, h=100` | `heading`, 왼쪽 정렬 |
| 이미지 패널 | `x=216, y=330, w=1040, h=560` | 스크린샷 규칙, `contain` |
| 설명 | `x=1320, y=410, w=430, h=360` | `body`, 왼쪽 정렬 |

이미지가 핵심이면 패널을 `x=216..1704`까지 넓히고 설명을 제목 아래 한 줄로 옮길 수
있다. 읽을 수 없는 전체 화면 캡처 대신 설명 대상이 보이는 영역만 자른다. 코드와
스크린샷을 같은 패널에 겹치지 않는다.

### L10 계층 구조

포함 관계, 실행 계층과 책임 경계를 보여줄 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 바깥 상자 | `x=216, y=170, w=1488, h=720` | 2 px `text-muted`, 투명 채우기 |
| 중간 상자 | 바깥 상자 안쪽 64 px | 2 px `text-muted`, 투명 채우기 |
| 안쪽 상자 | 중간 상자 안쪽 64 px | 2 px `text-muted`, 투명 채우기 |
| 가장 안쪽 상자 | 안쪽 상자 안쪽 64 px | 2 px `text-muted`, 투명 채우기 |
| 계층 라벨 | 각 상자 좌상단에서 24 px | `heading` 또는 `body-large` |
| 제한 설명 | 라벨 아래 16 px | `caption`, 주 강조색 |

계층은 최대 네 단계다. 상자 크기는 안쪽으로 갈수록 가로와 세로가 모두 작아져야 한다.
화살표 없이 포함 관계가 명확해야 하며, 설명 문장을 상자 밖에 흩어 놓지 않는다.

### L11 매핑 요약

앞에서 소개한 개념을 실제 역할이나 사용 시점에 대응시킬 때 사용한다.

| 요소 | 위치와 크기 | 스타일 |
| --- | --- | --- |
| 상단 안내 | `x=216, y=150, w=1488, h=70` | `body`, 왼쪽 정렬 |
| 열 제목 | `x=216, 732, 1248, y=290`, 각 `w=420` | `heading`, 중앙 정렬 |
| 행 본문 | `y=390..860`, 최대 7행 | `caption`, 중앙 정렬 |
| 연결선 | 열 사이 | 2 px `text-muted`, 수평 |

세 열의 권장 폭은 각각 420 px이며 열 사이 간격은 96 px다. 셀 배경과 바깥 표 테두리는
쓰지 않는다. 행의 의미는 정렬과 짧은 연결선으로 드러낸다. 한 셀은 두 줄을 넘지
않으며 행이 7개를 넘으면 두 슬라이드로 나눈다.

## 조합 규칙

- 레이아웃은 순서와 무관하게 선택한다.
- 한 슬라이드는 하나의 주장만 전달한다.
- 텍스트 위계는 세 단계 이하로 제한한다.
- 주 강조색은 슬라이드당 하나다.
- 의미 있는 요소 사이에는 최소 24 px, 독립 영역 사이에는 최소 64 px를 둔다.
- 같은 정보의 완성 전 상태를 별도 슬라이드로 만들지 않는다.
- 앞 슬라이드와 같은 레이아웃을 반복할 때 콘텐츠 전체를 교체한다.
- 장식보다 빈 공간을 우선한다.

## 금지 사례

- 16:9가 아닌 캔버스 또는 1920 × 1080과 다른 논리 좌표계
- 검정 `#000000` 배경이나 순백 `#FFFFFF` 본문으로 임의 변경
- 한 슬라이드에서 주황과 초록을 장식 목적으로 동시에 반복 사용
- Noto Sans KR와 Pretendard 혼용
- 글자 크기를 토큰보다 줄여 콘텐츠를 억지로 맞추기
- 본문을 `text-muted`로 표시해 대비를 낮추기
- 그림자, 그라데이션, 입체 도형과 장식 아이콘 추가
- 이미지를 비율과 다르게 늘리기
- 읽을 수 없는 전체 화면 스크린샷이나 13줄을 넘는 코드
- 빈 이미지 프레임, 빈 로고 상자와 플레이스홀더 문구 유지
- 슬라이드 번호, 발표 순서와 고정 내러티브를 디자인 규칙으로 강제
- 점진적 빌드업용 중간 슬라이드, 전환과 애니메이션 추가

## 생성 후 검증

1. 캔버스와 검증 뷰포트가 1920 × 1080 CSS px인지 확인한다.
2. 모든 슬라이드의 배경이 `surface-canvas`인지 확인한다.
3. 덱 전체가 Noto Sans KR 또는 Pretendard 한 종류만 사용하는지 확인한다.
4. 텍스트와 의미 도형이 안전 영역 안에 있는지 확인한다.
5. 모든 슬롯이 실제 콘텐츠를 갖거나 완전히 제거됐는지 확인한다.
6. `scrollWidth > clientWidth` 또는 `scrollHeight > clientHeight`인 텍스트 상자가 없는지
   검사하고 모든 의미 요소의 `getBoundingClientRect()`가 캔버스 경계 안인지 확인한다.
7. 의도적인 워터마크와 중첩 원을 제외한 겹침을 검사한다.
8. 모든 슬라이드를 PNG로 렌더링해 전체 크기로 확인한다.
9. 최소한 표지, 문장, 비교, 원형 지도, 코드 또는 스크린샷, 계층과 요약 레이아웃을
   한 번씩 생성해 규칙만으로 재현 가능한지 확인한다.
10. 원본 대응 유형과 비교할 때 색상, 타이포그래피, 여백, 정렬, 선, 원, 코드와 이미지
    슬롯만 평가하고 문구와 슬라이드 순서는 평가하지 않는다.
11. 임시 HTML, CSS와 렌더 이미지는 저장소 밖 작업 디렉터리에만 둔다.
