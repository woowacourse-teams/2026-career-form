# Jev fields 요청 한도와 응답 검증

2026-10-13 실사이트 fields 요청 재전송에서 확인한 Typesafe Jev 연동의 제약이다.

- `JevFieldMappingResolver`는 후보마다 질문을 만들고 질문마다 프로필 키 선택지 119개를 넣는다. 질문이 많으면 Typesafe가 `400 {"detail":{"error_type":"max_tokens_exceeded"}}`를 반환한다. 페이지 전체를 state로 넣은 크래프톤 요청에서 질문 12개는 성공하고 13개부터 실패했다.
- 실패는 크기에 따라 경계가 흔들린다. 같은 하위 요청이 성공과 실패로 갈린 경우가 있었다.
- Jev는 선택지 확률을 소수 둘째 자리로 반올림해 반환하므로 확률 합이 0.99가 될 수 있다. 현재 `JevClient`의 확률 합 허용 오차 0.01은 이런 정상 응답을 거부하고 사유를 로그에 남기지 않는다.
- 위 두 문제로 네이버(69칸), 안랩(37칸), 크래프톤(102칸) fields 요청은 Jev에서 `LLM_UNAVAILABLE`이 됐다. 질문 묶음 전송과 허용 오차 조정은 별도 백엔드 작업 대상이다.
