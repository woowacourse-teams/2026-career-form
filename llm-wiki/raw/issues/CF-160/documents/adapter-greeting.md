# Greeting 잠긴 기본정보와 날짜·주소 입력 보완

## 적용 경계

manifest의 Supersedes로 연결한 CF-94 계약의 DNS/DOM 판별, 기존 API, 회사 어댑터 우선순위와 승인 경계는 유지한다. 아래 변경은 CF-160에서 확인한 공통 Greeting 동작에 적용한다. 기업별 host 허용 목록이나 범용 분석 우회를 추가하지 않는다.

## 사이트 식별과 쓰기 허용 분리

현대오토에버는 Greeting CNAME과 공통 DOM을 사용하는 기존 정책 대상이다. 같은 분석 서버에 보낸 비식별 요청에서 disabled 이름·전화는 `ADAPTER_STRUCTURE_MISMATCH`, 잠김 없는 요청은 `COMPLETE`였다. 수정된 로컬 API는 잠긴 이름·전화를 `BLOCKED`로 유지하고 편집 가능한 이메일을 `READY/SET_TEXT`로 반환했다.

유일한 최상위 visible text 이름·전화와 소유 구조가 맞으면 disabled 계정 필드도 사이트 식별 근거가 된다. readonly·inert·숨김·중복·잘못된 제어 및 반복 행 위장은 계속 거부한다. 구조 식별 허용은 쓰기 허용이 아니다. BE `FieldInteractionPolicy`와 FE candidate registry는 disabled 필드에 쓰기 명령을 주지 않는다.

## 날짜 정밀도와 실패 격리

일 단위 달력에 월 문자열을 넣고 Enter를 누르면 포커스된 날짜가 확정될 수 있다. 실제 day view를 확인하면 완전한 날짜를 사용한다. 빈 칸에서 시작한 달력이 다른 날짜를 확정한 경우 유일한 clear-trigger로 원복하고, 원복 여부를 `DATE_UNCONFIRMED` 또는 `DATE_ROLLBACK_FAILED`로 구분한다. 이미 있던 다른 날짜를 지우는 처리는 하지 않는다.

날짜·검색 state driver가 실패하면 이름 있는 컨트롤 하나만 소유한 field root를 보류하고 나머지 입력을 계속한다. 여러 컨트롤이 묶인 영역이나 후속 필드를 드러내는 라디오·체크박스·버튼 선택 실패에는 이 격리를 적용하지 않는다.

## 표시값과 선택 증거

관측한 Greeting 검색 combobox는 값이 있는 상태로 다시 열면 선택 항목을 렌더링하지 않을 수 있다. 표시값이 프로필과 같아도 선택 증거를 확인하지 못하면 성공으로 승격하지 않는다. `SEARCH_SELECTION_UNVERIFIED` 또는 `VALUE_MATCH_UNRECORDED`를 전달하고 결과는 입력 실패와 구분한 확인 대상으로 남긴다.

## 현주소 검색

같은 출처의 주소 찾기 dialog에서 우편번호와 도로명 주소가 정확히 하나 일치하는 결과만 선택한다. 검색을 검증하지 못하면 상세주소도 쓰지 않는다. 기존 다른 주소와 실행 도중 바뀐 사용자 값을 보존한다.

주소 모달은 배경 입력칸을 `aria-hidden`으로 가린다. 모달 안에서는 원래 주소 입력칸의 유일한 이름·동일 요소·readonly/disabled 상태를 확인한다. 결과 클릭 직전에는 비동기 프로필 확인 이후에도 같은 열린 dialog·검색어·유일 결과가 유지되는지 다시 확인한다. 상세주소를 쓰기 직전에도 다른 기존 값이 없는지 검사한다.

닫기 클릭 직후에는 배경이 계속 가려져 있을 수 있다. 모달 종료와 배경 `aria-hidden`/`inert` 복구까지 기다린 뒤 후속 필드를 처리한다. 복구를 확인하지 못하면 정상 완료로 진행하지 않는다.

## 검증 범위

- 계정 잠금 API 회귀는 분석 완료와 잠긴 필드의 쓰기 금지를 함께 확인한다.
- 달력 day 정밀도·다른 날짜 원복·실패 격리, 표시값과 선택 증거 구분을 합성 회귀로 확인했다.
- 주소 모달의 배경 숨김과 비동기 닫힘을 반영한 회귀 3개는 수정 전 실패하고 수정 후 통과했다. 프로필 확인 중 상세주소 변경과 중복 결과 추가도 각각 실패를 재현한 뒤 보호 조건을 보완했다.
- 실제 페이지에서 주소 창이 배경 입력칸 60개를 가리고 다음 화면 갱신에서 복구되는 것을 관측했다. 수정 모듈의 비일치 검색은 지원서 값 불변, 반환 시 숨김 입력칸 0개·열린 주소 창 0개와 버튼 복구를 확인했다.
- 사용자는 자동 기입이 동작한다고 확인했다. 에이전트가 최종 설치 확장으로 전체 항목의 첫 실행·재실행을 독립 대조한 것은 아니며, 모든 필드와 다른 회사 화면의 성공으로 확대하지 않는다. 실제 저장·제출·페이지 이동·미리보기와 운영 배포는 수행하지 않았다.

필드별 범위는 [CF-160 현황](adapter-field-inventory.md)을 따른다.
