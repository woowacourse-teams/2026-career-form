# CF-160 Greeting 추가 필드와 검증 범위

manifest의 Supersedes로 연결한 CF-94 필드 현황의 다른 회사와 기존 Greeting 항목은 유지한다. 아래 표는 CF-160의 추가 연결이며, 자동 회귀에서 확인한 코드 지원을 모든 실사이트 입력 성공으로 표시하지 않는다.

| 범주 | 추가 연결 | 경계 |
| --- | --- | --- |
| 계정 연결 기본정보 | disabled 이름·전화를 사이트 식별 근거로 인정 | 값·잠금 유지, 쓰기 명령 없음 |
| 현주소 | 우편번호·기본주소·상세주소 | 유일한 정확 검색 결과만 선택, 검색 미확인 시 상세주소도 보류, 모달 종료 후 배경 복구 대기 |
| 경력 | 퇴직사유 | 기존 경력 행 경계 유지 |
| 대학교 | 총 이수학점 | 대응 프로필 키가 있는 대학에 한정 |
| 대학교·대학원 | 학교 소재지 | 확인된 지역 표시명과 같은 반복 행에 한정 |
| 프로젝트 | 이름·역할·내용·시작일·종료일과 행 추가 | `workHistory.projects` 반복 경계, FE·BE의 `SELECT_DATE` 계약 일치 |
| 공인어학 | 등록번호 | 해당 시험 행에 한정 |
| 자격증 | 등급·등록번호 | 해당 자격증 행에 한정 |
| 병역 | 병과·병역구분·제대구분 | 확인된 표시명 연결, 만기전역→만기제대 등 명시적 대응만 적용 |
| 장애 | 장애등록번호 | 기존 승인·조건부 필드 경계 유지 |
| 보훈 | 보훈관계 | 확인된 관계 표시명에 한정 |

대응 프로필 키가 없는 보훈비율과 프로젝트의 client/placeOfEmployment/contribution 등은 미지원으로 유지한다. 자유 텍스트를 표준 학교·자격증으로 추정하는 기능은 이 변경에 포함하지 않는다.

## 검증 구분

BE 매핑·입력 명령과 FE 수집·반복 행·날짜 명령 계약은 자동 회귀로 확인한다. 날짜는 실제 day/month 정밀도를 구분하고 잘못 확정된 날짜를 원복한다. 표시값은 같지만 선택 증거가 없으면 확인 필요로 남긴다.

주소 모달 실패 경로는 실제 페이지에서 지원서 값 불변과 입력 가능 상태 복구를 확인했다. 사용자의 동작 확인은 있으나 최종 설치 확장의 전체 항목 첫 실행·재실행을 에이전트가 독립 검증한 것은 아니다. 전체 필드 성공·다른 회사의 지원·실제 저장 호환성을 주장하지 않는다. 구조·보호 조건과 상세 관측은 [CF-160 계약](adapter-greeting.md)을 따른다.
