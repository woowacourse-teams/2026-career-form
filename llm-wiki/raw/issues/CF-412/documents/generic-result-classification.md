# 범용 결과 화면 분류와 수집 제외

## 결과 분류

- 확인 필요에는 프로필 값이 있는데 처리하지 못했거나 넣은 값을 확인해야 하는 칸만 둔다.
- 프로필 값이 없는 칸은 등급과 상관없이 확인 필요에서 뺀다. 프로필 항목 연결이 없으면 "프로필에 없는 항목", 연결됐지만 값이 없으면 "프로필 미입력" 회색 접힘 묶음으로 보낸다. 묶음은 개수만 먼저 보여 주고 실패 태그를 쓰지 않는다.
- 빨간 테두리는 범용에서 확인 필요 칸에만 그린다. #389의 "모두 빨강" 결정을 바꾼다.
- 필수 칸은 따로 표시하지 않는다. 범용 경로에서 필수 판정 기준이 사이트마다 달라 오판할 수 있다.
- 숨긴 중복 칸(hiddenFromReview)과 확인 필요 행과 같은 입력칸은 회색 묶음에서 세지 않는다.
- 개발자 진단의 결과 개수는 화면과 같은 함수로 계산한다.
- 묶음과 테두리 변경은 범용 경로에만 적용하며 정적 경로는 바뀌지 않는다.

원인은 #397에서 추가한 BLOCKED 분기였다. 프로필 값이 없어도 BLOCKED이면 "입력 못함"으로 세어서 실패가 많은 것처럼 보였다. 비식별 실측 한 건에서 확인 필요가 46칸에서 11칸으로 줄었고 34칸은 회색 묶음으로 옮겨졌다. 실측은 한 사이트이고 다른 구조는 합성 시험으로 확인했다.

## 수집 제외

범용 수집은 페이지 수준 contentinfo 랜드마크 안에 있으면서 form 밖에 있는 입력칸을 지원서 칸으로 세지 않는다. 랜드마크는 role=contentinfo이거나, article·aside·main·nav·section 조상이 없는 footer다(HTML-AAM 대응 규칙). form 안의 footer와 구획 안의 footer에 있는 칸은 계속 수집한다.

## health 구역 분류

범용 health 키를 NONE 구역으로 두어 범용 매핑에서 빼는 정책을 유지한다(2026-11-05 사용자 결정). 지원하려면 단위와 값 형식 계약이 필요하므로 별도 Issue로 다룬다.
