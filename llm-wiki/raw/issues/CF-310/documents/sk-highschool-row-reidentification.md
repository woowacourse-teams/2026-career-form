## 승인 후보

SK R262309형 공고의 고교 행(학교명·지역 없음)에서 후속 추가 버튼 재식별 조건이 실패하는 구조다.

## 근거

- **증상:** 공고 R262309의 지원서에서 자동 기입이 고등학교 행을 하나 추가한 뒤 "화면 갱신 뒤 추가 동작을 다시 찾지 못했습니다 (고등학교 학력 정보 추가)" 예외로 멈춘다. 2026-10-21 일회성 스크립트 4회(기존 값 초기화 유무 무관)와 2026-10-22 `frontend/scripts/live-qa` 하네스 1회에서 같은 제목으로 재현됐다. 2026-10-22 실행에서는 기대한 행 12개 중 고등학교 1행만 만들어졌고, 실행 전 입력 가능 칸 중 병역 대상 분류 1칸만 입력됐다.
- **행 구조 차이:** 2026-10-22 실행 후 수집에서 R262309의 새 고등학교 행 컨트롤은 `academicCourse01`, `eduhgEducationStatus`, `eduhgFromDate`, `eduhgToDate` 네 개였다. 같은 날 같은 하네스로 측정한 R262303의 고등학교 행은 여기에 `eduhgEducationName`과 `eduhgEducationRegion`이 더 있었다. 즉 이 공고의 고등학교 행에는 학교명 입력과 지역 선택이 없다.
- **재식별 조건:** SK 정책(`backend/src/main/resources/policies/sk-browser-v1.json`)의 `btnAddEducationHigh` 행 추가 규칙은 `requiredSelector`로 `input[name='eduhgEducationName']`을 요구한다. 정책 수집(`frontend/src/autofill/policy/collection.ts`)은 행 안에서 이 선택자에 맞는 요소가 정확히 하나일 때만 후속 추가 버튼을 같은 동작으로 인정한다. 준비 실행기(`frontend/src/autofill/preparation/executor.ts`)는 클릭 뒤 같은 동작을 다시 찾지 못하면 `action-not-reidentified`로 멈추고, 실패 문구 변환이 위 패널 제목을 만든다.
- **이전 서술의 정정:** 2026-10-21 보고서는 "원래 위치의 버튼이 숨겨지고 새 행 안의 버튼이 보여 재탐색에 실패한다"고 적었다. 추가 뒤 원래 버튼이 숨고 행 안 버튼이 보이는 것은 모든 SK 공고의 정상 동작이고(저장소 fixture와 반복 준비 테스트가 같은 구조), R262303·R262305는 같은 조건에서 정상 동작했다. 차이는 버튼 위치가 아니라 고등학교 행에 학교명 입력이 없다는 점이다. 같은 보고서의 "이메일·연락처까지 비어 있다"는 QA가 실행 전에 화면 값을 비운 결과이며 제품 증상이 아니다.
- **측정 영향:** 2026-10-22 QA에서 R262309는 입력 가능 95칸(실행 전·새 칸 17 + 만들어지지 않은 행 11개의 추정 칸 78) 중 정답 1칸으로 집계됐다. 미생성 행의 칸 수는 실제로 만들어진 고등학교 행 구조로 다시 추정한 값이다.

## 쓰임

- 수정 방향: 후속 추가 버튼 재식별을 학교명 입력의 존재에 의존하지 않게 바꾼다(행 수 증가나 행 컨테이너 기준). 회귀 fixture는 학교명·지역이 없는 고등학교 행 구조로 만든다.
- 실사이트 QA 하네스 보고서는 이 실행을 `extension-exception`으로 표시하고 만들어지지 않은 행의 칸을 분모에 더한다.
