이 문서는 2026-10-21에 승인된 CF-310 후보 2를 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 어댑터 계약은 바꾸지 않는 새 운영 지식이며, 바꾸지 않은 내용은 Supersedes가 가리키는 CF-168 근거를 따른다. 실제 지원값·계정·세션·URL 쿼리·대화 전문은 포함하지 않는다.

## 승인 후보

Greeting의 학교·전공 검색은 지원 페이지로 보내는 Next.js 서버 액션이고, 본문은 12–43바이트다.

## 근거

- 후보의 12–43바이트는 본문 크기를 바이트로 기록한 두 지원서(kakaogames 22건 12–43바이트, kurly 15건 12–38바이트)의 범위다. 아래처럼 다른 기록은 글자 수로 남아 있어 바이트 범위의 근거가 되지 않는다.
- 2026-10-21 실사이트 QA에서 kurly·zigbang·kakaogames 지원서를 실행했을 때, 학교·전공 검색은 지원 페이지 주소(`/<언어>/o/<공고 번호>/apply`)로 보내는 POST였고 `Next-Action` 헤더가 붙었다. 관측한 언어 경로는 `ko`뿐이다. 서버 액션이므로 별도 API 경로가 없다. 로그는 어느 칸의 조회인지 남기지 않으며, 같은 실행이 회사명·시험명·자격증명·국적도 검색했으므로 아래 건수와 크기에는 학교·전공 외의 검색도 섞여 있을 수 있다.
- 허용 목록을 도입하기 전 그날 실행 기록의 서버 액션 조회는 74건이었다. 그중 하네스가 바이트로 기록한 kakaogames 22건은 본문이 12–43바이트였다. 이전 일회성 도구가 글자 수(`body.length`)로 기록한 나머지 52건(kurly·zigbang·kakaogames)은 12–28자였다. 같은 kurly 화면의 두 기록이 한글 한 글자당 2씩 차이 나는 것은 본문에 한글 검색어가 있다는 정황이다.
- 허용 목록으로 바꾼 뒤 다시 실행한 kurly 지원서에서는 검색 15건이 12–38바이트였고 모두 조회로 허용됐다.
- 지원 페이지 경로가 `apply`라서, 경로 낱말로 저장성 요청을 막던 첫 차단 규칙은 이 검색 요청까지 막았다. 그래서 경로가 아니라 `Next-Action` 헤더와 본문으로 조회를 구분해야 한다.

## 쓰임

`frontend/scripts/live-qa/requests.mjs`는 지원 페이지로 가는 서버 액션 가운데 본문이 200바이트 이하이고, 원소가 60자 이하 문자열·유한한 숫자·null이거나 그 값만 가진 평평한 객체인 비어 있지 않은 JSON 배열이며, 지원서 내용 낱말이 없는 요청만 조회로 허용한다. 본문이 없거나 읽을 수 없으면 막는다.
