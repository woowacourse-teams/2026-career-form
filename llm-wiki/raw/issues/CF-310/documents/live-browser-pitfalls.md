# 실사이트 평가 브라우저의 원복과 대화상자 함정

> Issue: CF-310
> Collected: 2026-10-21
> Approval-Digest: 613b4acd5fd87f8d2186b4ac401715fbed539b93eea1421f11163fb5591ee258
> Source-Revision: 149b350a7ed85aefcb65448f816c6901d30f2b12

이 문서는 2026-10-21에 승인된 CF-310 후보 3과 4를 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 평가 계약은 바꾸지 않는 새 운영 지식이며, 바꾸지 않은 내용은 Supersedes가 가리키는 CF-173 평가 계약 1.1을 따른다. 실제 지원값·계정·세션·URL 쿼리·대화 전문은 포함하지 않는다.

정리한 도구는 `frontend/scripts/live-qa` 실사이트 QA 하네스다. 이 하네스는 CF-177 live-eval 도구에서 상주 브라우저와 단계 이동 코드를 옮겼다. 새로고침 원복의 잔존 값은 이 하네스의 전신인 2026-10-21 일회성 QA 스크립트에서, 대화상자 자동 처리는 Playwright 1.64.0 소스에서 확인했고, 수정 뒤 확인은 하네스로 했다. 여기서 원복은 자동 기입 뒤 합성 값을 버리려고 같은 지원서를 저장 없이 다시 여는 동작이다.

## 승인 후보

3. Chrome은 새로고침 때 입력값을 복원한다. 그래서 원복은 `#`을 뗀 주소로 새로 이동해야 한다.
4. Playwright로 브라우저에 붙으면, 대화상자를 듣는 코드가 없을 때 모든 탭의 대화상자를 스스로 처리한다. 일반 창은 닫고, 페이지 이탈 확인은 수락한다.

## 근거: 새로고침 원복

- 2026-10-21 일회성 QA 스크립트가 자동 기입 뒤 `page.reload()`로 원복했더니 직방·카카오게임즈(Greeting) 지원서에 합성 값이 그대로 남아 있었다. 서버 저장은 없었고, 그 탭들은 이미 비웠다.
- `#`이 붙은 같은 주소로 이동하면 같은 문서 안 이동이라 값이 남는다. 그래서 하네스는 Greeting 같은 일반 페이지에서 `#`을 뗀 주소로 `goto`하고, 이동 전에 심은 marker가 사라졌는지로 새 문서인지 확인한다. marker를 심지 못하면 이동하지 않고 실패로 끝낸다. 에이치닷 MRS2 페이지는 저장 없이 같은 단계를 다시 여는 POST로 원복한다.
- 이어서 같은 주소(쿼리와 `#` 제외)인지, 에이치닷은 같은 단계인지, 칸 수가 실행 전의 80% 이상인지, 값이 남아 있는 칸(숨은 칸 포함)이 칸마다 실행 전 값과 같은지 검증한다. 같은 날 카카오모빌리티(칸 18/18)와 kurly(칸 48/48)에서 이 검증을 통과했다.

## 근거: Playwright 대화상자 자동 처리

- Playwright 1.64.0은 context와 page 어디에도 `dialog` 구독이 없으면 서버의 `DialogManager`가 `beforeunload`는 accept, 나머지는 dismiss한다. client의 `BrowserContext`도 구독은 있으나 listener가 없는 경우에 같은 기본값을 적용한다. dismiss는 확인창에 취소로 답한다.
- `connectOverCDP`로 평가 브라우저에 붙으면 이 처리는 붙어 있는 동안 그 브라우저의 모든 탭에 적용된다. 사람이 그 브라우저에서 작성 중인 탭도 포함된다. 그래서 확인창의 저장·삭제가 사람 몰래 취소되거나, 작성 중인 탭의 이탈 확인이 수락될 수 있다.
- 그래서 `frontend/scripts/live-qa/dialogs.mjs`는 붙는 명령마다 context 전체에 listener를 먼저 걸고 로그인 연장 확인창만 수락한다. 나머지 대화상자는 그대로 열려 있어 사람이 답한다. 하네스가 구동하는 탭은 따로 맡아 로그인 연장 확인창은 수락하고 그 밖의 사이트 대화상자는 dismiss한다. 페이지 이탈 확인은 원복하는 동안에만 수락하고 그 밖에는 열어 둔다.
