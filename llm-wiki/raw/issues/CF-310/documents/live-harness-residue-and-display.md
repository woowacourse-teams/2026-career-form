# 실사이트 QA 하네스의 원복 재키 대조와 표시 규칙의 한계

> Issue: CF-310
> Collected: 2026-10-22
> Approval-Digest: 6e367ec4018bfd976fab32c98e94b94d35cfc59d33de0747f61917e65736919f
> Source-Revision: 733c097092f54154e8be5e91bb4b10863b75c193

이 문서는 2026-10-22에 승인된 CF-310 후보 3과 후보 5를 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates-2.md) 전체 UTF-8 바이트의 SHA-256이다. 평가 계약을 바꾸지 않는 하네스 운영 지식이며, 바꾸지 않은 내용은 Supersedes가 가리키는 [원복·대화상자 근거](live-browser-pitfalls.md)를 따른다. 실제 지원값·계정·세션·URL 쿼리·대화 전문은 포함하지 않는다.

## 승인 후보

- SK는 새로고침마다 숨은 행 템플릿의 이름(GUID 접미사)이 바뀌어 원복 검증을 값으로 대조해야 한다.
- 하네스 표시 규칙의 한계: 실행 전 값 지문을 페이지 전체와 대조해 우연히 같은 값이 확인 불가로 가려진다.

## 근거

### 원복 검증의 재키 대조

- SK 지원서는 화면에 보이지 않는 행 템플릿 입력을 두고, 그 `name`에 붙는 GUID 접미사를 페이지를 열 때마다 새로 만든다. 2026-10-22 R262303 첫 실행에서 원복 뒤 칸을 이름으로 대조하자 값이 같은데도 이름이 바뀐 칸 46개가 "예상 밖"으로 집계돼 원복 검증이 실패했다.
- `frontend/scripts/live-qa/page/census.mjs`의 `discardResidue`는 먼저 같은 이름의 칸끼리 지문을 비교하고, 실행 전에 없던 이름의 칸은 실행 전 값 지문 풀과 대조해 `rekeyed`로 센다. 이 대조로 다시 실행한 R262303·R262305·R262309는 "예상 밖" 0으로 검증을 통과했고, 결과 수치는 첫 실행과 같았다.
- 한계: 재키 대조는 값 지문만 보므로 숨은 템플릿 칸끼리 값이 자리를 바꿔도 잡지 못한다. 템플릿은 숨겨져 있고 서로 같은 구조라 허용했다.

### 표시 규칙의 한계

- 하네스는 실행 전 값을 실행마다 새로 만든 솔트의 지문으로만 다룬다. 실행 후 값의 지문이 **페이지 전체의 실행 전 지문 목록**에 있으면(같은 칸이 아니어도) 실행 전부터 있던 값으로 보고 표시하지 않는다(`census.mjs`의 `preexisting` 판정). 판정자는 이런 칸을 `UNVERIFIABLE`로 두고 분모에서 뺀다.
- 2026-10-22 한국타이어 2단계에서 실행 중 생긴 값 12칸(실행 전에 비어 있고 비활성이던 대학원 칸 6개와 새 행의 칸 6개)이 다른 칸의 실행 전 값과 지문이 같아 가려졌다. 숫자 표기 차이(`3.650`과 `3.65`)도 같은 값으로 보지 않아 ABL생명·GS건설 2단계의 학점 칸이 가려졌다.
- 이 규칙은 값을 덜 보여 주는 쪽으로만 틀리므로 정답 수를 부풀리지 않는다. 2026-10-22 측정의 확인 불가 217칸 중 에이치닷 187칸은 대부분 사람이 지우지 않은 저장 값 때문이고, 위 두 한계가 그중 일부를 더한다.

## 쓰임

- 원복 검증은 이름 대조 뒤 값 풀 대조를 거친 결과(`verified`, `unexpected`, `rekeyed`)로 판단한다.
- 하네스 개선 후보: 실행 전 지문을 같은 칸끼리만 대조하고, 숫자 표기를 정규화한다. 그 전까지 보고서는 확인 불가를 분모 밖에서 따로 적는다.
