# 병합된 작업 브랜치의 워크플로 정리

## 상태
승인됨

## 날짜
2026-10-23

## 관련 Issue
- #330
- #155

## 배경
CF-155는 release → develop 동기화가 끝날 때까지 release를 유지하려고 저장소 자동 삭제를 껐고, 그 결과 모든 작업 브랜치의 원격 정리가 사람 몫이 됐다. 2026-10-23 설정 해제 이후 병합 PR마다 브랜치가 남는다. 안전한 lease 삭제는 release 정리에 이미 구현돼 있다.

## 검토한 대안
- 저장소 자동 삭제를 다시 켠다: 작업 브랜치는 편하지만 CF-155의 동기화 실패가 재발한다.
- PR 담당자가 계속 수동 정리한다: 추가 구현이 없지만 누락이 쌓이고 하네스 정리 스킬이 원격을 다루지 않아 확인 수단이 없다.
- 병합 PR closed 이벤트에서 워크플로가 허용 경로의 head만 lease 삭제한다: release 정리와 같은 안전 조건을 재사용하며, `release/*`·장기 브랜치는 대상에서 제외한다.

## 결정
같은 저장소의 병합 PR 중 `CF-*` → `develop`·`release/*`, `hotfix/CF-*` → `main`, `revert/*` → `main`의 head를 별도 워크플로가 삭제한다. 삭제 직전 원격 SHA를 PR head SHA와 비교해 lease로 삭제하고, 같은 head의 열린 PR이 있거나 조건이 하나라도 어긋나면 삭제하지 않는다. `main`, `develop`, `release/*`는 이 경로에서 삭제하지 않으며 release 정리는 CF-155 결정을 따른다. 저장소 자동 삭제 해제 상태는 유지한다.

## 결과
PR 담당자의 수동 정리가 사라지고 CF-155의 트레이드오프가 해소된다. 병합 없이 닫힌 PR, fork, PR 없는 브랜치는 여전히 사람이 정리한다. `release/*` 삭제를 막는 Ruleset을 추가하려면 두 정리 경로의 삭제 권한을 함께 확인해야 한다.
