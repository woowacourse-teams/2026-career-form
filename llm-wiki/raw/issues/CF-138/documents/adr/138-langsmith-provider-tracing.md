# LangSmith Java SDK를 통한 공급자 독립 호출 추적

## 날짜

- 승인 후 예상 raw 경로: `llm-wiki/raw/issues/CF-138/documents/adr/138-langsmith-provider-tracing.md`

## 배경

Jev는 구조화된 state와 questions를 직접 HTTP로 전달하고 OpenAI는 Spring AI를 사용한다. 두 호출 경로의 요청과 결과를 함께 조회해야 범용 매핑 실패를 조사할 수 있다. 관측 도구 도입이 기존 공급자 호출 계약이나 개인정보 경계를 변경해서는 안 된다.

## 검토한 대안

1. 기존 로그와 메트릭만 사용한다. 의존성은 늘지 않지만 호출별 입력과 결과 비교 및 실행 맥락 연결이 부족하다.
2. LangSmith REST API를 직접 구현한다. 원하는 payload를 보낼 수 있지만 HTTP 인증, 직렬화와 API 계약 유지 코드를 직접 관리해야 한다.
3. 공식 LangSmith Java SDK를 사용한다. 기존 모델 호출 구조를 유지하면서 타입이 있는 API와 비동기 클라이언트를 활용할 수 있다. SDK 버전과 의존성 호환성, 전송 자원 관리는 검증해야 한다.
4. LangChain4j로 호출 구조를 전환한다. 모델 호출 추상화와 리스너를 활용할 수 있지만 현재 목적보다 변경 범위가 커지며 Jev 직접 호출에 자동 적용되지 않는다.

## 결정

공식 LangSmith Java SDK로 두 공급자 호출을 명시적으로 추적한다. Jev 직접 HTTP와 OpenAI Spring AI 구조는 유지한다. 추적은 기본 비활성화하고 설정된 환경에서만 사용한다.

전송 데이터는 허용된 비식별 구조, 지시문, 선택 기준, 구조화 결과와 실행 메타데이터로 한정한다. 실제 지원 정보, 계정·세션 정보와 시크릿은 보내지 않는다. 공급자의 원본 판단과 앱에서 적용한 최종 판단을 구분한다.

비동기 추적 실패는 모델의 성공·실패 계약에 전파하지 않는다. 기존 모델 제한 시간, 응답 변환과 안전 중단 동작을 보존한다. 전송 자원은 제한하고 종료 시 무기한 기다리지 않는다.

LangSmith 프로젝트 생성, 접근 권한과 보존 기간 설정, 자격증명 주입은 사람이 담당한다. 보존 기간은 본 계약에서 임의의 값으로 확정하지 않으며 실제 데이터 전송 전에 사람이 테스트 프로젝트 설정을 확인한다.

## 결과

두 공급자의 입력과 결과를 공통 대시보드에서 비교할 수 있다. Spring AI와 Jev의 호출 코드는 관측 도구 때문에 다른 프레임워크로 전환하지 않는다. SDK 의존성과 비식별화 검증, 전송 실패 격리 및 자원 종료 검증이 추가된다. 후속 정확도 Issue는 이 추적 근거를 사용할 수 있지만 추적 자체가 매핑 정확도 개선을 보장하지는 않는다.
