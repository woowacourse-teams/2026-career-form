# CF-507 승인 후보 스냅샷

> Issue: [CF-507](https://github.com/woowacourse-teams/2026-career-form/issues/507)
> Collected: 2026-11-21
> Approval-Digest: 8aa4dba680ca8eee10d8d1b02bb1a96d9ad145d47518e7c537cc680232879294

worktree 체크포인트에 기록한 후보 세 개의 원문이다. 사람이 2026-11-19 "llm wiki 앞으로 잘 동작하는지 확인하고, 사람 승인 안받아도 되니 너가 알아서 기입해"라고 말해 에이전트가 자동 승인했다.

1. 에이치닷 v1 1단계 현주소 기입(#507): 본문 3칸(우편번호, 주소, 상세주소)은 잠겨 있고 사이트 자체 검색 창(제목 주소입력, iframe 없음)으로만 채워진다. 프로필 기본주소로 한 번 검색하고, 도로명이 정확히 일치하는 결과가 한 줄일 때만 고른 뒤 상세주소를 넣고 창의 확인을 누른다. 일치가 없거나 여럿이면 취소로 닫고 확인 필요로 남긴다. 결과 줄에는 우편번호가 없고, 결과 목록을 감싼 스크롤 상자는 항상 그려지지 않으므로 결과 줄은 도로명 라벨이 있는 목록 줄로 찾는다. 칸 이름은 hplace.v1.postalCode, hplace.v1.addressLine1, hplace.v1.addressLine2이고 잠긴 칸이지만 창을 거쳐 쓰는 대상이라 보이는 후보로 수집한다.
2. 에이치닷 v1 현주소 행의 확정 뒤 모양과 비교 기준(#507): 창의 확인 뒤 사이트가 현주소 행을 다시 그린다. 우편번호와 주소 칸은 읽기 전용(잠김 아님), 상세주소 칸은 편집 가능이 된다. 주소 칸에는 도로명 뒤에 괄호 부분(법정동, 또는 법정동과 건물명)이 붙는다. 그래서 행 검증은 빈 모양(세 칸 잠김)과 확정 모양을 모두 인정하고, 재확인과 기존값 비교는 끝의 괄호 부분 하나를 뗀 도로명으로 한다. 우편번호와 상세주소는 정확히 일치해야 한다. 같은 주소가 이미 있으면 창을 열지 않고 유지로, 다른 도로명이면 충돌로 보고한다.
3. 에이치닷 v1 사진 등록 창(#507): 공용 첨부 기능이 사진 파일을 넣으면 v1 화면이 제목 사진 등록 창을 띄운다. 창은 바로 뜨지만 자르기 그림과 자르기 영역은 조금 뒤에 준비되고, 그 전에 저장을 누르면 창만 닫히고 사진은 남지 않는다. 준비된 뒤 저장을 누르면 사이트가 사진 파일을 서버로 올리고(지원서 임시저장은 아니다) 사진 카드의 파일 칸이 사진으로 바뀐다. 확장은 그림 준비를 기다려 저장을 한 번 누르고, 파일 칸이 사라졌는지로 성공을 확인한다. 공용 첨부 구역에는 사이트 지식 없는 선택적 후속 단계만 두고 v1 동작은 어댑터 쪽에 둔다. 저장을 확장이 누르는 것은 2026-11-21 사용자 결정이다.
