# Issue 단위 불변 raw와 주제 단위 Wiki 읽기 모델

## 상태

수락됨

## 날짜

2026-08-22

## 관련 Issue

- #41

## 배경

분산된 문서를 한 경로에 복사하는 것만으로는 결정 변화와 작업 단위 근거를 함께 보존하기 어렵다. raw를 바로 수정하면 과거 판단을 잃고, 작업 중 모든 대화를 즉시 수집하면 확정되지 않은 내용과 개인정보가 섞일 수 있다. context 축약과 세션 재개에도 결정 후보가 남아야 한다.

## 검토한 대안

- 가변 정본 문서와 Git 이력만 사용: 현재 문서는 읽기 쉽지만 일반 질의마다 Git 이력을 다시 조사해야 한다.
- 주제별 raw 저장: 같은 주제의 버전 탐색은 쉽지만 하나의 Issue가 여러 주제를 바꿀 때 작업 근거가 분산된다.
- Issue별 raw와 주제별 Wiki 분리: 확정 작업을 한 묶음으로 보존하면서 읽기 모델에서 여러 Issue의 같은 주제를 연결할 수 있다.

## 결정

신규 raw는 `llm-wiki/raw/issues/CF-<번호>/`에 Issue 단위로 추가하고 `develop` 병합 뒤에는 수정하지 않는다. 주제별 Wiki는 raw의 명시적 대체 관계를 따라 현재 상태와 이력을 제공하며 충돌 시 `Disputed`로 표시한다.

작업 중 계획과 결정 후보는 worktree 체크포인트에 임시 저장하고 raw 작성 직전에 후보 전체를 한 번에 사람에게 확인받는다. 모든 Issue는 `Recorded` 또는 `No reusable knowledge`를 확정해야 Draft PR을 만들 수 있다. 기존 raw의 경로와 내용, 개인정보와 대화 수집 금지 원칙은 유지한다.

## 결과

작업 단위 추적과 주제 단위 질의를 함께 제공하고 context 축약 뒤에도 후보를 복구할 수 있다. 대신 모든 Issue에 지식 판정 단계가 추가되고 raw와 Wiki의 관계, 승인 digest와 불변성을 하네스가 검증한다.
