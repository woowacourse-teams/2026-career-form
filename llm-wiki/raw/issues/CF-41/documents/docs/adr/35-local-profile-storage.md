# 버전이 있는 프로필 로컬 저장 계약

## 상태

승인됨

## 날짜

2026-08-19

## 관련 Issue

- #35

## 배경

팝업, 프로필 관리 탭과 사이드 패널이 핵심 10개 범주의 같은 데이터를 사용해야 한다. 저장 계약 없이 화면별 폼 상태를 직접 저장하면 두 레이아웃과 후속 자동 기입이 서로 다른 데이터 구조에 결합된다. 프로필에는 민감정보가 포함될 수 있으므로 외부 전송 없이 Chrome 확장 프로그램 전용 로컬 저장소만 사용해야 한다.

## 검토한 대안

1. 화면별 key와 폼 상태를 그대로 저장한다. 초기 구현은 빠르지만 화면 변경마다 저장 형식과 소비자를 함께 수정해야 한다.
2. 버전이 있는 프로필 envelope와 UI 독립 저장소 adapter를 둔다. 초기 계약과 경계 코드가 필요하지만 모든 화면이 같은 구조를 사용하고 후속 변경을 감지할 수 있다.
3. 모든 값을 범주·필드 ID·값의 범용 목록으로 저장한다. 필드 추가는 쉽지만 단일·반복 범주의 구조와 타입을 잃고 자동 기입 소비자가 매번 재구성해야 한다.

## 결정

`chrome.storage.local`의 `careerForm.profile` key에 `schemaVersion: 1`을 가진 단일 프로필 envelope를 저장한다. 단일 범주는 객체, 여러 건을 허용하는 범주는 안정적인 식별자를 가진 배열로 표현하며 필드 ID는 `PROFILE_FIELDS.md`를 따른다. 학력과 어학처럼 한 범주에 하위 유형이 있는 반복 항목은 `sectionId`로 유형을 명시한다.

값은 사용자가 입력한 문자열의 의미를 변환하지 않는다. 저장 경계에서 앞뒤 공백을 제거하고 빈 값과 모든 값이 빈 반복 항목만 제외한다. Chrome 저장 API는 adapter 뒤에 두고 React 화면은 저장 API를 직접 호출하지 않는다. 레이아웃 선택은 `careerForm.layout` key로 프로필 envelope와 분리한다.

지원하는 `schemaVersion`이 아니거나 저장에 실패하면 기존 저장값을 덮어쓰지 않고 사용자에게 오류를 표시한다. 저장 데이터는 외부로 전송하거나 로그에 기록하지 않으며 MVP에서 별도 암호화와 잠금을 추가하지 않는다.

## 결과

팝업, 두 프로필 레이아웃과 사이드 패널이 같은 데이터를 공유하고 한 레이아웃을 제거해도 저장 데이터가 유지된다. 후속 자동 기입은 화면 상태가 아닌 명시된 프로필 계약을 소비할 수 있다. `schemaVersion` 변경 시 별도의 마이그레이션 결정과 테스트가 필요하다. 로컬 저장은 외부 서버 전송을 막지만 같은 브라우저 프로필이나 기기에 접근할 수 있는 사람으로부터 값을 보호하지 않으므로 화면에서 이 한계를 안내한다.
