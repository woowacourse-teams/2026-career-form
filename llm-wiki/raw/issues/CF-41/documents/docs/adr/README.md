# Architecture Decision Records

ADR은 여러 대안을 검토한 결정 중 후속 작업, 제품 정책, 아키텍처, 보안, 데이터
또는 공용 워크플로우에 지속적으로 영향을 주는 결정을 기록한다. 일반 작업 순서,
일시적인 조사 메모와 파일 배치는 ADR로 만들지 않는다.

## 작성 시점

1. `status:planning`에서 ADR 필요 여부를 판단한다.
2. ADR이 필요하면 전문과 파일 경로를 Issue 계약과 함께 제안한다.
3. 사람이 Issue 계약과 ADR 전문을 승인하기 전에는 저장소 파일을 만들지 않는다.
4. 승인 후 `CF-<Issue 번호>` 브랜치에서 ADR을 작성해 같은 PR에 포함한다.

`[Plan]`은 조사, 요구사항 정리와 문서 기획 같은 구현 전 작업에 사용한다. 기본
산출물은 조사 결과, 요구사항, 기획 문서와 ADR이다. 처음 승인된 Issue 계약에 구현이
포함돼 있으면 같은 Issue와 PR에서 구현까지 진행할 수 있다. 기획 중 새로 발견된 구현
범위는 현재 Issue에 추가하지 않고 별도 Project draft 후보로 제안한다.

## 파일명

```text
docs/adr/<Issue 번호>-<영문 slug>.md
```

하나의 Issue에 서로 독립적인 장기 결정이 있으면 ADR 파일을 나눈다.

## 필수 항목

```markdown
# 결정 제목

## 상태

제안됨 또는 승인됨

## 날짜

YYYY-MM-DD

## 관련 Issue

- #123

## 배경

결정이 필요한 이유와 제약을 적는다.

## 검토한 대안

검토한 선택지와 장단점을 적는다.

## 결정

선택한 방향과 적용 경계를 적는다.

## 결과

얻는 효과, 비용과 후속 작업에 미치는 영향을 적는다.
```

대화 전문, 실제 지원 정보, 계정 정보와 브라우저 세션 상태는 기록하지 않는다.
