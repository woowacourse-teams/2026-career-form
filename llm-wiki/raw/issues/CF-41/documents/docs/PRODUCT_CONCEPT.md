# 채용 지원 정보 자동 입력 도구

> 흩어진 취업 정보를 브라우저에 한 번 정리하고, 채용 지원서에서 사용자가 확인한 항목만 자동으로 입력하는 Chrome 확장 프로그램

## 기획 요약

채용 지원서를 작성할 때마다 이름과 연락처뿐 아니라 주소, 학력, 어학, 프로젝트, 자격증, 병역, 보훈, 장애, 건강 관련 정보를 반복해서 입력해야 한다. 특히 자격증 번호나 취득일처럼 기억하기 어려운 정보는 발급 기관 사이트나 별도 문서를 다시 찾아야 한다.

이 서비스는 반복해서 사용하는 지원 정보를 브라우저에 한 번 정리해 두고, 채용 지원서에서 입력 가능한 항목과 입력 예정 값을 보여준 뒤 사용자의 확인을 거쳐 자동으로 기입한다.

이 서비스는 사용자의 정보를 대신 수집하는 서비스가 아니다. 사용자가 직접 등록하고 관리한 정보를 필요한 시점에 안전하게 다시 사용할 수 있도록 돕는 도구다.

## 해결하려는 핵심 문제

문제는 사용자가 자신의 정보를 전혀 저장하지 않았다는 것이 아니다. 필요한 정보가 기관 사이트, 이력서 파일, 메모 등에 흩어져 있어 실제 지원 시점에 즉시 꺼내 쓰기 어렵다는 것이다.

- 지원할 때마다 같은 정보를 반복해서 입력해야 한다.
- 자격증 번호, 취득일, 어학 성적 정보 등을 다시 찾아야 한다.
- 사이트마다 항목의 이름과 입력 형식이 달라 그대로 복사하기 어렵다.
- 자동 입력 도구가 어떤 값을 변경하는지 알 수 없으면 신뢰하기 어렵다.

## 대상 사용자

- 여러 기업의 채용 공고에 반복적으로 지원하는 취업 준비생
- 주소, 학력, 어학, 자격증, 프로젝트, 병역, 보훈, 장애, 건강 관련 정보를 여러 지원서에 다시 입력하는 사용자
- 자신의 지원 정보를 한곳에서 관리하고 필요할 때 빠르게 재사용하고 싶은 사용자

대표적인 사용 시점은 사용자가 채용 지원서를 작성하기 직전 또는 작성하는 도중이다.

## 핵심 가치

- **반복 입력 감소:** 자주 사용하는 지원 정보를 매번 다시 입력하는 시간을 줄인다.
- **정보 탐색 감소:** 자격증 번호와 취득일 등을 찾기 위한 외부 사이트 재접속을 줄인다.
- **적용 전 확인:** 입력할 값과 입력하지 못하는 항목을 적용 전에 보여준다.
- **사용자 통제:** 사용자가 확인하고 선택한 경우에만 값을 입력한다.
- **제출 분리:** 지원서 작성은 돕지만 저장, 다음 단계 이동, 최종 제출은 자동화하지 않는다.
- **로컬 우선:** 공통 정보는 외부 서버가 아닌 브라우저 로컬 저장소에 저장한다.

## 핵심 사용자 흐름

1. 사용자가 Chrome 확장 프로그램에서 자신의 지원 정보를 직접 등록하고 관리한다.
2. 사용자가 채용 지원서 페이지에서 확장 프로그램을 실행한다.
3. 확장 프로그램이 페이지의 입력 항목을 분석하고 저장된 정보와 연결한다.
4. 확장 프로그램이 분석 결과를 다음 상태로 구분해 보여준다.
   - `입력 가능`: 저장된 정보와 지원서 항목의 연결이 명확한 상태
   - `확인 필요`: 연결 후보가 있지만 사용자의 판단이 필요한 상태
   - `입력 불가`: 대응하는 정보가 없거나 안전하게 입력할 수 없는 상태
5. 사용자가 입력 예정 값과 기존 입력값의 충돌 여부를 확인한다.
6. 사용자가 입력할 항목을 선택하고 적용을 승인한다.
7. 확장 프로그램이 승인된 항목만 지원서에 입력한다.

확장 프로그램은 이 과정에서 지원서의 저장 버튼, 다음 단계 버튼, 최종 제출 버튼을 조작하지 않는다.

## MVP 범위

### 저장하고 자동 입력할 정보

MVP에서는 다음 열 종류의 정보만 구조적으로 관리한다. 주소는 연락처 범주에서 관리한다.

1. 기본 인적사항
2. 연락처
3. 학력
4. 어학
5. 자격증
6. 프로젝트
7. 병역
8. 보훈
9. 장애
10. 건강

각 정보에 포함될 세부 필드와 데이터 구조는 후속 설계에서 결정한다.

### 제공 기능

- 지원 정보 직접 등록, 조회, 수정
- 현재 지원서 페이지의 입력 필드 분석
- 저장된 정보와 지원서 항목의 매핑
- 국문·한자·영문 성과 이름을 분리해 저장하고 분리형 지원서에 직접 매핑
- 입력 가능 여부와 입력 예정 값 미리보기
- 사용자가 선택한 항목의 자동 입력
- 기존 입력값과의 충돌 표시
- 병역, 보훈, 장애, 건강 정보의 개별 확인 입력
- 주요 기업용 전용 어댑터와 일반 사이트용 범용 탐지

## 사이트 지원 전략

채용 사이트마다 화면 구조와 입력 방식이 다르므로 전용 어댑터와 범용 탐지를 함께 사용한다.

1. 삼성, SK, 현대, CJ 등 우선 지원 기업의 채용 페이지에서는 해당 사이트에 맞춘 **전용 어댑터**를 우선 사용한다.
2. 전용 어댑터가 없는 채용 페이지에서는 HTML 구조, 필드 이름, 레이블 등의 정보를 활용하는 **범용 탐지**를 사용한다.
3. 전용 어댑터를 적용할 수 없거나 지원 범위를 벗어난 경우 범용 탐지를 폴백으로 사용한다.
4. 안전하게 판단할 수 없는 항목은 추측해서 입력하지 않고 `확인 필요` 또는 `입력 불가`로 표시한다.

이 서비스는 모든 채용 사이트에서 모든 항목을 완벽하게 입력하는 것을 보장하지 않는다. 지원하지 못하는 항목을 숨기지 않고 사용자에게 알려주는 것을 정확한 자동 입력만큼 중요하게 다룬다.

## 자동 입력 원칙

### 적용 전 확인

- 자동 입력 전에 대상 항목과 입력 예정 값을 사용자에게 보여준다.
- 사용자가 명시적으로 선택하고 승인한 항목만 변경한다.
- 판단이 불확실한 필드는 자동 적용 대상으로 미리 선택하지 않는다.
- 전체 이름만 있는 값을 성과 이름으로 추측해 분리하지 않는다.
- 국문·한자 전체 이름은 저장된 성과 이름을 순서대로 붙여 조합한다.
- 영문 전체 이름은 대상 사이트가 요구하는 순서와 구분자를 확인할 수 있을 때만 조합하고, 불명확하면 `확인 필요`로 표시한다.
- 사용자가 저장한 영문 대소문자와 한자 표기를 임의로 변환하지 않는다.

### 기존 입력값 보호

- 이미 값이 있는 필드는 기본적으로 덮어쓰지 않는다.
- 저장된 값과 기존 값이 다르면 충돌 상태로 표시한다.
- 사용자가 해당 항목의 덮어쓰기를 개별적으로 승인한 경우에만 기존 값을 교체한다.

### 제출 금지

- 지원서 저장을 자동으로 실행하지 않는다.
- 다단계 지원서의 다음 단계 이동을 자동으로 실행하지 않는다.
- 지원서를 자동으로 제출하지 않는다.

## 개인정보와 저장 원칙

- 사용자가 등록한 지원 정보는 Chrome 확장 프로그램 전용 로컬 저장소에 보관한다.
- MVP에서는 사용자 정보를 외부 서버로 전송하거나 서버에 동기화하지 않는다.
- 정보의 등록과 수정은 사용자가 직접 수행한다.
- 병역, 보훈, 장애, 건강 정보는 민감정보임을 표시하고 사용자가 원하는 항목만 선택적으로 저장한다.
- 민감정보는 자동 입력 일괄 적용 대상으로 기본 선택하지 않으며, 지원 건마다 사용자가 항목과 값을 개별 확인한 경우에만 입력한다.
- 프로필 값은 오류 보고, 분석 로그, 원격 측정 데이터에 포함하지 않는다.
- 로컬 저장은 외부 서버 전송을 막지만, 같은 브라우저 프로필이나 기기에 접근할 수 있는 사람으로부터 정보를 완전히 보호하는 것은 아니다. 이 한계를 사용자에게 안내한다.
- 별도 비밀번호를 이용한 잠금과 암호화는 MVP 범위에 포함하지 않는다.

## MVP에서 하지 않는 것

다음 기능은 MVP 범위에 포함하지 않는다.

- 이력서, 증명서, 기타 문서에서 정보 자동 추출
- 자격증 또는 어학 시험 기관과의 연동
- 계정 시스템과 외부 서버 동기화
- 자기소개서 작성 또는 생성
- 지원서 저장, 다음 단계 이동, 최종 제출 자동화
- 경력, 수상, 교육 등 핵심 열 종류 이외의 정보 관리
- 모든 채용 사이트와 입력 항목에 대한 완전한 호환성 보장

비범위 기능은 후속 검토 대상일 수 있지만, 별도의 결정 없이 MVP 기능으로 간주하지 않는다.

## MVP 성공 기준

MVP는 지원 사이트의 수보다 안전하고 통제 가능한 자동 입력을 우선한다. 다음 조건을 만족하면 핵심 목표를 달성한 것으로 본다.

- 사용자가 핵심 열 종류의 정보를 필요한 만큼 선택해 등록하고 반복해서 사용할 수 있다.
- 자동 입력 전에 대상 항목과 값을 확인할 수 있다.
- 사용자가 승인하지 않은 항목은 변경되지 않는다.
- 기존 입력값과의 충돌을 식별하고 기본적으로 기존 값을 보존한다.
- 지원하지 못하거나 확신할 수 없는 항목을 사용자에게 알린다.
- 확장 프로그램이 지원서를 저장하거나 제출하지 않는다.
- 등록된 지원 정보가 외부 서버로 전송되지 않는다.

## 용어 정의

- **지원 정보:** 채용 지원서에서 반복적으로 사용하는 사용자의 인적사항, 연락처와 주소, 학력, 어학, 자격증, 프로젝트, 병역, 보훈, 장애, 건강 정보
- **민감정보:** 프로필 정보 중 병역 면제 사유, 보훈, 장애, 건강처럼 노출되었을 때 사용자의 권리와 사생활에 큰 영향을 줄 수 있는 정보
- **프로필:** 확장 프로그램의 로컬 저장소에 보관된 사용자의 지원 정보 모음
- **필드 탐지:** 현재 웹 페이지에서 지원서 입력 항목과 그 의미를 찾는 과정
- **매핑:** 탐지한 지원서 항목을 프로필의 정보와 연결하는 과정
- **입력 예정 값:** 사용자 승인 후 지원서 필드에 들어갈 값
- **전용 어댑터:** 특정 기업 또는 채용 사이트의 구조와 입력 규칙에 맞춘 처리 방식
- **범용 탐지:** 특정 사이트에 종속되지 않고 페이지의 일반적인 구조와 레이블을 분석하는 처리 방식

## AI와 후속 작업자를 위한 해석 기준

- 이 프로젝트는 취업 정보를 대신 수집하는 서비스가 아니라 사용자가 직접 등록한 정보의 재사용 도구다.
- 편의성과 입력 속도보다 사용자의 확인, 통제, 기존 데이터 보호를 우선한다.
- 자동 입력과 자동 제출은 서로 다른 기능이며, 이 프로젝트는 자동 제출을 지원하지 않는다.
- 새로운 기능을 설계할 때도 로컬 저장, 적용 전 확인, 선택적 입력, 제출 금지 원칙을 유지한다.
- 민감정보는 저장 가능하다는 이유만으로 일반 정보와 동일하게 취급하지 않으며, 일괄 자동 입력보다 항목별 명시적 확인을 우선한다.
- 전용 어댑터와 범용 탐지는 서로 대체하는 선택지가 아니다. 전용 어댑터를 우선하고 범용 탐지를 폴백으로 사용하는 계층적 전략이다.
- 이 문서에 명시되지 않은 기능을 MVP에 포함된 것으로 추론하지 않는다.
- 확정되지 않은 기술, 세부 필드, 사이트 우선순위를 임의로 확정하지 않는다.

## 향후 결정 사항

다음 내용은 프로젝트 방향이 아니라 후속 제품·기술 설계에서 결정할 사항이다.

- 핵심 열 종류 정보의 세부 필드와 검증 규칙
- 전용 어댑터를 우선 개발할 기업과 순서
- 범용 필드 탐지와 매핑의 구체적인 판단 방식
- 입력 미리보기 화면과 프로필 관리 화면의 UI
- 로컬 데이터의 내보내기, 가져오기, 백업 지원 여부
- MVP 이후 추가할 정보 종류와 사이트 지원 범위
