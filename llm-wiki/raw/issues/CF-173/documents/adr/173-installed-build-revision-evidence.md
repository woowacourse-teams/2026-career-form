# 설치본 내장 revision 메타데이터와 평가 근거

## 상태
승인됨

## 날짜
2026-10-09

## 관련 Issue
#173. 승인 후 예상 경로: llm-wiki/raw/issues/CF-173/documents/adr/173-installed-build-revision-evidence.md.

## 배경
작업 디렉터리 HEAD와 확장 프로그램 version은 현재 실행 중인 설치본의 소스 revision을 증명하지 못한다. 빌드와 평가 사이에 재사용 가능한 식별 계약이 필요하다.

## 검토한 대안
1. 평가자가 HEAD나 설치 경로를 기록한다. 구현 비용은 낮지만 구버전 설치와 dirty 빌드를 구분하지 못하므로 채택하지 않는다.
2. 빌드 시 메타데이터를 포함하고 설치본 내부에서 읽는다. 별도 권한과 서버 없이 현재 설치본과 연결할 수 있지만 dirty 상태와 메타데이터 부재를 명시해야 한다. 이를 채택한다.
3. 원격 빌드 등록소 및 서명 검증을 도입한다. 공급망 무결성까지 다룰 수 있으나 이번 평가 재현성 범위를 넘으므로 제외한다.

## 결정
build-info.json에 버전 있는 스키마, 전체 commit SHA 또는 null, CLEAN/DIRTY/UNKNOWN을 빌드 시 생성하고 build/ZIP에 포함한다. 설치본 내부 조회 결과를 평가 근거로 사용한다. CLEAN이며 SHA와 설치본 조회가 유효할 때만 VERIFIED로 기록하고 나머지는 UNVERIFIED와 사유를 남긴다. 메타데이터 digest는 식별용이지 서명이 아니다. 환경변수, 사용자 경로 및 개인정보는 기록하지 않으며 웹 페이지에 공개하지 않는다.

## 결과
설치된 구버전과 최신 작업 디렉터리를 혼동하지 않고 평가를 재현할 수 있다. 빌드 생성·ZIP 검사·설치본 조회·평가 parser가 같은 스키마를 유지해야 한다. dirty 실행의 지표는 남길 수 있지만 commit 기반 개선·회귀 근거로는 사용하지 않는다. 백엔드 버전과 악의적 artifact 변조의 증명은 제공하지 않는다.
