# CF-368 approved candidates (2026-10-29, [FE] 1.4.0 QA의 Greeting 학교명 미확정과 사이드 패널 표시 문제 수정 및 프로필 입력 보강)

1. Greeting 고교 학교명 동명 후보(CF-368 A): 정책 버전을 올리지 않고 FE에서 처리한다. 고교 검색 칸에서 같은 이름 정식 후보가 2개 이상일 때만, 기준 지역(카탈로그 selected면 카탈로그 detail 첫 조각의 시도, 아니면 같은 항목 schoolRegion의 표준 라벨)과 선택지 item-description이 정확히 같은 후보가 하나이고 모든 후보 설명이 보일 때 그 후보를 고른다. selected 신원과 프로필 지역이 어긋나면 좁히지 않는다. 그 밖에는 SEARCH_AMBIGUOUS로 남는다. 후보 1개 동작은 바꾸지 않았다(다른 시도 단일 후보 선택은 후속 후보).
2. Greeting 고교 재실행(CF-368 A): 다시 연 목록에 같은 이름 정식 항목이 여럿이면 체크된 항목이 같은 동점 해소 결과와 같아야 성공이다. 지역 근거가 없거나 어긋나면 SEARCH_AMBIGUOUS를 보고하고 기존 값은 덮어쓰지 않는다. 동점 해소로 고른 영수증은 detail=카탈로그 detail, description=지역을 남긴다. ReviewPlanItem.searchRegion은 API로 보내지 않는 로컬 전용 필드다.
3. Greeting 한국폴리텍 대학 번호 표기(CF-368 B): KESS 카탈로그 이름에는 캠퍼스군 번호가 없고(한국폴리텍대학 서울정수캠퍼스) 사이트 목록에는 있다(한국폴리텍 I 대학 서울정수캠퍼스). matchesCatalogNumberedCollege는 university·graduateSchool에서 번호가 한쪽에만 있고 번호를 뺀 키가 카탈로그 항목 하나만 가리킬 때만 같은 학교로 본다(2026-10-07 카탈로그 기준 충돌 0). normalizedCatalogLabel은 바꾸지 않았다. 이렇게 고른 사이트 라벨은 재실행 검토에서 프로필 값과 달라 기존 값 충돌로 표시되고 덮어쓰지 않는다.
4. 카카오게임즈 Greeting 실측(2026-10-29, 테스트 계정·합성 프로필): 운영 1.4.0과 develop dcee68dd에서 동명 고교(대진고 3곳)는 학교명이 비고, develop은 SEARCH_AMBIGUOUS로 보고했다. CF-368 빌드(develop 로컬 서버, Greeting 정책 v19)에서는 기본·카탈로그 선택·직접 입력 프로필 모두 고교가 확정됐다. 이는 고교 선택지에 시도 설명이 있다는 간접 근거다. 카탈로그 선택 폴리텍 대학은 정식 항목 '한국폴리텍 I 대학 서울정수캠퍼스'로 확정됐다. 즉 프로필 이름 검색 결과에 정식 항목이 나온다. 직접 입력 프로필은 #347 동작대로 직접 입력 값이 들어갔다.
5. 사이드 패널 값 표시(CF-368 C): 페이지 안 패널, Chrome side panel, 랜딩 미리보기가 같은 App을 쓴다. 필드 정의 선택지(optionsFor 우선)로 코드형 저장값(region:seoul 등)을 라벨로 보여 주고 라벨을 복사한다. 저장값은 코드 그대로이고 선택지에 없는 값은 그대로 보인다. 값 검색 금지 계약은 유지한다. 공통 함수는 frontend/src/profile/field-display.ts의 optionLabel/fieldDisplayValue이고 가져오기 검토 화면도 이를 쓴다.
6. 사이드 패널 반복 항목(CF-368 D): 반복 항목은 프로필 관리 카드와 같은 '섹션 라벨 + 범주 안 순번'(고등학교 1, 대학교 2) 소제목과 role=group으로 묶고, 옆에 학교명·시험명·자격증명 같은 식별 값을 보여 준다. 반복 항목 복사 버튼 이름은 '<소제목> <필드> 복사'다. 소제목은 검색 대상이 아니다. 긴 기관명은 줄바꿈한다.
7. 패널 열기 단축키(CF-368 E): manifest commands._execute_action(제안 키 Alt+Shift+C)이다. 팝업이 없어 툴바 클릭과 같은 action.onClicked → 페이지 안 패널 경로를 탄다. 페이지 안 패널은 background에 메시지로 commands.getAll()을 요청하고 background는 sender.id를 확인한다. 할당 키가 있으면 키를, 없으면 chrome://extensions/shortcuts 안내를 헤더에 보인다. 읽기 실패 시 안내를 숨긴다. assert-build와 assert-zip이 commands를 검사한다.
8. 자격증 발급기관 자동 채움(CF-368 F, CF-162 결정 일부 변경): 자격증명을 카탈로그에서 고르면 발급기관이 비었거나 공백일 때만 카탈로그 detail 첫 ' · ' 조각(HRDK 613건 한국산업인력공단, KDATA 7건 한국데이터산업진흥원)으로 채운다. 입력된 발급기관은 바꾸지 않고, 자동 채움 여부를 저장하지 않아 이름을 고쳐 연결이 풀려도 남는다. 학교·어학 선택, 직접 입력, 가져오기는 관련 필드를 추론하지 않는다. 국가전문자격 일부는 첫 조각이 시행기관이라 실제 발급 주체와 다를 수 있다.
9. 자격증 등록번호 라벨(CF-368 G): 자격증 registrationNo 표시 라벨은 '등록번호 및 자격번호'이고 필드 키는 그대로다. 어학 registrationNo 라벨은 '등록번호'로 남아 FE 의미 어휘에서 '등록번호'가 빠지지 않는다.
10. 어학 시험 목록(CF-368 H): 저장소 상수 8종으로 TOEIC Speaking(value toeic-speaking, 별칭 토익스피킹)을 추가했다. 항목 추가는 새 ID만 만들므로 CATALOG_VERSION은 올리지 않는다(올리면 저장된 selected 신원이 모두 무효). 라벨 'TOEIC Speaking'은 현대자동차 optionMap 키와 같아야 코드 15로 연결된다. TOEIC 선택이 TOEIC Speaking 칸을 채우지 않는 회귀는 유지한다.
11. 프론트 도구 관찰(2026-10-29): frontend eslint.config.js가 **/*.{ts,tsx}를 ignores에 두어 npm run lint가 TS 소스를 검사하지 않는다. develop dcee68dd에서 npm run typecheck가 native-executor.static-gate.test.ts TS2322로 이미 실패하며, frontend CI와 verify.py는 typecheck를 실행하지 않는다.
