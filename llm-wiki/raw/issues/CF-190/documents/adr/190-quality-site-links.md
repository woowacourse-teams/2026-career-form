# 품질 확인 후보의 사이트 표시와 공개 지원서 링크

> Issue: [CF-190](https://github.com/woowacourse-teams/2026-career-form/issues/190)
> Decision-Date: 2026-10-12
> Status: Accepted

같은 사이트가 여러 요청 후보로 표시되고 회사 홈만 안내되어 확인할 공고를 구분하기 어려웠다. 사이트 표시를 묶고 공개 지원서 링크를 관측하되 후보 이력과 사람이 확인한 분모의 적용 범위를 보존한다.

## 공개 지원서 링크의 전달 경계

공개 링크는 sender와 분석 host가 일치하는 HTTPS Greeting의 /ko/o/<번호>/apply 또는 /en/o/<번호>/apply만 허용한다. 번호는 1~12자리 양의 정수, 주소는 512자 이하이며 query, fragment, 계정, port, 인코딩과 다른 경로는 거부한다. 품질 전용 헤더로 양쪽에서 검증하며 분석 body, AI와 일반 로그에는 넣지 않는다.

## 링크 보관과 구형 문서

후보와 사이트 카드에는 동일 URL을 중복 없이 최근 20개까지 보관하고 최근 관측 시점을 갱신한다. 초과하면 오래된 링크를 제외하고 한도 초과를 표시한다. 구형 문서는 빈 링크 목록으로 읽어 마이그레이션 없이 보완하며 만료 링크는 LINK_UNAVAILABLE로 보류한다.

## 사이트 목록과 후보 이력

관리 목록은 환경과 사이트별로 묶은 뒤 페이지를 나눈다. 정책 company 경계를 유지하고 미확인 공유 호스트는 기업 소속 미확인으로 표시한다. 후보 ID, 구조, 담당, 보류, 완료 이력과 집계는 합치지 않는다. 모두 완료한 사이트만 완료 목록에 둔다.

## 사람 확인 분모와 요청 여력

여러 공고나 기존 확인과 다른 링크에는 사람 분모를 자동 재사용하지 않는다. 명시적으로 확인한 전용 호스트와 구조의 승인 범위는 유지한다. Discord는 사이트를 한 번만 안내하되 기존 담당 화면 수를 그대로 차감해 하루 여력 5개를 보존한다.
