# 범용 지원서의 구조 행동 자동 실행과 값 쓰기 승인 유지

## 상태

제안됨 (CF-222 초안. 구현 결과를 반영한 확정은 계획 Task17에서 한다)

## 날짜

2026-10-16

## 관련 Issue

- #222
- #198
- #218

## 배경

범용 지원서(정적 정책이 없는 사이트)에서 행 추가나 섹션 펼치기 같은 준비 작업은 지금 범용 preparation이 담당한다. 이 경로는 사람이 승인한 계획을 한 번 실행하는 방식이라 행을 추가한 뒤 새로 드러난 칸을 다시 감지하지 못한다. 클릭 후보 필터도 버튼 문구 검사뿐이다. form 안에서 type을 지정하지 않아 기본 submit으로 동작하는 button, 다른 페이지로 이동하는 링크, 새 창을 여는 요소는 코드로 걸러지지 않는다(계획 GAP-6).

제품 기준은 사용자 확인과 통제, 기존 값 보호, 제출 금지를 요구한다. 오입력은 빈칸보다 비용이 크다. 반면 현재 확신도 처리는 서버의 0.8 이진 컷뿐이다. 그래서 1순위 후보는 맞지만 확신도가 낮은 칸(실험에서 학력 칸 0.4~0.7)이 모두 버려진다(GAP-4).

2026-10-15 계획 인터뷰에서 사용자는 범용 경로의 행 추가까지 승인 없이 자동으로 수행하기로 결정했다. 이 결정은 제품 기준의 "사용자 확인과 통제"와 충돌할 수 있으므로 자동 범위와 금지선을 기록해야 한다.

## 검토한 대안

1. 현행 유지(구조 행동마다 사람이 승인하고 계획은 한 번만 실행): 제품 기준과 충돌하지 않는다. 하지만 승인 단계가 하나 더 늘고, 한 번 세운 계획만 실행하므로 행 추가 뒤 드러난 칸을 처리하지 못한다.
2. 구조 행동과 값 쓰기를 모두 자동 실행: 사용자 조작이 가장 적다. 하지만 값 쓰기 승인과 민감 항목 개별 승인을 없애 제품 기준을 위반하고 오입력 위험이 크다. 폐기한다.
3. 구조 행동만 자동, 값 쓰기는 승인 유지(계획 기획 평가 E4, 조건부 유지): 승인 단계가 줄고 행 추가와 재감지를 반복할 수 있다. 대신 승인 모델이 바뀌므로 적용 범위를 명시하고 결과 화면에 기록을 남겨야 한다. 채택한다.
4. 프로필 기준 행 생성(프로필의 학력·경력 개수만큼 행 추가, 초기안): 구현은 단순하다. 하지만 사이트가 요구하지 않는 행이 생기고, 종료 조건이 프로필 개수에 묶이며, 프로필 개수가 판단 입력이 된다. 폐기하고 무엇을 만들지는 사이트 근거로 정하며 프로필은 필터로만 쓴다(E3).
5. 클릭 차단을 문구 필터와 모델 판단에만 맡김(현재 방식의 확장, E5): 추가 구현이 적다. 하지만 문구가 무해한 기본 submit button이나 이동 링크를 막지 못하고, 모델 판단은 결정적이지 않다. 폐기하고 코드 허용 목록을 1차, JEV 판단을 2차로 둔다.
6. 확신도 이진 컷 유지와 3단계 등급 비교(E9): 이진 컷은 단순하지만 낮은 확신도의 정답 후보를 버린다. 3단계 등급은 이런 후보를 사람 확인으로 살릴 수 있다. 대신 확인 필요 칸이 많아지면 사용자 부담이 커지므로 기본 체크를 해제하고, 경계는 측정 후 조정한다. 3단계를 채택한다.
7. 전체 화면을 한 번에 계획하는 방식과 막힌 곳에만 관찰-행동-재감지 루프를 쓰는 방식 비교(E2): 한 번에 계획하면 호출은 적지만 재감지를 못 한다. 루프는 호출 수와 비결정성을 막힌 섹션으로 한정한다. 다만 무한 반복을 막아야 하므로 아래 상한을 둔다. 루프를 채택한다.

## 결정

대안 3을 채택하고 대안 5·6·7의 보완을 함께 적용한다.

적용 경계:
- 문서 회사 판정이 generic일 때 실행하는 범용 경로에만 적용한다. 정적 어댑터의 preparation과 동작은 바꾸지 않는다.

승인 없이 자동으로 수행하는 구조 행동(이 셋에 한정):
- 행 추가(REPEAT_ADD): 사이트의 반복 그룹에 행을 하나 추가한다.
- 섹션 펼치기(SECTION_REVEAL): 접힌 섹션을 펼친다.
- 행 종류 선택(ROW_KIND_OPTION): 섞인 반복 행에서 사이트가 제시한 행 종류 선택지 중 하나를 고른다. 선택한 뒤에는 그 행을 다시 매칭해 검증하고, 검증에 실패하면 그 행을 입력 불가로 표시한다. 특정 사이트에서 유래한 별칭 표나 "첫 select" 규칙은 쓰지 않는다.

승인을 유지하는 범위:
- 모든 프로필 값 쓰기는 검토 화면에서 사용자가 승인한 뒤에만 실행한다.
- 민감 확인 항목은 개별 승인을 유지한다.

어떤 경우에도 클릭하지 않는 대상:
- 제출, 저장, 임시저장, 페이지 이동, 삭제, 업로드, 로그아웃, 미리보기, 초기화 요소.

클릭 판단 구조:
- 1차(코드 허용 목록): 다음 중 하나라도 해당하는 요소는 후보에서 제외한다.
  - 보이지 않거나 비활성화된 요소
  - form 안에 있으면서 type이 명시적으로 button이 아닌 button
  - submit·reset·image 형식의 input
  - href가 페이지 안 이동이나 빈 스크립트가 아닌 링크
  - 새 창을 여는 target
  - formaction이나 form 속성을 가진 요소
  - 금지 문구 합집합에 해당하는 요소
  - 대상 섹션이나 반복 그룹 범위 밖에 있는 요소
- 2차(JEV 판단): 1차를 통과한 후보만 JEV 질문에 넣는다. JEV가 기권하면 실행하지 않는다.
- 클릭 뒤에는 기존 사후 검증(행 수 증가, 기존 값 보존, URL 불변)을 그대로 적용한다. 위반이 확인되면 해당 섹션을 중단한다.

반복 상한과 실패 격리:
- 구조 행동은 섹션당 최대 10회까지 실행한다.
- 같은 후보가 2회 실패하면 그 후보는 더 시도하지 않는다.
- 추가 버튼이 비활성화되거나 사라지면 멈춘다.
- 실패는 섹션 단위로 격리한다. 실패한 섹션은 입력 불가와 이유로 표시하고 나머지 섹션은 계속 진행한다.

기록:
- 결과 화면에 자동으로 수행한 구조 행동(섹션, 행동 종류, 결과)을 표시한다. 사용자는 승인 없이 일어난 페이지 변화를 확인할 수 있다.

확신도 3단계:
- 자동: 확신도 0.8 이상이고 코드 검사를 통과한 칸. 검토 화면에서 기본으로 체크된다.
- 확인 필요: 확신도 0.5 이상 0.8 미만인 칸. 검토 화면에서 기본으로 체크가 해제된다.
- 입력 불가: 확신도 0.5 미만이거나 근거가 없는 칸. 이유를 함께 표시한다.
- 선택지 형식, 칸 종류, 행 일관성 코드 검사에 실패하면 등급을 낮춘다.
- 경계값 0.8/0.5는 측정 후 조정할 수 있는 제안값이다. 사전·사후 측정(Task3, Task15) 결과로 확정한다.

제품 기준과의 관계:
- 이 ADR은 "사용자 확인과 통제"를 값 쓰기와 민감 항목 승인 경계로 적용한다. 구조 행동은 사용자 데이터를 쓰지 않고 빈 행이나 펼친 섹션만 만든다. 그래서 허용 목록, 상한, 결과 기록을 조건으로 자동화한다.
- 제품 기준 원문은 이 Issue에서 수정하지 않는다. 이 해석을 제품 기준에 반영할지는 Task17에서 사람이 결정한다.

## 결과

- 범용 지원서의 승인 단계가 줄고, 행 추가 뒤 드러난 칸까지 한 흐름에서 처리할 수 있다.
- 실수로 클릭될 위험은 코드 허용 목록, JEV 판단, 사후 검증의 세 겹으로 줄인다. 그래도 자동으로 추가된 빈 행이 페이지에 남을 수 있다. 자동 삭제는 금지이므로 정리는 사용자가 한다.
- 승인 모델이 바뀐다. 따라서 후속 Issue는 허용 목록(Task4), 구조 역할(Task9), 루프와 실패 격리(Task11), 등급 검토 화면(Task12), 행 종류 선택(Task13)에서 각각 이 경계를 테스트로 고정해야 한다. 정적 회귀 검사(STATIC-REGRESSION)도 매번 통과해야 한다.
- 확인 필요 칸이 많아지면 사용자 부담이 늘 수 있다. 경계값과 기본 체크 해제 정책은 측정 결과로 다시 검토한다.
- 값 쓰기 무승인화, 그리고 제출·저장·임시저장·페이지 이동·미리보기 자동화는 이 결정으로 허용되지 않는다.
