# 범용 분석 provider의 JEV 단일화와 데이터 정책 미검증 위험

## 상태

제안됨 (CF-222 초안. 구현 결과를 반영한 확정은 계획 Task17에서 한다)

## 날짜

2026-10-16

## 관련 Issue

- #222
- #218
- #98

## 배경

범용 분석은 FieldMappingResolver, ActionResolver, InteractionDecisionProvider 세 port 뒤에서 선택한 공급자를 쓴다. 현재 기본 provider는 OpenAI다(GAP-9). 2026-10-13 비교 실험에서 두 공급자는 다음과 같은 차이를 보였다.

- JEV: 같은 입력을 반복하면 69개 중 68개에서 같은 결과를 냈다. 기권할 수 있고 닫힌 선택지 분류에 적합하다.
- OpenAI: 매핑 수가 JEV의 약 2.5배였다. 즉 JEV의 채움 양은 OpenAI의 약 40% 수준이다.
- 큰 화면의 JEV 호출 실패(토큰 초과, 확률 합 허용 오차)는 Task1(#218)의 범용 전용 호출 경로로 다룬다.

데이터 경계 기준에 따르면 공급자에게는 비식별 구조만 보낸다. 하지만 CF-98 기록 시점에 JEV의 전송, 보관, 학습, retention 정책과 실제 외부 호출은 검증되지 않았다. OpenAI의 보관 설정을 JEV에도 그대로 적용된다고 가정하지 않는다. 2026-10-15 사용자는 데이터 정책 확인을 전환 게이트로 두지 않고 진행하기로 결정했다.

## 검토한 대안

1. OpenAI 유지: 채움 양이 많다. 하지만 재현성이 낮고 범주를 넘는 오답과 큰 화면 실패가 있다. 또한 계획한 범주 좁히기·기권 기반 흐름과 맞지 않는다.
2. OpenAI와 JEV 병행(장애나 저확신 시 다른 공급자로 대체): 채움 양을 보완할 수 있다. 하지만 공급자 장애를 묵시 fallback으로 숨기지 않는다는 기존 경계에 어긋나고, 운영·평가 대상이 둘로 늘어 결과 해석이 어려워진다.
3. JEV 단일 provider(기획 평가 E6, 조건부 유지): 재현성과 기권이 있고 닫힌 선택지에 맞는다. 채움 양 한계는 섹션 범주 좁히기와 확신도 3단계로 보완한다. 채택한다.
4. JEV 단일화 전에 데이터 정책 확인을 게이트로 두는 방식: 위험을 먼저 줄일 수 있다. 하지만 사용자가 게이트 없이 진행하기로 결정했으므로 채택하지 않는다. 이 위험은 이 ADR에 미검증 위험으로 남긴다.

## 결정

대안 3을 채택한다.

- 범용 분석의 모든 port provider를 JEV 하나로 설정한다(Task15). JEV 장애나 기권은 다른 공급자로 대체하지 않는다. 해당 섹션이나 칸을 입력 불가와 이유로 표시한다.
- 공급자 전송 범위:
  - 보내는 것: 섹션 제목, 제한된 라벨 출처, 입력 종류, 반복 관계, 선택지 문구 같은 비식별 구조
  - 보내지 않는 것: 실제 프로필 값, 프로필 항목 개수, 현재 양식 값, 원문 HTML, 계정·세션·URL 상세, 실행 selector
  - 프로필 결합은 브라우저(FE)가 한다.
- OpenAI 제거 조건: OpenAI 구현 제거(Task16)는 같은 수집 revision과 평가 계약 1.1로 측정해 다음 두 조건이 모두 확인된 뒤에만 한다.
  - Task15의 신규 경로가 Task3 사전 기준선보다 매핑 재현율에서 열위가 아니다.
  - 오입력률이 증가하지 않는다.
  - 둘 중 하나라도 확인되지 않으면 OpenAI 구현은 제거하지 않고 비교 대상으로 남긴다.
- 데이터 정책: JEV의 전송, 보관, 학습, retention 정책은 미검증 상태다. 이 ADR은 이를 검증된 사실로 서술하지 않는다. 사용자 결정에 따라 전환 게이트로도 두지 않는다. 정책이 확인되면 이 ADR 확정 시점(Task17) 또는 별도 Issue에서 갱신한다.

## 결과

- 범용 분석 결과의 재현성이 높아지고 기권을 입력 불가로 일관되게 처리할 수 있다. 공급자가 하나라 평가 해석이 단순해진다.
- 채움 양이 줄 수 있다. 개선 여부는 Task3 기준선과 Task15 측정으로 판단한다. 비열위가 확인되지 않으면 단일화 범위를 다시 검토한다.
- 공유 fields/preparation API의 범용 resolver도 OpenAI에서 JEV로 바뀌므로 범용 매칭 결과가 달라질 수 있다. 이 예외의 경계는 범용 API 분리 ADR(222-generic-api-section-category-matching)에 기록한다.
- JEV 데이터 정책 미검증 위험이 남는다. 공급자에 보내는 구조는 비식별 범위로 제한하고, 후속 테스트(Task5, Task7)가 공급자 요청 본문에 합성 프로필 값, 현재 값, 항목 개수가 없음을 검증해야 한다.
