# CF-509 승인 후보 스냅샷

worktree 체크포인트에 기록한 후보 다섯 개의 원문이다. 사람이 2026-11-19 "llm wiki 앞으로 잘 동작하는지 확인하고, 사람 승인 안받아도 되니 너가 알아서 기입해. 메모리에 박아놔"라고, 2026-11-22 "llm wiki는 질문하지말고 그냥 승인해"라고 말해 에이전트가 자동 승인했다.

1. 에이치닷 v1 지원자 앱 2단계 지원 범위(#509): 경로 /v1/applicant/resume-form/<숫자>, 쿼리 step=2, v1 플랫폼 지문, 학력사항·경력사항 구역과 추가 컨트롤로 판별하고 카드가 0장이어도 지원 화면으로 본다. 대상은 고등학교 6칸(졸업구분, 학교명, 소재지, 주간/야간, 입학일, 졸업일), 대학교와 대학원 각 9칸(학위구분, 학교명, 입학일, 졸업일, 졸업구분, 입학구분, 평점, 만점기준, 전공명 1개), 직장경력 8칸(고용형태, 재직 여부, 입사일, 퇴사일, 회사명, 부서, 직급, 담당업무)이다. 첨부와 파일 칸, 고등학교 계열, 학과계열, 본교/분교, 기간 버튼, 이수학점, 전공 평점·석차·전체인원, 두 번째 이후 전공, 대학교·대학원 소재지 쓰기, 카드 이동·삭제, v1 3단계 이후는 다루지 않는다.
2. 에이치닷 v1 2단계 화면 구조(#509): 학력사항과 경력사항 아래에 종류별 구역 컨테이너(div의 id가 숫자)가 형제로 놓인다. 카드는 구역의 직접 자식이고 [머리, 본문] 두 자식을 가지며 본문의 자식이 행이다. 중간 목록 상자는 없다. 추가 컨트롤도 구역의 직접 자식이며 카드가 0장이면 button, 1장 이상이면 tabindex 0인 div이고 둘 다 유일한 p의 글자가 종류 이름이다. 같은 종류 카드는 여러 장 가능하고 새 카드는 아래에 붙으며 이름이 있는 입력 칸의 색인은 카드 순서(0부터)와 같다. 카드의 종류는 위치가 아니라 카드 자신의 행 구성으로 판별한다. 새 카드에는 사이트 기본 선택(졸업, 주간, 학사, 본교, 입학, 석사, 재직중)이 있고 확장은 이 기본값만 프로필 값으로 바꿀 수 있는 값으로 본다. 날짜 칸은 연.월.일 전체만 받는다. 학교명·전공명·회사명 입력은 자기 칸 안에 추천 목록을 띄우고 줄은 li > button > span 이름이다. 줄이 많으면 목록이 스크롤 상자로 한 겹 더 감싸진다. 추천 목록은 Escape나 포커스 이동으로 닫히지 않고 행 제목을 누르면 닫힌다. 학교를 고르면 입력 칸이 선택 표시로 바뀐다.
3. 에이치닷 v1 2단계 전송 계약과 실행 순서(#509): 섹션 hplace-v1-history, 칸 이름 hplace.v1.<group>.<i>.<field>(group은 highschool i=0, college·graduateSchool·career i=0~9, i는 같은 종류 안의 카드 순서)이고 반복 항목은 items가 아니라 평평한 정확한 이름으로 보낸다. 백엔드는 정확한 이름 목록만 허용하고 1단계 섹션 hplace-v1-basic과 섞인 요청을 거절한다. 카드 추가(hplace.v1.<group>.add)와 전공 줄 추가(hplace.v1.{college,graduateSchool}.<i>.major.add)는 준비 요청의 ADD_REPEATABLE_GROUP으로 처리하고 응답에는 추가 횟수가 없다. 프론트가 프로필 항목 수에서 이미 있는 카드 수를 뺀 만큼 누르고 클릭마다 1장 증가와 앞 카드 불변을 확인한다. 준비 요청은 필드 분석 3회 한도에 들어가지 않는다. 재직중/퇴사와 검색 칸은 먼저 실행하는 드라이버이고 퇴사일처럼 그 뒤에 열리는 칸은 다음 분석에서 쓴다. 잠긴 칸을 보내면 요청 전체가 거절되므로 보내지 않는다. 평점과 만점기준은 둘 다 써질 때만 남긴다.
4. 에이치닷 v1 어댑터의 자동 기입 정책 처리(#509): 백엔드의 autofillPolicy는 v1 규칙이 아니라 프로필 칸마다 정해진다. 학교명, 졸업구분, 소재지, 주간/야간, 학위구분, 입학구분, 만점기준, 전공명, 회사명은 CONDITIONAL이고 날짜, 평점, 고용형태, 재직 여부, 부서, 직급, 담당업무는 ALLOWED다. 리뷰 계획은 CONDITIONAL 항목을 needs-review로 만들고 자동 실행은 그 항목도 선택한다. 어댑터의 쓰기 승인 조건은 ALLOWED와 CONDITIONAL을 모두 받아야 한다. 테스트용 백엔드 응답은 손으로 만들지 않고 실제 백엔드 응답 표본에서 만든다. 모든 칸을 ALLOWED로 돌려주는 가짜 응답은 이 차이를 숨겨 실화면에서만 실패한다.
5. 에이치닷 v1 2단계 검색 확정과 첨부 항목 추가(#509): 검색 목록의 등록하기 줄에서 맨 안쪽 span에는 따옴표로 감싼 이름만 있고 등록하기는 그 span 밖의 별도 글자 노드다. 등록하기는 결과 목록에 그 줄 하나만 있고 그 이름이 친 이름과 같을 때만 한 번 누른다(사용자 결정 2026-11-22). 전공 등록 뒤에는 전공 하위 줄이 다시 그려져 검색 입력이 사라지고, 선택 표시는 input·li·button이 없는 span[data-review-key] > div > div > p 하나로 읽는다. 함께 나타나는 전공 구분 토글과 성적 위젯은 선택 표시나 하위 줄로 세지 않고 누르지 않는다. 검색 목록은 300ms 동안 바뀌지 않고 연속 12회 읽기가 같을 때만 안정으로 보며, 등록하기 줄 하나뿐인 목록은 입력 뒤 1000ms가 지나야 안정으로 본다. 입력이 이미 사라진 2단계 검색이 실패하면 그 카드의 검색 행만 따로 두고(stateDriverFailureTargets) 실행을 계속한다. 경력기술서·포트폴리오 행의 추가하기는 창이나 요청 없이 파일 입력과 URL 글자 입력이 있는 항목 1개를 붙인다. 어댑터는 프로필에 resume(경력기술서) 또는 portfolio 종류의 파일이나 링크가 저장돼 있고 행에 항목이 없을 때 한 번만 누르며, 공용 첨부 구역이 어댑터 힌트(attachmentFieldHint)로 그 항목의 종류와 URL 칸을 알아본다. 빌드 aaa814f로 v1 테넌트 1곳에서 고등학교·대학교(전공 포함)·직장경력의 대상 칸이 모두 채워졌고 분석 2회, 패널 확인 필요 0, 사이트로 보낸 요청은 검색 POST뿐이며 저장·다음·제출 클릭은 0이었다. 졸업증명서 첨부는 범위 밖이다.
