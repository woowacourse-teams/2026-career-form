# 에이치닷 v1 지원자 앱 3단계 어학·자격·기타

> Issue: [CF-510](https://github.com/woowacourse-teams/2026-career-form/issues/510)
> Collected: 2026-11-23
> Approval-Digest: fb169cce8e40f21e49fc3432af9f7dd5df938a5fb0097ad54dd5401cb313b839

[승인 후보 스냅샷](approved-candidates.md)의 후보 1~5를 적는다. 두 번째 v1 테넌트의 차이는 [두 번째 테넌트 실측](hplace-v1-second-tenant.md)에 있다. v1 1단계와 2단계의 범위, 화면 구조, 전송 계약, 검색 규칙은 Supersedes가 가리키는 CF-509 근거와 그 이전 CF-507·CF-505 근거를 그대로 따른다. 이 문서는 3단계(`step=3`, 어학/자격/기타)만 더한다. MRS2 실행 정책과 동작은 바뀌지 않는다. 칸별 표는 [3단계 필드 현황](hplace-v1-step3-field-inventory.md)에 있다. 실제 지원값, 계정, 세션, 회사 화면 원문, 공고 제목은 적지 않는다.

## 화면 구조 (후보 1)

- 판별 조건은 경로 `/v1/applicant/resume-form/<숫자>`, 쿼리 `step=3`, v1 플랫폼 지문이다. 여기에 알려진 구역 제목(`h5`: `어학`, `자격/지식/기술`, `경험`) 중 하나 이상이 중복 없이 있고 대상 블록(자격증, 외국어활용능력)이 하나 이상 있어야 한다. 대상 블록은 있는 것만 각각 따로 다룬다(두 번째 v1 테넌트에는 어학 구역이 없다). 2단계와 4단계의 판별은 바뀌지 않으며 4단계 이후는 미지원이다.
- 첫 번째 v1 테넌트에는 `어학` 아래에 `공인외국어시험`과 `외국어활용능력`, `자격/지식/기술` 아래에 `자격증`과 `컴퓨터활용능력` 블록이 있다. 블록은 정확한 제목으로 찾는다.
- 블록 모양은 본문 > 감싸개 > [목록, `추가하기`]다. 블록마다 자기 `추가하기`가 있고 누르면 블록 안에 하위 줄이 하나 붙는다. 하위 줄은 [내용 `div`, 아이콘 버튼]이다. 하위 줄이 0개인 블록에는 목록 감싸개가 없을 수 있어 두 모양을 모두 인정한다.
- `경험` 구역(수상경력 등 5개)은 하위 줄이 아니라 구역 이름의 버튼으로 카드를 붙인다.
- 처음에는 입력 칸이 없다. 하위 줄을 붙여야 칸이 생긴다.
- 모양이 계약과 다른 블록이나 칸은 그것만 빼고 입력 불가(화면 구조 확인 불가)로 보고한다.

## 공인외국어시험 제외 (후보 2)

- 하위 줄의 검색 칸은 2단계와 같은 모양의 목록을 띄운다. 시험을 고르면 새 탭으로 외부 성적 확인 페이지가 열리고, 등록번호·취득점수·만점기준 입력은 잠긴 채로 남는다.
- 성적은 사이트의 확인 절차로만 채워진다. 확장은 확인 창을 열지 않아야 하므로 이 블록 전체를 범위에서 뺐다(에이전트 판단, 안전 쪽). 어댑터는 이 블록에서 아무것도 찾거나 수집하거나 누르지 않는다.
- 테스트는 이 블록의 클릭과 입력을 금지 동작으로 기록하고 0건을 단언한다.

## 자격증·외국어활용능력 하위 줄 (후보 3)

- **자격증 검색:** 하위 줄은 이름 없는 검색 입력(placeholder `자격증명을 검색해주세요.`)으로 시작한다. 검색 요청은 `POST …/search-filter/license`이고 목록 줄은 `li > button > span` 이름이다.
- **선택 뒤 모양:** 정확히 일치하는 줄을 고르면 창 없이 하위 줄이 다시 그려진다. 선택 표시는 `span[data-review-key] > div > div > p`이고(review-key가 없는 테넌트에서는 이름 묶음의 유일한 글자 잎), 발급기관 글자 칸, 이름 없는 취득일 글자 칸(placeholder `취득일`), 등록번호 글자 칸이 나타난다. 발급기관과 등록번호는 placeholder와 이름 앞부분으로 찾는다.
- **취득일:** 과거 날짜만 넣는다. 전체 날짜는 `YYYY.MM.DD`로, 월까지만 있는 프로필 날짜는 `YYYY.MM`으로 쓰고 미래 날짜는 넣지 않는다. 페이지가 `YYYY.MM`만 남기면 같은 연월을 유지로 본다. 넣은 뒤 포커스를 잃게 하고 값을 다시 읽어 사라졌으면 실패로 본다.
- **검색 규칙:** 정확 일치 선택, 등록하기 줄 한 번 누르기, 목록 안정 판정, 실패 뒤 정리는 2단계와 같다. 2단계 검색 엔진을 공용 모듈 `v1-search.ts`로 옮겨 2단계와 3단계가 함께 쓴다. 3단계에서는 블록이 포함 범위이자 제목 줄이다.
- **외국어활용능력:** 하위 줄의 첫 컨트롤은 언어 드롭다운이다. 정확히 같은 선택지만 고르고, 선택지에 없거나 이미 다른 언어가 골라져 있으면 쓰지 않는다.
- **기존 값:** 글자 칸의 기존 값은 덮어쓰지 않는다. 다른 이름이 있는 선택 표시는 충돌로 보고하고 바꾸지 않는다. 최대 길이를 넘는 값은 쓰지 않는다.

## 전송 계약과 범위 (후보 4)

- 섹션 ID는 `hplace-v1-extra`이고 `domId`와 `domName`이 같다. 칸 이름은 `hplace.v1.certificate.<i>.{licenseName,organization,acquireDate,registNumber}`와 `hplace.v1.languageSkill.<i>.language`(i=0~9)다. 허용 이름은 생성한 정확한 목록 50개다.
- 자격증 칸은 `input`/`text`, 언어는 `select`/`select`로 보낸다. 자격증명은 먼저 실행하는 검색 드라이버다.
- 자격증명·발급기관·언어는 CONDITIONAL, 취득일·등록번호는 ALLOWED다. 언어는 측정한 선택지 이름에 대한 LOOKUP이다.
- 하위 줄 추가는 준비 요청의 `ADD_REPEATABLE_GROUP`인 `hplace.v1.certificate.add`와 `hplace.v1.languageSkill.add`(`button`/`button`)다. 응답에는 추가 횟수가 없고 프론트가 프로필 항목 수에서 이미 있는 하위 줄 수를 뺀 만큼 누른다. 늘지 않으면 준비를 실패로 끝낸다. 모양이 다른 블록에는 추가를 제안하지 않는다.
- 범위 밖: `경험` 구역, `컴퓨터활용능력`(프로필 범주 없음), 회화수준(측정한 하위 줄에 두 번째 컨트롤이 없다), 자격증 등급(선택 뒤 하위 줄에 등급 컨트롤이 없다), 파일 칸. 백엔드는 이 이름과 다른 섹션과 섞인 요청을 거절한다.
- 지원서의 임시저장, 다음 단계, 단계 표시, 제출, 동의, 삭제 아이콘은 누르지 않는다.
- MRS2 정책 문서와 지원 프로필 키 목록은 바뀌지 않는다.

## 실화면 상태 (후보 5)

- 화면 구조와 블록 모양, 공인외국어시험의 외부 확인 탭, 자격증 선택 뒤 칸 모양과 취득일 칸 모양은 v1 테넌트 1곳에서 공개 검색어로 측정했다. 지원서는 저장하지 않았고 측정 뒤 다시 불러왔다.
- 첫 번째 v1 테넌트의 공고가 2026-11-22에 마감돼 그 테넌트에서는 3단계를 실화면에서 돌리지 않았다.
- 두 번째 v1 테넌트에서 빌드 fc0d9bc가 자격증 하위 줄 1개를 붙이고 자격증명·발급기관·취득일·등록번호를 채웠다. 자격증명에 `입력 결과를 확인하지 못했어요` 1건이 남았고, 사이트로 보낸 GET 외 요청은 자격증 검색 POST뿐이었다. 값 없는 판독 진단 빌드 0eb8030은 2026-11-23 사이트 세션 만료(로그인 화면)로 실행하지 못했다.
- 근거는 측정한 모양으로 만든 합성 fixture와 단위·workflow 테스트다(2026-11-22 26파일 522개, 두 번째 테넌트 반영 뒤 26파일 566개 통과). 금지 클릭 기록은 모든 테스트에서 0건이다.
- 실측하지 않은 가정: 자격증 등록하기 줄 모양, 행 제목 클릭으로 자격증 목록이 닫힌다(정리 경로에서만 사용), 외국어활용능력 실화면 기입, 처음 30개 이후의 언어 선택지. 모두 안전 쪽으로 실패한다.
