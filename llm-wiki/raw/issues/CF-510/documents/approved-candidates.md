# CF-510 승인 후보 스냅샷

> Issue: [CF-510](https://github.com/woowacourse-teams/2026-career-form/issues/510)
> Collected: 2026-11-23
> Approval-Digest: fb169cce8e40f21e49fc3432af9f7dd5df938a5fb0097ad54dd5401cb313b839

worktree 체크포인트에 기록한 후보 열한 개의 원문이다. 2026-11-22의 후보 다섯 개 중 1·3·5를 두 번째 v1 테넌트 실측에 맞게 고치고 6~11을 더했다. 사람이 2026-11-19 "llm wiki 앞으로 잘 동작하는지 확인하고, 사람 승인 안받아도 되니 너가 알아서 기입해. 메모리에 박아놔"라고, 2026-11-22 "llm wiki는 질문하지말고 그냥 승인해"라고 말해 에이전트가 자동 승인했다.

1. 에이치닷 v1 3단계 화면 구조(#510): 경로 /v1/applicant/resume-form/<숫자>, 쿼리 step=3, v1 플랫폼 지문, 알려진 구역 제목(h5: 어학, 자격/지식/기술, 경험) 중 하나 이상이 중복 없이 있고 대상 블록(자격증, 외국어활용능력)이 하나 이상일 때 지원 화면이다. 대상 블록은 있는 것만 각각 따로 다룬다. 첫 번째 v1 테넌트에는 어학 아래 공인외국어시험·외국어활용능력, 자격/지식/기술 아래 자격증·컴퓨터활용능력 블록이 있고 블록마다 자기 추가하기가 블록 안에 하위 줄을 붙인다. 블록 모양은 본문 > 감싸개 > [목록, 추가하기]이고 하위 줄은 [내용 div, 아이콘 버튼]이며 하위 줄이 0개인 블록에는 목록 감싸개가 없을 수 있다. 경험 구역(수상경력 등)은 구역 이름의 버튼으로 카드를 붙인다. 처음에는 입력 칸이 없다.
2. 에이치닷 v1 3단계 공인외국어시험 제외(#510): 시험을 고르면 새 탭으로 외부 성적 확인 페이지가 열리고 등록번호·취득점수·만점기준 입력은 잠긴 채로 남는다. 성적은 사이트의 확인 절차로만 채워지므로 어댑터는 이 블록에서 아무것도 찾거나 수집하거나 누르지 않는다(에이전트 판단, 안전 쪽). 테스트는 이 블록의 클릭과 입력을 금지 동작으로 기록한다.
3. 에이치닷 v1 3단계 자격증·외국어활용능력 하위 줄(#510): 자격증 하위 줄은 이름 없는 검색 입력(placeholder 자격증명을 검색해주세요.)으로 시작하고 검색 요청은 POST …/search-filter/license다. 정확히 일치하는 줄을 고르면 창 없이 선택 표시, 발급기관 글자 칸, 이름 없는 취득일 글자 칸(placeholder 취득일), 등록번호 글자 칸이 나타난다. 선택 표시는 span[data-review-key] > div > div > p이고, review-key가 없는 테넌트에서는 이름 묶음의 유일한 글자 잎으로 읽는다. 취득일은 과거 날짜만 넣는다. 페이지가 YYYY.MM만 남기면 같은 연월을 유지로 보고, 월까지만 있는 프로필 날짜는 YYYY.MM으로 쓴다. 검색 확정·등록하기·목록 안정 규칙은 2단계와 같고 2단계 검색 엔진을 공용 모듈 v1-search.ts로 옮겨 함께 쓴다. 외국어활용능력 하위 줄은 언어 드롭다운이며 정확히 같은 선택지만 고른다. 기존 값과 다른 이름의 선택 표시는 덮어쓰지 않는다.
4. 에이치닷 v1 3단계 전송 계약과 범위(#510): 섹션 hplace-v1-extra, 칸 이름 hplace.v1.certificate.<i>.{licenseName,organization,acquireDate,registNumber}와 hplace.v1.languageSkill.<i>.language(i=0~9, 정확한 이름 50개), 추가 동작 hplace.v1.certificate.add와 hplace.v1.languageSkill.add(준비 요청의 ADD_REPEATABLE_GROUP, 프론트가 프로필 항목 수에서 이미 있는 하위 줄 수를 뺀 만큼 누름)다. 자격증명·발급기관·언어는 CONDITIONAL, 취득일·등록번호는 ALLOWED다. 경험 구역, 컴퓨터활용능력(프로필 범주 없음), 회화수준, 자격증 등급, 파일은 범위 밖이고 백엔드는 그 이름을 거절한다. MRS2 정책 문서는 바뀌지 않는다.
5. 에이치닷 v1 3단계 실화면 상태(#510): 첫 번째 v1 테넌트의 공고가 2026-11-22에 마감돼 그 테넌트에서는 3단계를 실화면에서 돌리지 않았다. 두 번째 v1 테넌트에서 빌드 fc0d9bc가 자격증 하위 줄 1개를 붙이고 자격증명·발급기관·취득일·등록번호를 채웠지만 자격증명에 '입력 결과를 확인하지 못했어요' 1건이 남았다. 사이트로 보낸 GET 외 요청은 자격증 검색 POST뿐이었다. 원인을 보려고 값 없는 선택 값 판독 진단 로그를 넣은 빌드 0eb8030은 2026-11-23 사이트 세션이 만료돼(로그인 화면) 실행하지 못했다. 외국어활용능력 실화면 기입과 처음 30개 이후의 언어 선택지는 실측하지 않았다.
6. 에이치닷 v1 테넌트별 구역 구성(#510): v1 테넌트마다 구역 구성이 다르다. 두 번째 v1 테넌트의 2단계 구역 제목은 학력사항·경력사항뿐일 수 있고, 3단계에는 어학 구역 없이 자격/지식/기술(자격증 블록)과 경험만 있다. 단계 이동 표시 글자도 다르다(예: 학력 및 경력, 자격/기타). 판별은 경로, step, v1 지문과 알려진 구역 제목 하나 이상(중복 없음)으로 하고 단계 이동 글자는 읽지 않는다. 2단계는 학력사항·경력사항 중 하나 이상과 종류 하나 이상이면 지원 화면이다. 범위 안의 블록과 종류는 각각 따로 다룬다.
7. 에이치닷 v1 2단계 추가 컨트롤과 카드 종류(#510): 추가 컨트롤 글자에 필수 표시가 붙을 수 있다(예: 고등학교 *). 종류 이름 뒤의 *만 허용하고 다른 덧글자는 종류로 보지 않는다. 첫 카드 뒤 추가 컨트롤은 필수 표시 없는 div[tabindex=0]이 된다. 카드 종류는 행 구성이 아니라 카드가 든 구역의 추가 컨트롤 이름으로 정한다. 대학교와 대학원 카드는 행 구성이 같을 수 있기 때문이다. 카드에 다른 종류의 측정 행이 있으면 그 종류는 입력하지 않는다. 어느 종류도 측정하지 않은 행(예: 퇴직사유)은 건너뛰고 입력 불가(화면 구조 확인 불가)로 보고한다. 카드는 구역의 직접 자식으로서 행 블록을 담고 모든 입력 컨트롤이 행 안에 있으면 인정한다.
8. 에이치닷 v1 저장되는 카드와 전공 하위 줄(#510): 어떤 테넌트는 추가한 카드를 사이트가 저장해 새로 불러와도 남긴다. 이미 있는 빈 카드도 프로필 항목 수에 세어(추가 수 = 프로필 항목 수 − 화면 카드 수) 중복 추가하지 않고 그 카드를 채운다. 전공 하위 줄에 이름 있는 입력이 없으면 검색 입력 수로 세고, 선택된 전공이 있으면 수를 모르는 것으로 보고 추가하지 않는다. 준비 단계가 멈추면 값 없는 stop stage=preparation 로그 한 줄로 동작 이름과 사유를 남긴다.
9. 에이치닷 v1 review-key 없는 검색 목록·선택 표시와 월 단위 날짜(#510): 어떤 테넌트에는 data-review-key span이 없다. 그때 검색 목록(#dropdown-body 아래 ul)은 입력의 행 밖, 같은 숫자 id 구역 안에 붙는다. 엔진은 입력 뒤 새로 나타난 목록 하나만 읽고 0개나 여러 개면 입력을 비우고 실패로 끝낸다. 고른 값은 검색 입력이 사라진 행 내용의 유일한 글자 잎(버튼·목록 항목·목록·svg·행 제목 밖)으로 읽고 없거나 여럿이면 읽지 않는다. 결과 화면 판독은 2단계와 3단계 규칙을 모두 쓴다. 입학일·졸업일·취득일은 페이지가 YYYY.MM만 남길 수 있다. 같은 날을 어떤 구분자로 보여도, 페이지가 연월만 보이면 같은 연월이면 유지로 본다. 월까지만 있는 프로필 날짜는 YYYY.MM으로 쓰고 전체 날짜만 받는 페이지가 지우면 value-not-kept로 보고한다.
10. 에이치닷 v1 첨부 항목(#510): 첨부 항목은 파일 위젯과 선택적인 URL 입력으로 센다. 경력기술서 항목은 파일+URL 입력, 포트폴리오 항목은 파일만일 수 있다. 다른 이름의 글자 입력이 있으면 수를 모르는 것으로 본다. 공용 첨부 구역은 결과 화면이나 중단 화면에 처음 나타날 때 페이지의 파일 칸을 한 번 읽고 저장된 프로필 파일을 붙인 항목에 자동으로 올린다(업로드 POST 1회). 그 테넌트에서는 업로드 뒤 다시 그려지며 저장하지 않은 포트폴리오 항목이 사라질 수 있다. 페이지 동작이며 바꾸지 않았다.
11. 에이치닷 v1 두 번째 테넌트 2단계 실화면(#510): 빌드 fc0d9bc의 실행이 패널 안내 0건으로 끝났다. 이미 있던 카드와 새로 붙인 카드·항목이 모두 채워졌고 필드 분석은 2회였다. 사이트로 보낸 GET 외 요청은 검색 POST와 첨부 업로드 1회뿐이고 임시저장·다음 단계·제출은 누르지 않았다.
