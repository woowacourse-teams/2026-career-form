# 에이치닷 v1 두 번째 테넌트 실측

> Issue: [CF-510](https://github.com/woowacourse-teams/2026-career-form/issues/510)
> Collected: 2026-11-23
> Approval-Digest: fb169cce8e40f21e49fc3432af9f7dd5df938a5fb0097ad54dd5401cb313b839
> Source-Revision: 0eb8030

[승인 후보 스냅샷](approved-candidates.md)의 후보 6~11과 고친 후보 1·3·5의 두 번째 v1 테넌트 부분을 적는다. 2026-11-22~23에 두 번째 v1 테넌트의 2단계와 3단계를 측정하고 실행했다. 바꾸지 않은 v1 2단계 계약은 CF-509 근거를, 3단계 계약은 [3단계 근거](hplace-v1-step3.md)와 [3단계 필드 현황](hplace-v1-step3-field-inventory.md)을 따른다. MRS2 정책과 백엔드 전송 계약은 바뀌지 않는다. 실제 지원값, 계정, 세션, 회사 이름, 회사 화면 원문, 공고 제목은 적지 않는다.

## 테넌트별 구역 구성 (후보 6, 후보 1)

- v1 테넌트마다 구역 구성이 다르다. 두 번째 v1 테넌트의 2단계 구역 제목은 `학력사항`·`경력사항`뿐일 수 있고, 3단계에는 `어학` 구역 없이 `자격/지식/기술`(자격증 블록)과 `경험`만 있다.
- 단계 이동 표시 글자도 다르다(예: `학력 및 경력`, `자격/기타`). 판별은 이 글자를 읽지 않는다.
- 3단계 판별: 경로, `step=3`, v1 지문, 알려진 구역 제목(`어학`, `자격/지식/기술`, `경험`) 중 하나 이상(중복 없음), 대상 블록 하나 이상. 블록마다 따로 다루고 없는 블록은 건너뛴다. 대상 블록이 하나도 없을 때만 미지원이다.
- 2단계 판별: 경로, `step=2`, v1 지문, `학력사항`·`경력사항` 중 하나 이상(중복 없음), 종류 하나 이상.

## 2단계 추가 컨트롤과 카드 종류 (후보 7)

- 추가 컨트롤 글자에 필수 표시가 붙을 수 있다(`고등학교 *`). 종류 이름 뒤에 `*`가 붙은 것만 허용하고 다른 덧글자(괄호 설명, `**` 등)는 종류로 보지 않는다.
- 첫 카드 뒤 추가 컨트롤은 구역의 마지막 자식인 `div[tabindex=0]`이 되고 필수 표시가 없다.
- 카드 종류는 카드가 든 구역의 추가 컨트롤 이름으로 정한다. 두 번째 테넌트의 대학교와 대학원 카드는 같은 6행(학위구분, 학교정보, 재학기간, 입학구분, 졸업구분, 전공)을 가질 수 있어 행 구성으로는 가를 수 없다. 추가 컨트롤이 없는 구역만 행 구성 규칙을 쓴다.
- 카드의 행은 그 종류의 측정 행과 어느 종류도 측정하지 않은 행으로만 이뤄져야 하고 그 종류의 행이 하나 이상 있어야 한다. 다른 종류의 측정 행이 있으면 그 종류는 입력하지 않는다.
- 어느 종류도 측정하지 않은 행(두 번째 테넌트 직장경력의 `퇴직사유`)은 수집·쓰기·클릭하지 않고, 짝이 되는 프로필 항목이 있으면 입력 불가(화면 구조 확인 불가)로 보고한다.
- 카드는 구역의 직접 자식으로서 행 블록을 담고 모든 입력 컨트롤(input, select, textarea)이 행 안에 있으면 인정한다. 행 밖의 감싸개·안내·버튼은 허용하고 누르지 않는다. 추가 컨트롤 이름이 종류와 맞지 않는 구역은 건너뛰고 값 없는 진단 줄(`v1-history-add-unmatched`, `v1-history-level-*`)을 남긴다.

## 저장되는 카드와 전공 하위 줄 (후보 8)

- 두 번째 테넌트는 추가한 카드를 사이트가 저장해 새로 불러와도 남긴다. 추가 수는 프로필 항목 수에서 화면 카드 수를 뺀 값이고, 이미 있는 빈 카드는 새 카드처럼 수집하고 채운다.
- 전공 하위 줄에 이름 있는 입력(`…MajorList.N.`)이 없으면 검색 입력 수로 하위 줄을 센다. 선택된 전공이 있으면 입력이 남지 않으므로 수를 모르는 것으로 보고 추가하지 않는다.
- 준비 단계가 멈추면 `stop stage=preparation key=<동작 이름> reason=<코드> detail=<값 없는 세부>` 한 줄을 남긴다. 결과와 화면 제목은 바뀌지 않는다.

## review-key 없는 검색 목록·선택 표시와 월 단위 날짜 (후보 9, 후보 3)

- 두 번째 테넌트에는 `data-review-key` span이 없다. 검색 목록(`div#dropdown-body` 아래 스크롤 감싸개 안의 `ul`)은 입력의 행 밖, 같은 숫자 id 구역 안에 붙는다.
- review-key가 없으면 엔진은 입력 뒤 그 구역에 새로 나타난 목록 하나만 읽는다. 입력 전부터 있던 목록은 무시하고, 새 목록이 0개나 여러 개면 입력을 비우고 실패로 끝낸다. review-key가 있는 테넌트는 전과 같다.
- 고른 값은 검색 입력이 사라진 행 내용의 유일한 글자 잎(버튼, 목록 항목, 목록, svg, 행 제목 밖)으로 읽는다. 3단계 자격증명은 이름 묶음(`div > div > div > p`, 입력·버튼이 없는 첫 내용 블록)의 유일한 글자 잎이다. 없거나 여럿이면 읽지 않는다(안전 쪽).
- 결과 화면의 진행 표시와 칸 상태 판독은 2단계 규칙 다음에 3단계 규칙을 쓴다.
- 입학일·졸업일(재학기간)과 취득일은 페이지가 `YYYY.MM`만 남긴다. 같은 날을 어떤 구분자로 보여도, 페이지가 연월만 보이면 같은 연월이면 유지로 본다. 다른 연월은 인정하지 않는다. 글자 칸, 버튼 묶음, 드롭다운은 그대로 정확히 비교한다.
- 월까지만 있는 프로필 날짜는 `YYYY.MM`으로 쓴다. 전체 날짜만 받는 페이지(첫 번째 테넌트)가 포커스를 잃은 뒤 지우면 최대 300ms 기다려 `value-not-kept`로 보고한다. 입사일·퇴사일은 두 번째 테넌트에서도 전체 날짜를 유지했다.

## 첨부 항목 (후보 10)

- 첨부 항목은 파일 위젯 하나와 선택적인 URL 입력 하나로 센다. URL 입력은 행의 이름을 가져야 하고 다른 이름의 글자 입력이 있으면 수를 모르는 것으로 본다(안전 쪽).
- 두 번째 테넌트의 경력기술서 항목은 파일+URL 입력, 포트폴리오 항목은 파일만이다.
- 공용 첨부 구역은 결과 화면이나 중단 화면에 처음 나타날 때 페이지의 파일 칸을 한 번 읽고, 저장된 프로필 파일을 붙인 항목에 자동으로 올린다(`POST …/attach-file/upload/resume` 1회). 준비 단계의 항목 수 확인에는 영향을 주지 않는다.
- 그 테넌트에서는 업로드 뒤 첨부 행이 다시 그려지며 저장하지 않은 포트폴리오 항목이 사라질 수 있다. 페이지 동작이며 바꾸지 않았다(업로드를 미루거나 생략할지는 별도 결정).

## 실화면 결과 (후보 11, 후보 5)

- **2단계, 빌드 fc0d9bc:** 패널 안내 0건으로 `자동 기입을 마쳤어요`. 이미 있던 고등학교·대학교 카드와 새로 붙인 직장경력 카드, 경력기술서 항목, 전공 하위 줄이 채워졌고 필드 분석은 2회였다. 사이트로 보낸 GET 외 요청은 학교·전공·회사 검색 POST와 첨부 업로드 1회뿐이었고 임시저장·다음 단계·제출은 누르지 않았다.
- **3단계, 빌드 fc0d9bc:** 자격증 하위 줄 1개를 붙이고 자격증명을 골랐으며 발급기관·취득일·등록번호를 채웠다. 자격증명에 `입력 결과를 확인하지 못했어요` 1건이 남았다. GET 외 요청은 자격증 검색 POST뿐이었다.
- **남은 일:** 결과 화면이 고른 값을 읽지 못한 이유를 값 없이 남기는 진단 줄(`skip stage=result … reason=picked-unread detail=…`, 글자 잎·이름 묶음·review-key 개수만)을 넣은 빌드 0eb8030은 2026-11-23 사이트 세션이 만료돼(로그인 화면) 실행하지 못했다.
- 첫 번째 v1 테넌트의 공고는 2026-11-22에 마감돼 그 테넌트에서 3단계는 실행하지 않았다.
- 실측하지 않은 것: 두 번째 테넌트의 대학원 카드 내부, 학위구분 글자, 등록하기 뒤 다시 그려진 모양, 외국어활용능력. 다른 모양은 그 칸만 입력 불가로 남는다.
