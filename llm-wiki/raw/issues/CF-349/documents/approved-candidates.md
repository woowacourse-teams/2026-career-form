# CF-349 approved candidates

1. [extension-push-notifications] 확장 Web Push 구독 수명주기: 설치(onInstalled)·브라우저 시작(onStartup)·켜기·재시도 알람·pushsubscriptionchange가 모두 PushSubscriptionService.sync()로 수렴한다. 서버가 endpoint로 중복 처리하므로 매번 다시 등록하고, 기존 브라우저 구독의 applicationServerKey가 서버 공개키와 다르면 unsubscribe 뒤 재구독한다. 끄기는 로컬 설정 off → 서버 해지 → 브라우저 unsubscribe 순서이며 켜기는 설정 on 뒤 등록이다. 상태는 registered·disabled·unsupported·not_configured·endpoint_unavailable·failed 6종을 chrome.storage.local(careerForm.push.status)에 남기고, 재시도는 NETWORK·TIMEOUT·SERVER_ERROR에만 chrome.alarms로 1·5·15·60분 상한 백오프를 건다. NOT_CONFIGURED, ENDPOINT_UNAVAILABLE(404), BAD_REQUEST, Chrome 121 미만은 재시도 없이 상태만 남긴다.
2. [extension-push-notifications] 조용한 공고 푸시 수신 규칙: pushManager.subscribe({ userVisibleOnly: false })와 manifest minimum_chrome_version 121(UA 메이저 버전 2중 확인)로 사용자에게 보이지 않는 푸시를 받는다. payload는 push-api.ts의 parseServerPosting으로 검증해 HTTP(S) 링크가 아니거나 형식이 다르면 버리고, 같은 공고 ID와 마감 지난 공고는 알림 없이 버린다. 알린 공고는 careerForm.push.notified에 공고 데이터와 함께 기록해 서비스워커 재시작 뒤의 클릭도 처리하며 마감이 지나면 정리한다. 탭은 알림 본문 클릭과 '공고 열기' 버튼의 사용자 클릭으로만 열고, '마감 알림 저장'은 기존 PostingService.save에 기본 알림 시점(1440·120분)으로 넘긴 뒤 저장·남은 알림 없음·이미 저장·마감 지남을 확인 알림으로 구분한다.

[extension-push-notifications] 확장 측 공고 알림 API 계약의 정본은 frontend/src/job-postings/push-api.ts 한 파일이다. 2026-10-26 기준 로컬 CF-348 브랜치(a98b9c1)의 NotificationController를 따른다: GET /api/v1/notifications/vapid-public-key → {publicKey}, POST /api/v1/notifications/subscriptions {endpoint, expirationTime, keys{p256dh, auth}} → 201/200 {subscriptionId, created}, POST /api/v1/notifications/subscriptions/unsubscribe {endpoint} → 204, GET /api/v1/notifications/postings → {postings[{id, company, role, link, opensAt, closesAt}]} 마감순, 푸시 payload는 같은 6필드 JSON. 요청에는 X-Career-Form-Version을 붙이고 credentials omit, 10초 타임아웃이며 404는 ENDPOINT_UNAVAILABLE, 미설정 빌드는 NOT_CONFIGURED로 강등한다. CF-348이 머지되기 전까지 계약 재확인이 필요하다.

[usage-analytics] 공고 알림 계측: PostHog 이벤트 push_subscription_enabled, push_subscription_disabled, posting_inbox_viewed, posting_inbox_saved(surface options)와 posting_notification_shown, posting_notification_opened, posting_notification_saved(새 surface notification)를 추가했다. 속성은 surface와 서버 공고 ID posting_id([A-Za-z0-9_-]{1,64})만 허용하고 회사명·링크·프로필 값은 parseAnalyticsMessage가 버린다. 백그라운드가 직접 만드는 알림 이벤트도 같은 PostHog 핸들러를 거쳐 키 없는 빌드는 전송하지 않는다.

[extension-push-notifications] 공지함과 구독 설정 UI 결정: 공지함은 관리 페이지 '지원 공고' 탭 안의 NoticeBoard 구역이며 사이드 패널의 기존 '지원 공고 관리' 진입을 재사용한다. 목록은 백그라운드 경유(careerForm.push 메시지, 관리 페이지 발신자만 허용)로 진행 중 공고를 받아 마감순으로 보여 주고, 저장 여부는 로컬 공고 url과 서버 link 문자열 일치로 판단하므로 서버 마감 변경은 로컬 리마인더에 반영되지 않는 한계가 남는다. 백엔드 미설정·엔드포인트 없음·네트워크 오류는 문구를 분리하고 다시 불러오기 버튼을 둔다. 구독 스위치는 기본 켜짐이고 미지원 Chrome에서는 비활성화하며, 구독 주소가 서버에 저장된다는 데이터 안내를 둔다(개인정보 고지 확정은 사람 몫).

[extension-push-notifications] 알림 표시 자가 진단 결정: Chrome 확장 API로는 OS 알림 허용 여부를 감지할 수 없어(chrome.notifications.create는 허용이 꺼져도 정상 완료) 사용자 응답으로 대신한다. 로컬 careerForm.push.visibility에 결과(unknown·seen·not_seen), 확인 시각, 출처(test·notification_click·card), 첫 표시 시각(shownAt), 나중에 시각(askLaterAt)을 두고, 테스트 알림(careerForm.push.test)은 사용자의 버튼 클릭으로만 띄우며 설치·시작·푸시 수신 시 자동 알림은 없다. 공고 알림 클릭은 자동으로 seen이다. 노출은 설치 온보딩 카드(SiteApp installed 모드에서 pushClient가 주입된 확장에서만, 공개 사이트 제외), 지원 공고 탭 질문 카드(미확인·구독 켜짐·나중에 없음), 첫 알림 뒤 미클릭 확인 카드(봤어요·못 봤어요), 구독 설정 패널의 결과 행과 상시 알림 테스트이며 결과가 기록되면 카드는 사라진다. not_seen이거나 getPermissionLevel이 denied면 macOS(시스템 설정 › 알림 › Google Chrome, 알림 스타일, 집중 모드)·Windows(설정 › 시스템 › 알림, 방해 금지)·Chrome 사이트 설정 경로를 UA에 따라 글로 안내하고 다시 테스트를 두며 시스템 설정을 대신 열지 않는다. 발신자 검사는 options.html 전체, onboarding.html은 status·disable·test·record만 허용하고 그 밖은 차단한다.

[extension-push-notifications] 미확인 공고 배지: 새 공고 알림마다 careerForm.push.unread에 공고 ID→마감 시각을 넣고 chrome.action.setBadgeText(숫자만)·setBadgeBackgroundColor·setTitle로 그린다. 공지함 열람(inbox 메시지가 목록을 받은 뒤)은 전부, 알림 클릭으로 연 공고는 개별로 지우고 마감 지난 항목은 정리하며, 서비스워커 시작마다 저장 목록으로 다시 그린다. 사이드 패널 '지원 공고 관리' 버튼은 storage를 직접 읽는 reader로 같은 개수를 표시하고 storage.onChanged로 갱신한다. 배지에는 회사명·직무를 넣지 않고 아이콘 클릭 동작(사이드 패널 열기)은 바꾸지 않는다.

[extension-push-notifications] 공고 열기 시 마감 알림 자동 저장: 설정 careerForm.push.autoSave는 기본 켜짐이며 구독 켜짐·꺼짐과 독립이다. 알림 본문 클릭, 알림 '공고 열기' 버튼, 공지함 '공고 열기' 세 경로에서 CF-161 PostingService.save에 기본 알림 시점으로 저장하고 이미 저장·마감 지난 공고는 건너뛰며 미래 알림이 없어도 목록에는 저장한다. 알림 표시만으로는 저장하지 않는다. 알림 경로는 careerForm.push.autosaved.<id> 후속 알림의 '저장 취소' 버튼, 공지함은 카드 인라인 '취소'로 PostingService.remove를 불러 저장 공고와 예약을 함께 지운다. 취소 대상은 url이 같은 planned 로컬 공고이며 수동 저장한 공고에는 취소를 제안하지 않는다. 저장 계측은 trigger(button·open)로 구분하고 취소는 posting_auto_save_cancelled로 기록한다.

[extension-push-notifications] 화면 정리와 계측 확장: 공지함은 3건까지 펼치고 'n건 더 보기'로 나머지를 열며, 구독 설정 패널은 저장 공고 목록 아래·알림과 로컬 저장 안내 위에 둬 저장 공고가 첫 화면에 보이게 한다. 알림 아이콘은 1254px 로고 대신 128px 전용 자산 notification-icon.png를 쓰고 CF-161 마감 알림도 같은 자산을 쓴다. 온보딩 하단 안내와 설정 패널에 'OS 알림이 꺼져 있어도 아이콘 숫자와 공지함으로 새 공고를 알 수 있다'를 적는다. 계측은 notification_test_sent, notification_visibility_answered(answer: seen·not_seen), posting_auto_save_cancelled를 더하고 저장 이벤트에 trigger(button·open)를 허용하며 그 밖의 값은 parseAnalyticsMessage가 버린다. 추가분은 모두 설정으로 되돌릴 수 있는 화면 동작이라 ADR 없이 topic Wiki extension-push-notifications에 근거를 남긴다.
