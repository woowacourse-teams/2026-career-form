# CF-349 approved candidates

1. [extension-push-notifications] 확장 Web Push 구독 수명주기: 설치(onInstalled)·브라우저 시작(onStartup)·켜기·재시도 알람·pushsubscriptionchange가 모두 PushSubscriptionService.sync()로 수렴한다. 서버가 endpoint로 중복 처리하므로 매번 다시 등록하고, 기존 브라우저 구독의 applicationServerKey가 서버 공개키와 다르면 unsubscribe 뒤 재구독한다. 끄기는 로컬 설정 off → 서버 해지 → 브라우저 unsubscribe 순서이며 켜기는 설정 on 뒤 등록이다. 상태는 registered·disabled·unsupported·not_configured·endpoint_unavailable·failed 6종을 chrome.storage.local(careerForm.push.status)에 남기고, 재시도는 NETWORK·TIMEOUT·SERVER_ERROR에만 chrome.alarms로 1·5·15·60분 상한 백오프를 건다. NOT_CONFIGURED, ENDPOINT_UNAVAILABLE(404), BAD_REQUEST, Chrome 121 미만은 재시도 없이 상태만 남긴다.
2. [extension-push-notifications] 조용한 공고 푸시 수신 규칙: pushManager.subscribe({ userVisibleOnly: false })와 manifest minimum_chrome_version 121(UA 메이저 버전 2중 확인)로 사용자에게 보이지 않는 푸시를 받는다. payload는 push-api.ts의 parseServerPosting으로 검증해 HTTP(S) 링크가 아니거나 형식이 다르면 버리고, 같은 공고 ID와 마감 지난 공고는 알림 없이 버린다. 알린 공고는 careerForm.push.notified에 공고 데이터와 함께 기록해 서비스워커 재시작 뒤의 클릭도 처리하며 마감이 지나면 정리한다. 탭은 알림 본문 클릭과 '공고 열기' 버튼의 사용자 클릭으로만 열고, '마감 알림 저장'은 기존 PostingService.save에 기본 알림 시점(1440·120분)으로 넘긴 뒤 저장·남은 알림 없음·이미 저장·마감 지남을 확인 알림으로 구분한다.
3. [extension-push-notifications] 확장 측 공고 알림 API 계약의 정본은 frontend/src/job-postings/push-api.ts 한 파일이다. 2026-10-26 기준 로컬 CF-348 브랜치(a98b9c1)의 NotificationController를 따른다: GET /api/v1/notifications/vapid-public-key → {publicKey}, POST /api/v1/notifications/subscriptions {endpoint, expirationTime, keys{p256dh, auth}} → 201/200 {subscriptionId, created}, POST /api/v1/notifications/subscriptions/unsubscribe {endpoint} → 204, GET /api/v1/notifications/postings → {postings[{id, company, role, link, opensAt, closesAt}]} 마감순, 푸시 payload는 같은 6필드 JSON. 요청에는 X-Career-Form-Version을 붙이고 credentials omit, 10초 타임아웃이며 404는 ENDPOINT_UNAVAILABLE, 미설정 빌드는 NOT_CONFIGURED로 강등한다. CF-348이 머지되기 전까지 계약 재확인이 필요하다.
4. [usage-analytics] 공고 알림 계측: PostHog 이벤트 push_subscription_enabled, push_subscription_disabled, posting_inbox_viewed, posting_inbox_saved(surface options)와 posting_notification_shown, posting_notification_opened, posting_notification_saved(새 surface notification)를 추가했다. 속성은 surface와 서버 공고 ID posting_id([A-Za-z0-9_-]{1,64})만 허용하고 회사명·링크·프로필 값은 parseAnalyticsMessage가 버린다. 백그라운드가 직접 만드는 알림 이벤트도 같은 PostHog 핸들러를 거쳐 키 없는 빌드는 전송하지 않는다.
5. [extension-push-notifications] 공지함과 구독 설정 UI 결정: 공지함은 관리 페이지 '지원 공고' 탭 안의 NoticeBoard 구역이며 사이드 패널의 기존 '지원 공고 관리' 진입을 재사용한다. 목록은 백그라운드 경유(careerForm.push 메시지, 관리 페이지 발신자만 허용)로 진행 중 공고를 받아 마감순으로 보여 주고, 저장 여부는 로컬 공고 url과 서버 link 문자열 일치로 판단하므로 서버 마감 변경은 로컬 리마인더에 반영되지 않는 한계가 남는다. 백엔드 미설정·엔드포인트 없음·네트워크 오류는 문구를 분리하고 다시 불러오기 버튼을 둔다. 구독 스위치는 기본 켜짐이고 미지원 Chrome에서는 비활성화하며, 구독 주소가 서버에 저장된다는 데이터 안내를 둔다(개인정보 고지 확정은 사람 몫).
