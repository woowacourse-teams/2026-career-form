# 장애·보훈·병역 상태에 따른 입력 잠금

> Issue: [CF-499](https://github.com/woowacourse-teams/2026-career-form/issues/499)
> Collected: 2026-11-21
> Approval-Digest: 43bd06f26f90e1df0244bb18e7c50840f0d5e59564315c15406a45236d5f86c7

[승인 후보 스냅샷](approved-candidates.md)의 후보 1~3을 적는다. 자격증 `registrationNo` 표시 라벨과 그 밖의 필드 계약은 Supersedes가 가리키는 CF-368 근거와 CF-41 현재본을 그대로 따른다.

## 잠금 규칙 (후보 1, commit 9855e85·cffc88a)

- `ProfileFieldDefinition`은 선택 속성 `disabledWhen(values)`을 가진다. 참이면 칸은 보이지만 편집할 수 없다.
- 장애: `장애 여부`가 비대상이면 장애 유형, 장애 정도, 장애등록번호, 장애 등록일을 잠근다.
- 보훈: `보훈 대상 여부`가 비대상이면 보훈구분, 보훈 대상자와의 관계, 보훈번호를 잠근다.
- 병역: 복무 7칸은 병역구분, 군별, 병과, 계급, 복무 시작일, 복무 종료일, 전역구분이다.

| 병역 상태 | 복무 7칸 | 면제·비대상 사유 |
| --- | --- | --- |
| 군필 | 열림 | 잠금 |
| 복무중 | 열림 | 잠금 |
| 미필 | 잠금 | 잠금 |
| 면제 | 잠금 | 열림 |
| 비대상 | 잠금 | 열림 |
| 빈 값 | 열림 | 열림 |

- 상태 판정: 저장 값이 표준값 ID와 같거나, 그 ID의 라벨·별칭과 NFKC·trim·소문자 정규화 뒤 같을 때만 참이다. 빈 값과 모르는 값은 잠그지 않는다.
- 화면: 잠긴 칸은 `disabled`이고 회색 배경·흐린 글자(`:disabled` 스타일)로 보인다. 저장 값은 지우지 않으며 상태를 바꿔 칸이 열리면 그대로 다시 보인다.
- 자동 기입: 값 연결(`value-binding`)은 잠긴 칸을 `missing`으로 본다. 상태 칸은 그대로 기입 대상이다.
- 가져오기: 페이지 가져오기 병합과 검토 선택은 잠긴 칸을 숨김 칸과 같이 거부한다.

## 병역 규칙의 근거와 한계 (후보 2)

- hplace 플랫폼 지원서는 군필·복무중일 때만 복무 상세 칸을, 면제일 때만 면제사유 칸을 연다. 우아한형제들 지원서도 면제일 때만 면제사유 칸을 추가한다(CF-324 실측).
- 프로필 칸 이름이 `면제·비대상 사유`라서 비대상에도 사유 칸을 연다.
- 미필의 사유 잠금은 칸 이름과 hplace 구조에서 나온 추정이다. 미필 사유를 묻는 지원서가 확인되면 다시 본다.
- 값 연결을 쓰는 정적 경로도 잠긴 칸에 남은 값을 쓰지 않는다. 그 밖의 정적 결과는 같다.

## 실화면 검증 방법 (후보 3)

- WSL `frontend`의 Playwright chromium으로 `launchPersistentContext`(channel chromium, headless, `--disable-extensions-except`·`--load-extension`에 빌드 결과 `.output/chrome-mv3`)를 별도 임시 프로필로 연다. 서비스 워커 URL에서 확장 ID를 얻어 `options.html`을 연다.
- 칸은 `aria-label`이 필드 라벨이라 정확한 라벨로 고르고, `disabled` 같은 DOM 속성과 계산된 배경·글자색 차이로 판정한다. 사용자 Chrome과 확장 폴더는 건드리지 않는다.
- 수정 전 빌드에서는 잠겨야 할 31칸이 모두 열려 있었다. 수정 뒤 69개 검사(시각 구분 1개 포함)가 모두 통과했다.
