# CF-350 approved candidates (2026-10-26, Web Push VAPID 시크릿과 알림 기능 배포 설정)

1. cicd-setup: 배포 설정 레버에 알림 토글과 VAPID 값을 추가한다. Environment 변수 `CAREER_FORM_NOTIFICATION_ENABLED`(기본 false), 선택 `CAREER_FORM_PUSH_DISPATCH_INTERVAL`(기본 60s), `CAREER_FORM_PUSH_CONCURRENCY`(기본 20)로 변수 13개, 환경 시크릿 `CAREER_FORM_PUSH_VAPID_PUBLIC_KEY`, `CAREER_FORM_PUSH_VAPID_PRIVATE_KEY`, `CAREER_FORM_PUSH_VAPID_SUBJECT`(mailto:)로 시크릿 10개. 값이 없으면 compose 기본값으로 기능이 꺼진 채 기동하고 `deploy.sh` 필수값 6개는 그대로다. 숫자·기간 선택값의 기본값은 compose가 backend application.yml과 같게 채운다: workflow는 Environment 값이 없으면 빈 문자열을 넘기고 Spring placeholder는 빈 문자열에 기본값을 적용하지 않기 때문이다. Environment 변수·시크릿은 배포 시점에 읽히므로 바꾼 뒤 새 배포가 있어야 반영되고, development는 workflow_dispatch가 없어 paths 필터에 걸리는 develop push가 필요하다. 키 생성·등록·회전 절차의 Wiki 밖 정본은 `infra/WEB_PUSH_VAPID.md`다.
2. deployment-runbook 릴리스 점검표: 병합 전 점검의 "운영 설정에 새 필수값이 없는지"와 함께 "이번 릴리스에서 운영 알림 토글(`CAREER_FORM_NOTIFICATION_ENABLED`)을 켤지, 켠다면 production 시크릿 3개 등록과 staging 종단 확인(시크릿 등록 → staging 배포 → health → [FE] #349 스테이징 빌드)을 마쳤는지"를 확인한다. 운영 토글은 릴리스 승인 시 사람이 결정하며 main 병합 배포가 있어야 컨테이너에 전달된다. VAPID 키 회전은 기존 구독 전부를 무효로 만들어 확장이 재구독해야 하므로 유출 의심 시에만 공지 뒤 수행한다.
