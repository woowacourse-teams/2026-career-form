# 선택 기반 검토 패널 소속과 개수

## 승인된 현재 계약

범용 검토 패널은 등급 이름뿐 아니라 실제 선택 상태를 따른다. 표시 대상 중 선택됨, available, 비활성 아님, BLOCKED 아님을 만족하는 항목은 달력이나 검색 팝업을 사용하더라도 자동 기입 예정 목록에 들어간다. 선택을 해제하거나 available이 아니면 예외 목록으로 이동하며 BLOCKED는 입력 불가, 나머지는 확인 필요다. 범용 자동 기입 예정 배지는 그 목록 길이를 사용한다.

`WorkflowScreens.tsx`의 `tiered` guard는 범용 등급이 있는 경로에만 이 분류를 적용한다. 정적 경로의 달력·검색 항목 예외 처리와 개수 계약을 바꾸지 않는다. 숨은 칸을 제외한 표시 대상과 목록 개수를 비교해야 하며 전체 DOM control 수나 등급만으로 현재 선택 개수를 대신하지 않는다.

## 근거와 관측 한계

- `frontend/src/autofill/workflow/WorkflowScreens.tsx`: `exceptionalItems`, `plannedItems`, `plannedCount`.
- 기존 `cert-fix-ed34db1/run-1`, `run-2`, `run-3`의 `measurement.json`을 직접 대조했다. 표시 대상 46개에서 각 배지·배타 목록·진단 개수가 일치했다. 전체 AUTO/REVIEW/BLOCKED는 각각 15/18/13, 14/19/13, 15/18/13으로 달랐다. 따라서 전체 매핑이 세 번 같았다는 결론은 내리지 않는다.
- `accuracy-e1ac505`의 기존 측정은 분석 후 key·행 정확도와 실제 기입 정확도를 구분한다. 이번 수집은 실제 기입·저장·제출을 수행하지 않았다.

CF-259의 등급·이유 코드 표시, 연결 못한 칸의 BLOCKED 보충과 입력 불가 토글 금지는 유지한다. 기본 선택된 검색·달력이 실행 성공을 보장하지는 않는다.
