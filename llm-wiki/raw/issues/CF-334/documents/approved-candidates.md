# CF-334 approved candidates (2026-10-25, [BE] Greeting 컬리 구조 반복 마지막 분석 응답이 간헐적으로 MATCH 0/81로 돌아와 27칸이 조용히 빈다)

1. Greeting 지원서에서 드라이버가 열어 둔 Ark UI 팝오버(검색 콤보박스·달력·선택 메뉴)는 나머지 화면에 `aria-hidden`을 걸어(hideOthers) 모든 칸이 숨김으로 수집된다. 정적 필드 세션의 재결합 신원에 `visibility`가 포함되므로 그 스냅샷은 전 칸 `NO_MATCH`가 되고, 회차 끝 재분석은 숨은 칸을 변경으로 치지 않아 승인 0건으로 조용히 끝난다. 컬리에서 2026-10-22와 2026-10-25(60회 중 4회) 관측했고 백엔드 응답은 모두 정상이었다. CF-334는 숨김 감지 시 열린 위젯을 Escape로 닫고 포커스를 뺀 뒤 다시 수집하며, 그래도 묶이지 않은 칸은 기입할 것 없이 끝나는 회차의 결과 경고에 이름으로 표시한다. CF-333 근거의 "분석 응답이 0/81로 돌아왔다"는 서술을 정정한다.
2. 열린 채 남는 경로는 검색이 선택 없이 끝난 뒤의 정리 단계(`searchFlows.cleanup`)가 그 순간의 `aria-expanded`만 보고 Escape 여부를 정하고 trigger가 현재 요소가 아니면 정리를 건너뛰는 데 있다. 늦게 열린 목록은 남는다. 정리 단계가 Escape 뒤 닫힘을 기다리고 blur까지 하도록 Greeting 정책을 올리는 보강은 별도 후보로 남긴다.
3. 확장의 분석 API 호출은 서비스 워커에서 나가므로 탭 단위 Playwright 관찰에는 잡히지 않는다. 브라우저 컨텍스트 단위(`PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`)로 붙어야 요청·응답 본문이 보이고, 회차별 수집 후보는 디버그 빌드가 `console.log("request", …)`로 남기는 객체를 `jsonValue`로 받아 대조할 수 있다. 숨김의 정체는 숨김 감지 순간에 `aria-hidden` 조상과 `[data-scope][data-state="open"]`, 포커스 요소를 읽기 전용으로 덤프해 확정했다.
4. 재현율이 낮은 간헐 결함(컬리 1/15 안팎)은 같은 탭에서 회차를 자동 반복하며 첫 재현에서 멈추는 관찰 루프가 유효했다. Greeting은 서버 임시저장이 없어 reset 없이 연속 실행이 가능하고, 하네스 `run.json`의 콘솔 기록은 문자열 요약만 담아 디버그 로그 한 줄(`dismissed leftover popups`, `fields-resettled`)을 수정 개입의 증거로 쓸 수 있다.
