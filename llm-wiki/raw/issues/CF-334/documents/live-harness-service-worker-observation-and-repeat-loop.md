Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 바꾸지 않은 내용(테스트 계정 모드, 설치본 잠금, 채점 재사용, 합성 프로필 학교 검색 한계, reset의 버튼형 위젯 잔여)은 Supersedes가 가리키는 CF-336 근거와 그 앞의 근거를 따른다. 실제 지원값·계정·세션·요청 본문은 포함하지 않는다.

## 승인 후보

- 확장의 분석 API 호출은 서비스 워커에서 나가므로 브라우저 컨텍스트 단위로 붙어야 보인다. 수집 후보는 디버그 빌드의 `console.log("request", …)` 객체로 대조하고, 숨김의 정체는 감지 순간의 읽기 전용 DOM 덤프로 확정한다.
- 재현율이 낮은 간헐 결함은 같은 탭에서 회차를 자동 반복하며 첫 재현에서 멈추는 관찰 루프로 잡는다. Greeting은 reset 없이 연속 실행이 가능하고, `run.json`의 콘솔 요약 한 줄이 수정 개입의 증거가 된다.
- 컬리 `MATCH 0/81`은 백엔드 응답이 아니라 프론트 재결합 요약이다.

## 근거

### 서비스 워커 API 관찰

- 확장의 `preparation/analyze`·`fields/analyze` 호출은 background service worker에서 나간다. 탭(page) 단위 Playwright `request`/`response` 리스너에는 잡히지 않는다. `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`로 CDP에 붙고 `context.on("request"|"response")`로 걸면 요청·응답 본문이 보인다. 2026-10-25 컬리 관찰에서 무너진 회차의 백엔드 호출은 2번뿐이고 응답은 `68/75`·`74/81`로 모두 정상이었다.
- 회차별 수집 후보(필드 목록)는 `VITE_AUTOFILL_DEBUG=true` 빌드가 `console.log("request", …)`로 남기는 객체를 콘솔 메시지의 `args()[1].jsonValue()`로 받아 회차 간 diff로 대조한다. 숨김의 정체는 숨김이 감지된 순간에 `aria-hidden` 조상, `[data-scope][data-state="open"]` 요소, `document.activeElement`만 읽기 전용으로 덤프해 확정했다. 클릭·입력은 하지 않는다.
- 관찰 기록은 회차마다 즉시 쓰고 SIGTERM에서도 flush해야 한다. 끝에 한 번만 쓰는 관찰기는 루프가 중단되면 기록을 잃는다.

### 반복 관찰 루프

- 컬리의 재현율은 1/15 안팎(2026-10-25 60회 중 4회)이어서 한 번의 `run`으로는 잡히지 않는다. 같은 탭에서 `run --label`을 자동 반복하며 회차마다 `run.json`의 마지막 분석 요약과 결과 패널 수를 읽고 첫 재현에서 멈추는 루프가 유효했다. 수정 전 재현에 60회, 1차 수정 검증에 30회, 2차 수정 검증에 40회를 썼다.
- Greeting 지원서는 사이트 서버 임시저장이 없어 `reset` 없이 연속 실행이 가능하다. 매 회차 결과 패널 완료 71·확인 필요 3이 정상 기준이었고, 무너진 회차는 완료 47·확인 필요 5였다.
- 하네스 `run.json`의 콘솔 기록은 문자열 요약만 담는다. 디버그 로그 한 줄(`dismissed leftover popups=1`, `stage name=fields-resettled`)을 회차 기록에서 찾으면 수정이 개입했는지와 복귀했는지를 값 없이 증명할 수 있다. 2차 검증 40회 중 159·161회차에서 둘 다 남고 결과가 정상이었다.
- 관찰 중 마지막 분석 요약의 분모가 81 외에 86·87로도 기록됐다(40회 중 11회). 행 추가 뒤 늘어난 칸을 포함한 마지막 요약이 기록된 회차이며 매칭 수(74)와 결과 패널은 같았다. 원인은 더 좁히지 않았다.

### 컬리 0/81의 정정

- Issue #334 최초 보고(2026-10-22 CF-333 측정)의 "구조 반복 마지막 분석 응답이 `MATCH 0/81`로 돌아왔다"는 백엔드 응답이 아니라 프론트 정적 필드 세션의 재결합 요약이다. 원인은 드라이버가 열어 둔 Ark UI 팝오버가 양식 전체에 `aria-hidden`을 걸어 수집이 전부 숨김이 된 것이고, 어댑터 관점의 상세는 [Greeting 어댑터 근거](greeting-open-popover-hides-form.md)를 따른다. CF-333 raw 문서 자체에는 이 서술이 없다.
