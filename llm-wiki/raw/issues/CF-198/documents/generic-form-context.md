# 범용 폼 컨텍스트 수집 경계와 전후 비교

## 수집 경계

범용 텍스트 수집은 기본 수집 어댑터의 식별이 아니라 `resolveDocumentCompany(document)`로 선택해야 한다. 정책과 컴포넌트 실행이 수집 helper를 공유할 수 있기 때문이다.

- label과 context 옵션이 생략된 경우의 동작을 보존한다.
- `semanticText`의 내부 판정을 보존한다.
- 구조적 행 탐색 결과는 동기 DOM 읽기 단계 안에서만 캐시한다. 쓰기나 await를 넘어 재사용하지 않는다.

## 실사이트 전후 비교

CF-198 수집기의 mapping-only 전후 비교를 실제 지원 페이지 두 곳에서 실행했다. 같은 backend(CF-181 `f0d27c41`)와 같은 OpenAI 모델을 사용했고 셀당 5회, 호출 20회, 채점 질문 14개였다.

| 구분 | 전 | 후 |
| --- | --- | --- |
| 전체 | 59/70 | 52/70 |
| 사이트 A | 0/10 | 6/10 |
| 사이트 B | 59/60 | 46/60 (비정상 전체 NO_MATCH 호출 1건을 제외하면 46/48 대 48/48) |

- 채점 질문의 잘못된 key는 0건이다.
- 수집 누락은 0건이다.
- 결과는 혼합이며 분산이 크다. 개선이 입증된 것이 아니다.
- 설치된 확장 프로그램 revision은 `UNVERIFIED`다.
- 범위는 보이는 native control에 한정한다.

## 평가 해석 주의

후보 개수가 전후 동일했으므로 한 사이트의 하락은 수집 누락이 아니라 모델 측 NO_MATCH다.
