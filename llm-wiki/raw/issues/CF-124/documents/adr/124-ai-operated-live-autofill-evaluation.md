## 배경

CF-115는 평가 계약과 첫 기준선을 제공하지만 실제 브라우저 실행은 재사용 가능한 공용 흐름이 아니다. 외부 Chrome의 로그인 세션과 설치된 확장 프로그램을 사용하면서 팀원이 같은 승인 경계와 보고 구조로 평가할 방법이 필요하다. 평가자가 실행 결과를 본 뒤 정답 기준을 바꾸는 순환 판정도 막아야 한다.

페이지가 회원가입 등으로 자동 주입한 값과 사용자가 앞서 입력한 값을 자동으로 구분할 수 없으므로, 평가 실행에서 두 값을 다르게 취급하면 일관된 비교가 불가능하다.

## 검토한 대안

1. 기존 값이 있으면 중단하고 새로고침을 요구한다.
   - 기존 값 보호에는 유리하지만 회원가입 기본값이 있는 사이트를 평가에서 제외하며, 자동 입력이 기존 값 위에서도 기대대로 작동하는지 확인할 수 없다.
2. 값의 출처가 기본값으로 증명된 경우만 덮어쓴다.
   - 사용자 입력 보호에는 유리하지만 외부 사이트마다 값의 출처를 신뢰성 있게 증명할 근거가 없고, 사이트별 추론 로직이 필요하다.
3. 비민감 매핑 대상의 기존 값을 출처와 무관하게 덮어쓴다.
   - 가입 기본값을 포함한 초기 상태에서 일관된 자동 입력 평가가 가능하다. 사용자 입력까지 바뀔 수 있으므로 평가 전 명시적 실행 승인, 민감정보 제외, 제출 관련 동작 금지와 DOM 재검증이 필요하다.

## 결정

저장소 소유 `cf-live-autofill-evaluation` 스킬이 Computer Use를 통해 외부 Chrome을 조작한다. 사용자의 `평가 시작해줘` 요청은 현재 실행의 비민감 필드와 기존 값 충돌 항목 쓰기에 대한 승인으로 해석한다.

스킬을 실행하는 `evaluation-agent`는 확장 프로그램 UI를 열기 전에 페이지 전체 필드를 독립적으로 판정한다. 이 에이전트는 제품이 API로 호출하는 AI가 아니며 제품 AI 결과를 정답 기준으로 사용하지 않는다. 전체 필드를 `AUTOFILLABLE`, `CONDITIONAL`, `PROFILE_VALUE_MISSING`, `FORBIDDEN`, `CREATED_AFTER_ACTION`으로 분류하고 `AUTOFILLABLE` 수를 실행 전 분모로 동결한다.

기존 값의 출처는 판별하지 않는다. 기존 값이 있는 비민감 매핑 대상은 중단 또는 새로고침 없이 최종 `기입하기`에 포함한다. 민감 필드와 제출 관련 동작은 승인 범위에서 제외한다.

Console은 현장 진단에 사용하되 값, 요청과 응답 원문, 스크린샷을 외부 산출물에 남기지 않는다. 최종 판정은 실행 뒤 실제 DOM으로 한다.

매핑 정확도는 확장 프로그램 제안 수, 매핑 재현율과 정답 입력률은 동결된 `AUTOFILLABLE` 수를 분모로 계산한다. DOM 검증 뒤 공개 안정 `site_id`와 비식별 지표를 raw 보고서와 topic Wiki에 기록해야 평가를 완료할 수 있다.

## 결과

팀원이 가입 기본값이 있는 사이트도 같은 문장으로 평가를 시작하고 공통 지표와 메타데이터를 받을 수 있다. 이 결정은 기존 사용자 입력도 덮어쓸 수 있으므로 실제 제출로 이어지지 않는 평가 탭에서만 적용하며, 대상 탭과 현재 실행을 넘어 일반 제품 정책으로 확대하지 않는다.

평가 에이전트 사전 판정은 사람이 확정한 정답이 아니므로 보고서에 판정 주체와 사람 검토 여부를 표시한다. 결정적 브라우저 러너와 장기 추세 대시보드는 필요가 확인될 때 별도 Project draft로 다룬다.
