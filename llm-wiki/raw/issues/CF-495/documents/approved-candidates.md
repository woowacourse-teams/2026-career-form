# CF-495 승인 후보 스냅샷

> Issue: [CF-495](https://github.com/woowacourse-teams/2026-career-form/issues/495)
> Collected: 2026-11-19
> Approval-Digest: 379063a6beb66961283ff31cac975e0227ea6339d456b0f1ec4a092a51955db4

worktree 체크포인트에 기록한 후보 네 개의 원문이다. 사람이 2026-11-19 "llm wiki 앞으로 잘 동작하는지 확인하고, 사람 승인 안받아도 되니 너가 알아서 기입해"라고 말해 에이전트가 자동 승인했다.

1. 범용 검색 직접입력 진입 조건(#495): 검색 결과 0건이 0건 안내 문구로 확인되든 직접입력 신호로 확인되든, 프로필 값을 카탈로그에서 골랐는지와 상관없이 레이어의 유일한 직접입력 경로로 원문을 기입하고 확인한다. #488은 0건 안내 문구가 없는 레이어에서만 직접 쓴 값을 허용했다. 마지막 시도, 직접입력 버튼 1개, 새로 보이는 입력칸 1개, 확인 버튼 1개, 결과 1건 이상이면 사용 안 함, legacy 경로 제외는 그대로다. 버튼을 눌러도 입력칸이 생기지 않으면 unverified_search_form으로 기입하지 않고 레이어가 열린 채 남는다.
2. 범용 검색 직접입력 확인 단계(#495): 직접입력 값에는 사이트 코드가 없으므로 행의 숨은 코드 칸을 묶거나 요구하지 않고(여러 개여도, 비어 있어도 실패 아님), 같은 행의 숨은 input 변화는 사이트 처리로 보아 불변 검사에서 뺀다. 대상 칸 값이 프로필 원문과 같은지, 보이는 다른 칸과 행 밖 칸이 바뀌지 않았는지는 그대로 확인한다. 후속 칸 대기도 처음부터 준비되지 않은(숨은) select를 기다리지 않고 실제로 바뀐 칸만 준비될 때까지 기다린다.
3. 실측(#495, 2026-11-19, 진단 빌드, 합성 프로필, 범용 경로 지원서 1곳): 수정 전에는 직접 쓴 값의 0건 검색 5건이 모두 레이어를 닫고 끝났다. 진입 조건만 푼 1차 빌드는 숨은 코드 칸 요구(행의 숨은 칸 11개, 직접입력 뒤 빈 코드)와 숨은 select 후속 대기로 실패했고 뒤 항목 기입이 줄었다. 최종 빌드에서 5건 모두 직접입력으로 끝났고 기입 칸이 47개에서 52개로 늘었다. 교훈: 직접입력 경로는 진입 조건, 결과 코드 검증, 후속 칸 대기 세 단계를 모두 실측으로 확인한다.
4. 범용 검색 횟수 상한(#495, commit b42bc95): 범용(행 범위) 경로는 한 번의 기입 실행에서 빈 칸 검색 상한 8회를 실패한 검색(written도 unchanged도 아닌 결과)에만 쓴다. 성공한 검색은 상한에 넣지 않아, 검색 칸이 많은 지원서에서 앞선 성공 때문에 뒤 칸이 'UNSUPPORTED_CONTROL 검색 실행 횟수 상한에 도달해 중단했습니다'로 건너뛰어지지 않는다. 정적 경로 상한 4회는 모든 검색을 그대로 센다. 이 건너뜀 사유에는 failureCode가 없어 패널에는 기본 문구만 보인다. 실측: 검색 칸 13개 지원서에서 2~6번 자격증명이 상한으로 건너뛰던 것이 5칸 기입(1칸은 마지막 시도 결과 2건 중 정확 일치 없음으로 확인 필요), 기입 52→57칸.
