# 정적 정책 우선 범용 분석·검색 표면 실행과 공급자 교체의 분리

## 상태

제안됨

## 날짜

2026-09-22

## 관련 Issue

#98, #93, #94

## 배경

기존 LLM 경로의 의미 매핑과 실제 입력 범위를 함께 개선해야 한다. 필드를 올바르게 분류해도 반복 행 선택·조건부 제어·입력 후 값 유지가 해결되는 것은 아니다. Greeting 정적 정책과 기존 회사 어댑터의 실패 경계를 유지하면서 실제 사용 가능한 범용 흐름을 우선 완성해야 한다.

## 검토한 대안

- 기존 OpenAI와 iframe 특수 분기만 유지: 변경 폭은 작지만 dialog/listbox 일반화와 공급자 교체 요구를 충족하지 못한다.
- 공급자나 회사별 실행기를 따로 구현: 중복 안전 정책과 서로 다른 성공 기준이 생긴다.
- 공통 검색 표면·로컬 실행 계약을 먼저 만들고 같은 Issue에서 OpenAI/Jev adapter를 연결: DOM 동작과 공급자 품질을 각각 검증하면서 교체 가능성을 확보한다.
- 전용/정적 지원을 모두 모델로 대체: 검증된 정책과 실패 우회 금지 경계를 훼손하므로 채택하지 않는다.

## 결정

1. 정적 정책 유효 시 정적 매핑, 명시적 미등록 시에만 선택된 OpenAI/Jev 범용 분석을 사용한다. 정적 정책 오류와 미지원 필드를 범용으로 우회하지 않는다.
2. 기존 LLM의 비식별 입력 문맥과 허용된 매핑·준비 분석을 보강한다. 서버가 candidate/allowlist/출력 계약을 검증하고 명령·입력 정책을 결정한다.
3. FE가 로컬 프로필 결합, 반복 행 유일성, 현재 승인/충돌/민감정보 보호, 쓰기 전 DOM 검증과 입력 후 확인을 소유한다.
4. 모델 요청에 실제 값·원문 HTML·세션/URL 상세·실행 selector를 넣지 않는다. 정적 Greeting 실제 입력 결과와 미등록 로컬 양식의 범용 결과를 분리한다.
5. SearchSurface로 dialog/iframe/listbox의 관찰을 통합하고 query generation·exact unique·반영/종료/유지와 단계당 1회 조작을 검증한다. 불확실한 실행 뒤 전체 run을 중단한다.
6. 세 application port 뒤에서 OpenAI/Jev를 단일 설정으로 교체한다. 기존 enable 설정의 호환성을 유지하고 구·신 충돌이나 공급자 장애를 묵시 fallback으로 숨기지 않는다.
7. Jev의 typed question·NoMatch/ABSTAINED·ID 대응·보관 정책과 실제 확장 사용을 같은 Issue에서 검증한다. 환경이 없으면 독립 작업은 진행할 수 있지만 해당 공급자의 인수 조건은 미완료로 남긴다.

## 결과

공통 실행 안전 경계 안에서 세 검색 표면과 OpenAI/Jev 공급자 교체를 제공한다. 공급자별 의미 분류와 실제 DOM 기입 결과를 분리해 검증한다. 회사별 특수 검색이나 모든 사이트 호환성을 보장하지 않으며 정적 페이지의 결과를 범용 성능 증거로 사용하지 않는다. Jev 구현·설정·실호출 검증까지 완료 조건에 포함하되 대규모 벤치마크나 성능 우월성 보장은 포함하지 않는다.
