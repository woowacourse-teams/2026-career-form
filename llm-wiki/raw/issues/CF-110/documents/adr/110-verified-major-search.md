# 검증된 검색 실행 계약으로 제한하는 CJ 대학교 주전공 검색

## 상태

채택됨. CF-110의 제한된 구현 경계이며 범용 POST 지원 확대 결정은 아니다.

## 날짜

2026-09-25

## 관련 Issue와 근거

[Issue #110](https://github.com/woowacourse-teams/2026-career-form/issues/110), 구현 `ee39197`, 검증 경계 문서 `1b222f2`.

## 배경

범용 검색 경로는 POST, hidden 문맥과 inline handler를 안전성 근거 없이 허용하지 않는다. CJ 전공 팝업의 검색과 선택을 위해 해당 기본 거부 정책을 풀기보다, 사전 확인된 대상과 검색·응답·팝업 효과만 허용하는 별도 경계가 필요하다. 이전 범용 검색 계약과 CF-108의 실패 진단 및 후속 보류는 `llm-wiki/raw/issues/CF-108/documents/generic-autofill-search.md`대로 유지한다.

## 검토한 대안

1. 버튼 라벨만 수정하고 전공 입력을 계속 보류한다. 안전하지만 이번 전공 검색 목표를 달성하지 못한다.
2. 같은 출처 POST와 inline handler를 범용적으로 허용한다. 검색 외 효과를 제한할 근거가 없어 채택하지 않는다.
3. 확인된 CJ 대학교 첫 행 주전공에만 별도 검색·선택·닫기 계약을 둔다. 구조를 검증할 수 없으면 자동 입력하지 않는다.

## 승인된 결정: 정확히 세 후보

1. CJ 대학교 첫 행 주전공만 정확한 origin·opener·행·필드 소유권 계약으로 허용한다. 검색 POST는 확장이 구성한 dtl_nm·num 두 필드만 전송하고, 일반 POST·hidden·inline handler 거부 정책은 유지한다.
2. 전공 결과의 callback은 실행하지 않고 literal 데이터로만 해석한다. 완전히 수신하고 구조를 검증한 렌더링 응답 안의 유일한 정확 일치만 허용하며, 표시값·코드·검토된 needPopup 닫기 lease·500ms 이상 유지가 모두 확인되어야 검색 실행 성공으로 인정한다. CJ 데이터베이스 전체 유일성이나 전체 패널 성공을 뜻하지 않는다.
3. 버튼형 input의 value만 의미 라벨로 사용하고 일반 text·password·hidden 입력값은 제외한다. 소유권·문맥·응답·팝업 변경, 값 충돌과 취소는 fail-closed로 처리하며, 실패 후 후속 검색 보류와 기존 사용자 값 보호를 유지한다.

## 결과와 검증 한계

CJ 전공에 한정된 실행 경로를 얻되 다른 사이트, 다른 학교 필드, 추가 전공 및 대학원에 일반화하지 않는다. 응답 내 유일성과 선택 후 유지가 입증되지 않으면 성공으로 표시하지 않으며, 일반 검색의 기본 거부와 CF-108 진단은 계속 적용한다.

`1b222f2`에 기록된 별도 합성 입력 대상과 공개 검색을 연결한 브라우저 실행 두 번은 표시값·코드, 팝업 닫힘과 각각 550ms, 536ms 유지를 확인했다. 이후 설치 확장의 실제 화면에서는 주전공 표시값·공개 결과 코드 일치, 닫힘과 578ms 유지 구간을 읽기 전용으로 관측했다. 다만 결과 UI는 해당 항목을 `입력 결과 확인`으로 분류하고 입력 완료를 0개로 표시했다. 기존 `LLM_SUGGESTED` 쓰기는 보수적으로 확인 필요로 남는다. 이 실행의 내부 매핑 상태나 실행기 반환값은 직접 수집하지 않았으므로 전체 패널 성공으로 해석하지 않는다. 실제 화면에서 다른 날짜 항목도 입력되어 전공만 실행했거나 다른 값 전체가 불변이었다고 주장하지 않는다. 서버 저장·제출 및 CJ 데이터베이스 전체 유일성도 검증하지 않았다.
