# 실사이트 QA 하네스의 테스트 계정 모드, 설치본 잠금, 채점 재사용과 합계 재계산

> Issue: CF-333
> Collected: 2026-10-24
> Approval-Digest: e3220900fa34d5fd1ee3718f11713ef2c78fa8bbdb93741c0fa6e1be570f8e41
> Source-Revision: fe786252f656a3e551a55bfa1825032e2366a086

이 문서는 2026-10-24 테스트 전용 모드 전환에서 승인된 CF-333 후보 2·3·6·7을 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 평가 계약 1.1의 분모·판정 규칙은 바꾸지 않으며, 바꾸지 않은 내용은 Supersedes가 가리키는 CF-310 재설치·응답 없는 탭 근거를 따른다. 실제 지원값·계정·세션·URL 쿼리·대화 전문은 포함하지 않는다.

## 승인 후보

- 평가 브라우저와 확장 설치본은 같은 기기의 모든 세션이 공유하므로 다른 세션의 재설치가 진행 중인 측정을 무효화할 수 있다. 측정의 유효성은 `run.json`의 `build.revision`으로 검증하고, CF-333부터는 설치본 잠금이 다른 세션의 재설치를 거부한다.
- 새 서버 정책 검증은 dev가 아니라 새 볼륨의 로컬 스택으로 한다. seeder는 기존 DB의 활성 버전을 바꾸지 않기 때문이다.
- 하네스는 테스트 계정 모드에서만 값 기록·임시저장(`reset`)·섹션 캡처·임시저장 본문 기록을 하며, 테스트 계정 여부는 사람이 allowlist 파일에 적은 호스트로 판정한다. 2026-10-23 실험에서 5페이지의 확인 불가가 68칸에서 12칸으로, 정답이 229/274에서 285/330으로 바뀌었다.
- 사전 채점은 구조 해시가 같으면 이전 채점을 재사용하고, 판정 합계는 모델 숫자가 아니라 항목과 joined 행에서 재계산한다.

## 근거

### 설치본 공유와 잠금

- 2026-10-22 측정이 끝난 직후 다른 세션이 같은 설치본 디렉터리에 다른 빌드를 설치했다. 31개 실행 기록의 revision이 모두 같아 측정 자체는 유효했지만, 그 뒤 재실행은 설치본을 되돌린 뒤에야 가능했다. 유효성 판정의 근거는 실행마다 `run.json`에 남는 서비스 워커 보고 revision이다.
- CF-333의 `start`는 설치 시 상태 디렉터리의 `extension.lock.json`에 설치한 세션의 프로세스 계보(pid, 부모, 조부모)와 revision·API 호스트를 적는다. CLI 프로세스는 명령이 끝나면 바로 죽으므로 pid 하나로는 잠금이 늘 무시된다. 조부모(터미널·에이전트 프로세스)까지 계보로 비교해, 그 중 하나가 살아 있고 현재 계보와 겹치지 않으면 다른 세션으로 보고 `install-locked`로 거부한다. `--force`만 이를 넘는다.
- revision이 같아도 빌드 manifest의 `host_permissions`(API 호스트)가 다르면 재설치해야 한다. `start`는 둘을 비교해 재설치 사유 `api-hosts`를 출력한다.

### 새 정책 검증 환경

- 정책 활성 버전은 서버 DB의 회사 문서 `activePolicyVersion`에 있고, 기동 seeder는 빈 DB만 채우며 기존 DB의 활성 버전은 바꾸지 않는다. 그래서 develop에 새 정책 버전이 들어가 dev에 배포돼도 dev API는 옛 버전을 준다. 2026-10-22 SK v38·Greeting v18 검증은 새 볼륨으로 올린 로컬 스택(seeder가 빈 DB를 채움)에서 했고, dev에서는 사람이 DB의 활성 버전을 바꾼 2026-10-24 뒤에야 같은 결과가 나왔다.

### 테스트 계정 모드

- 하네스는 확장을 시험하는 도구이지 지원서를 쓰는 도구가 아니다. 테스트 계정 탭(사람이 상태 디렉터리의 allowlist 파일에 호스트를 적은 탭)에서만 값 은닉 규칙과 저장 금지를 일부 푼다. 실행 전·후 값을 기록하되 계정 신원 칸만 가리고, `reset`은 화면을 비운 뒤 사이트 자체의 임시저장 버튼으로 빈 양식을 저장한 다음 서버에서 다시 열어 남은 값을 보고한다. 가드·요청 차단·확인창 수락의 완화는 `reset` 안에서만이며 제출·동의·본인 인증·파일은 테스트 계정에서도 막는다.
- 2026-10-23 실험(ABL 1–3단계, SK R262303, 카카오게임즈): 확인 불가 68칸 → 12칸, 정답 229/274(83.6%) → 285/330(86.4%), 오입력 0. 남은 12칸은 사이트 기본값 7칸과 어학·자격 코드 칸 5칸이었다. CF-333은 그래서 사이트 기본값(`siteDefault`)을 저장값과 구분하고 코드 칸의 숨은 이름 칸을 함께 수집한다.
- 섹션 캡처와 차단된 임시저장 요청 본문은 테스트 계정 탭에서만 남긴다. 캡처에는 계정 신원 칸이 보일 수 있어 그 밖의 탭에서는 찍지 않는다.

### 채점 재사용과 합계 재계산

- 2026-10-22 측정에서 사전 채점 93개 에이전트(약 710만 토큰)와 판정·반박 57개(약 590만 토큰)가 회차마다 반복됐고, 채점자가 바뀌면 분모도 바뀌었다(SK R262303 90→101칸). 구조 해시(값 없는 census의 controls에서 칸 번호를 뺀 것과 추가 버튼 문구의 canonical JSON SHA-256)가 같으면 이전 `final.json`을 재사용하며, 주소·label을 넣지 않아 같은 양식의 다른 공고도 재사용된다.
- 같은 측정에서 판정 2건의 합계 숫자가 자기 항목과 어긋나 손으로 고쳤다. CF-333의 보고서는 판정 파일의 숫자 필드를 믿지 않고 항목(kind별 개수)과 joined 행(AUTOFILLABLE 수)에서 다시 센다. 모델 숫자와 다르면 `verdict-mismatch`로 표시한다.

## 쓰임

- 긴 측정을 시작하기 전에 `lock`으로 설치본 잠금을 자기 세션 것으로 두고, 보고서의 revision이 실행마다 같은지 확인한다.
- 새 정책 버전을 검증할 때는 새 볼륨 로컬 스택을 쓰거나 dev DB의 활성 버전을 사람이 바꾼 뒤 API 응답으로 확인한다.
- 측정 전 `scope`로 범위를 사람이 정하고, 테스트 계정 탭은 `saved → reset --yes → saved`로 저장값을 비운 뒤 잰다. 확인 불가 비율을 측정 품질 지표로 본다.
