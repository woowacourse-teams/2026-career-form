# CF-312 approved candidates

1. Hidden same-row controls of another education stage must not block the row. The generic structure loop stage check (frontend/src/autofill/generic/structure-loop.ts, runGenericStructureLoop) collects MATCH profile keys only from row candidates whose registry handle is visible, so a hidden university-branch control mapped to an education.university.* key no longer turns a visible high-school row into STAGE_KEY_MISMATCH.
2. Visibility of a grouped candidate must be evaluated over ALL native controls the candidate owns (isFieldCandidateHidden in frontend/src/autofill/dom/collect.ts: hidden only when every owned element is hidden; custom elements are used only when there are no native elements). A narrower judgement was a fail-open found in review: a mixed-visibility candidate escaped the stage conflict check and the row was no longer blocked. The check reuses the collector's own hidden predicate instead of a second copy.
3. Grading siblings in repeat-row sections must exclude hidden candidates too (frontend/src/autofill/generic/generic-analysis.ts convertSection, visibleRowMatches); otherwise a hidden other-stage match still affects the visible fields' grades. Non-row grade evidence such as a hidden English family-name control stays available to name grading.
