# 현대 검색 결과 창의 바깥 클릭 핸들러와 학교명 소실, 결과 패널 판정, 카탈로그 신원 없는 검색

> Issue: CF-336

이 문서는 2026-10-25 CF-336(현대 학교명 검색 미확정)에서 승인된 후보 1·2·3을 현대 어댑터 관점에서 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 바꾸지 않은 내용(버튼형 선택지 코드 수집, trigger 식별, 정책 v25, 작성 화면 재진입 불가, Map·Set 재정의)은 Supersedes가 가리키는 CF-335 근거와 그 앞의 근거를 따른다. 실제 지원값·계정·세션은 포함하지 않는다.

## 승인 후보

1. 바깥 클릭 핸들러가 보이는 결과 창 전부의 표시값을 첫 창 기준으로 지운다. 확장은 선택 없는 검색의 창을 닫고 선택 뒤 창이 사라질 때까지 기다린다.
2. 결과 패널은 검색형 칸을 실행 뒤 DOM 값 기준으로 "확인 필요"에 올린다("입력 결과를 확인하지 못했어요"는 기입 확인 뒤 값이 사라진 경우). CF-333의 "입력 완료로 셌다" 관측 정정.
3. 카탈로그 신원이 없는 프로필의 학교 검색은 이름만 비교해 동명 학교가 여러 지역이면 "여러 개"로 남긴다.

## 관측 (2026-10-24, 실사이트 QA `qa-20261024-cf335/hy-mobility-2`와 읽기 전용 관찰 타임라인)

- 학력 4행(고등학교·학사·전문대학·석사)에서 학사·석사의 학교명은 hidden `schCd`에 코드가 들어갔으나 표시값이 비고 확정 표시(`exist`)가 없었다. 전문대학은 표시값·코드·확정 표시가 모두 정상이었다. 2026-10-21·22의 세 공고도 같은 분포였다(학사·석사 빈 값, 전문대학 정상).
- 0.2초 간격 관찰: 고등학교 검색이 결과 여러 개로 선택 없이 끝나 결과 창이 열린 채 남고, 그로부터 0.6초 안에 학사·석사의 결과가 클릭되어 코드가 들어갔으며 그 시점에 이미 표시값이 비어 있었다. 전문대학은 3초 뒤 다른 창이 모두 닫힌 상태에서 처리됐다.
- 결과 패널(`panel.pending`)은 세 칸을 모두 "확인 필요"에 올렸다. 고등학교는 `SEARCH_AMBIGUOUS`("일치하는 검색 결과가 여러 개예요"), 학사·석사는 사유 "입력 결과 확인"("입력 결과를 확인하지 못했어요", `written: true`). 후자는 `result-model.ts`가 기입 기록은 있으나 결과 시점의 DOM 값이 어긋날 때 붙인다. CF-333 근거의 "결과 패널은 그 3칸을 입력 완료로 셌다"는 틀렸다.

## 원인: 사이트 `apply.js`의 "검색 필드 - 포커스 아웃 시" 핸들러

- `$(document).on("click", "body", ...)`가 `.field.search` 밖의 클릭마다 `$(".field-search-view:visible")`로 보이는 결과 창 전부를 한 jQuery 집합으로 잡는다. 집합의 첫 요소 기준으로 `$field.find("input:hidden").val()`을 검사해, 비어 있으면 `$field.removeClass("exist"); $target.val("")`로 집합 전체 칸의 표시값을 지운다. hidden은 건드리지 않는다. 값이 있으면 첫 요소의 `data-search-result`를 집합 전체 표시값에 쓴다.
- 결과 클릭 핸들러는 `$(".field-search-view").slideUp()`으로 모든 창을 애니메이션으로 접는데, 접히는 동안은 `:visible`이다. 그래서 선택 없이 창을 남긴 행(고등학교)이 앞에 있고 그 직후 선택된 행(학사·석사)의 창이 아직 접히는 중이면, 확장의 다음 클릭(같은 행의 주야간 등 버튼형 선택)에서 선택된 행의 표시값까지 지워진다.
- 사이트는 못 고치므로 확장이 보이는 창을 남기지 않는다(CF-336, `policy/hidden-code/coded-search.ts`). 선택 없이 끝난 검색(여러 개·정확 일치 없음·시간 초과·확인 실패)은 검색어를 되돌린 뒤 기존 `searchNotify` 계획(input+keyup)을 빈 값으로 보내 사이트의 입력 핸들러 else 분기가 hidden·`data-search-result`를 비우고 창을 닫고 목록을 비우게 한다. 검색 전부터 hidden·선택 표시가 비어 있던 칸에서만 보낸다. 선택이 확정된 검색은 `.field-search-view`가 모두 jQuery `:visible` 기준으로 사라질 때까지(상한 1.5초) 기다린 뒤 성공을 돌려준다. 계약 JSON·정책 버전은 바꾸지 않았다.

## 카탈로그 신원이 없는 학교 검색

- `result-match.ts`의 매칭은 approval이 `selected`(프로필 항목에 검증된 카탈로그 신원이 있음)일 때 이름과 지역(`regionDetailIndexes`, 치환 규칙)을 함께 비교하고 같은 이름·지역의 카탈로그 항목이 하나일 때만 받는다. approval이 `legacy`(신원 없음)이면 이름만 비교한다.
- 2026-10-24 프로브: 결과 라벨 '대진고 - 서울노원', '대진고 - 대구달서', '대진고 - 강원고성', '분당대진고 - 경기성남', '일산대진고 - 경기고양'에 대해 `selected`(서울 노원 항목)는 서울노원만 참, `legacy`는 대진고 셋이 모두 참이어서 `SEARCH_AMBIGUOUS`가 된다. 하네스 합성 프로필은 신원이 없어 고교 학교명이 "여러 개"로 남는 것이 정상이며, 신원이 있는 실제 프로필에서는 하나로 좁혀진다. 이 동작은 바꾸지 않았다.
