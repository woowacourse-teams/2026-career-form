# 합성 프로필 측정에서 고교 학교명이 확인 필요로 남는 이유와 reset의 버튼형 위젯 잔여

> Issue: CF-336
> Collected: 2026-10-25
> Approval-Digest: 8f1781e209bbaec70946dac4806881f408aad04f7710e76f7df5de24a586fdee
> Source-Revision: 0df5dc2b8c2887a401ef1551c55a6af835f8cae4

이 문서는 2026-10-25 CF-336에서 승인된 후보 3·4를 실사이트 평가 관점에서 수집한 기록이다. Approval-Digest는 [승인 후보 스냅샷](approved-candidates.md) 전체 UTF-8 바이트의 SHA-256이다. 바꾸지 않은 내용(테스트 계정 모드, 설치본 잠금, 채점 재사용, 합계 재계산)은 Supersedes가 가리키는 CF-333 근거를 따른다. 실제 지원값·계정·세션은 포함하지 않는다.

## 승인 후보

- 카탈로그 신원이 없는 합성 프로필의 학교 검색은 이름만 비교해 동명 학교가 여러 지역이면 "여러 개"로 남는다. 합성 프로필 측정에서 고교 학교명의 확인 필요는 정상이다.
- 테스트 계정 `reset`은 버튼형 위젯을 비우지 못하고, 그 잔여는 현대 학력 준비를 멈춘다.

## 근거

- 합성 프로필(`cf-workflow/live-eval/profile-export.synthetic-full.json`)의 학교 항목은 검증된 카탈로그 신원이 없어 확장의 검색 approval이 `legacy`다. 현대처럼 결과 라벨에 지역이 붙는 사이트에서도 이름만 비교하므로 '대진고' 같은 동명 학교(서울·대구·강원)는 `SEARCH_AMBIGUOUS`로 남고 결과 패널에 "일치하는 검색 결과가 여러 개예요"로 올라온다. 판정에서는 이 칸을 오입력이 아니라 합성 프로필의 한계로 다룬다. 전문대학·대학·대학원처럼 동명이 없는 학교는 영향이 없다.
- 2026-10-24 현대 모빌리티 공고 탭에서 `reset`은 텍스트 64칸을 지우고 빈 양식을 임시저장했지만 버튼형 위젯(학력선택·졸업여부·주야간·고용형태)과 그에 딸린 hidden 값은 그대로 남았다(`saved`·`reset` 보고의 `widgetsLeft`). 그 상태로 `run`을 돌리면 확장이 학력 행을 기존 항목으로 보호해 "학력 종류와 입력 행을 안전하게 준비하지 못했습니다"로 멈추고 기입이 0이다. 사람이 사이트에서 학력 행을 지우고 나면(빈 행 2개, 학력선택 미선택) 정상 실행됐다. 확장이 추가한 행과 선택은 `discard` 뒤에도 남으므로, 같은 탭을 다시 측정할 때도 같은 정리가 필요하다.
- 실행 중 DOM 상태를 시간순으로 기록하는 읽기 전용 관찰(CDP로 붙어 0.2초마다 학교명 표시값·hidden 코드·exist·결과 목록 가시성만 읽음)은 하네스 `run`과 같은 세션에서 돌릴 수 있고, 하네스 기록만으로 좁히지 못한 "확정 뒤 소실"의 시점을 잡았다. 클릭·입력은 하지 않는다.
