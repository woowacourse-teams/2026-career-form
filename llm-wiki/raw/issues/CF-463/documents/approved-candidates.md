# CF-463 승인 후보 스냅샷

> Issue: [CF-463](https://github.com/woowacourse-teams/2026-career-form/issues/463)
> Collected: 2026-11-16
> Approval-Digest: 1de0e43eadcffe548c06a76dbea8f80ce34e8e357c2b5bef50ffde3399ff8d68

worktree 체크포인트에 기록한 후보 여섯 개의 원문이다. 사람이 2026-11-16 "승인"으로 확정했다.

1. 공고 저장 경로(정정): 공고는 알림의 '마감 알림 저장'과 관리 페이지 공지함(새 공고 탭)의 '저장' 버튼으로만 CF-161 공고로 저장한다. 알림 본문·'공고 열기'·새 공고 탭의 열기 링크로 공고를 열어도 저장하지 않고, 저장 확인 알림에는 버튼이 없다. 열기 자동 저장 설정(`careerForm.push.autoSave`, 기본 켜짐)과 후속 알림의 '저장 취소', 카드의 '취소'는 2026-11-03 PR #387에서 없어졌고, 이전 설치에 남은 설정 값은 읽지 않는다. 열기 자동 저장은 운영 확장(1.4.0~1.6.0)에 실린 적이 없다.
2. 확장 화면 위치(정정): 사이드 패널의 '공고 관리' 버튼에 미확인 공고 숫자가 보인다. 공지함(새 공고 탭)은 걸러진 진행 중 공고를 모두 마감순 표로 보이고 3건 펼치기는 없다. 알림 켜기·끄기는 관리 페이지 머리글의 '새 공고 알림' 스위치, 알림 테스트·표시 확인·받을 직무는 머리글 '알림 설정' 대화상자에 있다. onboarding.html은 상태 조회·켜기·끄기·테스트·결과 기록·분류 조회·직무 저장을 보낼 수 있다. 새 공고·저장 공고 표는 직무가 없으면 직무 칸을 비운다.
3. 계측(정정): 공고 저장 계측의 계기 `trigger` 값은 `button` 하나이고 `posting_auto_save_cancelled` 이벤트는 없다. 둘 다 #387에서 열기 자동 저장과 함께 빠졌다.
4. 저장 공고 정리 보완과 안내 결정: 마감 지난 지원 예정 공고 정리는 알림의 '마감 알림 저장'이 저장 직전에 부르는 목록 조회에서도 일어난다. 자동 삭제를 알리는 사용자 안내 문구는 2026-11-16 사용자 결정으로 두지 않는다.
5. 남은 불일치: 공개 기술 소개의 '구독으로 서버에 남는 것은 푸시 주소, 암호화 키 두 개, 등록 시각뿐' 문장은 서버가 구독마다 저장하는 받을 직무 코드(`roles`)와 그 갱신 시각(`rolesUpdatedAt`)을 빠뜨린다. 개인정보 고지 성격이라 2026-11-16 사용자 결정으로 CF-463에서 고치지 않았다.
6. 변경 이유: 확장 화면 개편 PR #387(2026-11-03)은 본문에 '사용자 결정으로 … 새 공고 저장 폼, 공고 수정, 자동 저장을 없앴습니다. 새 공고 탭에서 공고를 고릅니다'라고 적고 코드와 README 일부만 고쳤다. 사이트 기술 소개·랜딩·체험, 온보딩 알림 안내, README 공고 알림 절과 topic Wiki가 예전 동작을 말하고 있어 CF-463에서 바로잡았다.
