# 공고별 사람 확인 기록과 실행 관측의 분리

> Issue: [CF-195](https://github.com/woowacourse-teams/2026-career-form/issues/195)
> Decision-Date: 2026-10-12
> Status: Accepted

맥락: 화면 상태를 포함한 구조 해시로 확인 작업을 식별하면 같은 공고를 반복 확인해야 하며 사람이 해시 차이를 해석할 수 없다.

결정: 환경과 검증된 공개 공고 URL별 확인 기록을 별도로 두고 구조별 관측은 이력으로 보존한다. 조건부 항목을 펼치고 반복 항목을 각 1행 둔 기준으로 전체 필드 수를 확인한다. 사람의 명시적 재확인 외에는 화면 상태 변화로 공고 확인을 다시 대기시키지 않는다. 공고 확인 완료와 개별 실행의 분모 적용 가능성은 분리한다. 분모 적용 범위를 증명할 수 없는 실행은 적용을 보류한다.

대안: UI만 접으면 중복 확인 상태가 남는다. 구조 후보를 DB에서 합치면 관측과 확인 이력을 손상할 수 있다. 기존 확인값을 모든 상태에 복사하면 분모 범위가 잘못 적용된다.

결과: 사람의 작업 단위는 공고로 단순화되며 기존 관측을 보존한다. 이전 확인의 기준이 불명확하거나 값이 충돌하면 한 번의 공고 재확인이 필요하다. 정확한 URL이 없는 과거 후보는 임의로 공고를 추정하지 않는다.

## 승인된 구현 기준

공고 확인 기록은 환경과 검증된 공개 작성 URL별 하나로 관리하고 정책 회사 경계를 유지한다. 구조별 관측은 별도 이력으로 보존한다. 화면 상태 변화로 완료를 되돌리지 않으며 명시적 재확인만 허용한다.

전체 입력 가능 칸 수는 조건부 항목을 펼치고 반복 항목을 각 1행 둔 기준으로 확인한다. 실행별 검증된 공고 식별, snapshot의 칸 수 및 표시 상태와 반복 행 증거가 모두 기준에 맞을 때만 분모를 적용한다. 링크나 증거가 없거나 다른 공고 및 범위가 섞이면 적용을 보류하며 기존 고유 칸 중복 제거를 유지한다.

구형 확인 기록에는 반복 행 기준이 저장되어 있지 않아 숫자를 자동 승계하지 않는다. 과거 숫자와 구조 이력은 접힌 읽기 전용 이력으로 보존하고 공고별 재확인 하나를 제공한다. 정확한 링크가 없는 후보는 별도 과거 목록과 기존 API로 유지한다. 확인일과 팀 별칭을 기록하고 신구 화면의 담당자 보호를 적용한다.

Discord는 공고 확인 기록으로 연결하면서 사이트 중복 안내 제한과 하루 여력 5개를 유지한다. 연결된 과거 담당과 새 공고 담당만 중복 차감하지 않고 같은 사이트의 독립 공고 담당은 따로 차감한다. 공고 확인이 끝나면 연결된 과거 담당은 여력을 계속 차지하지 않는다. 과거 batch는 수정하거나 재발송하지 않는다.
