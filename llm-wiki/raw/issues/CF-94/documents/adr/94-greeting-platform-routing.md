# BE가 지정하는 Greeting 플랫폼 정책과 FE 입력 어댑터

> Status: Accepted
> Date: 2026-09-27
> Issue: [CF-94](https://github.com/woowacourse-teams/2026-career-form/issues/94)
> Approval-Digest: d36c93eae7d0daa585f8b33f6985c5edde7043a449cf12547daa9b0d6c5a4dbe

## 배경

기존 BE는 회사 host/path로 정적 정책과 범용 분석을 분기하고, FE는 SK·현대 host에 맞는 특수 입력 어댑터를 사용한다. Greeting은 기본 도메인과 기업 자체 도메인에서 공통 정책을 사용하므로 FE host 목록을 늘리면 공급업체 판정이 중복된다. 일반 FE 입력기만으로는 카카오모빌리티의 학교 검색·달력·버튼·반복 학력을 안전하게 실행할 수 없다.

## 검토한 대안

- 기업별 host 정책과 FE 분기를 복제하면 신규 자체 도메인마다 등록과 정책 중복이 생긴다.
- FE가 Greeting 구조나 footer로 공급업체를 판별하면 BE의 정적/범용 판정과 어긋날 수 있다.
- 일반 FE 입력기만 사용하면 기존 이름·전화 외의 카카오모빌리티 목표를 충족하지 못한다.
- BE가 연결과 정책을 확인해 FE 어댑터를 명시하고 새 구조를 검증하면 판정 책임을 한 곳에 유지할 수 있다.

## 결정

1. 기존 등록 회사 정책을 먼저 적용한다. 해당 정책 오류나 구조 불일치를 다른 정책 또는 LLM으로 우회하지 않는다.
2. BE는 정확한 Greeting 기본 도메인 경계 또는 지원서 형태의 공개 호스트에서 확인한 Greeting CNAME으로 연결을 판정한다. CNAME이 숨겨진 자체 도메인은 명시 등록으로 보완한다. 정상 조회에 양성 근거가 없으면 기존 범용 경로를 유지하되 비-Greeting으로 단정하지 않는다. DNS 오류와 이전 양성 판정의 충돌은 차단한다. 조회 시간·캐시·용량 제한을 유지한다.
3. 양성 판정 뒤 BE는 Greeting 공통 정책과 현재 양식 fingerprint를 확인한다. 정책 부재, 필수 구조 불일치와 모호한 필드를 범용 매처로 보내지 않는다.
4. BE는 capability를 협상한 클라이언트에 별도의 `greeting-v1` 실행 어댑터 식별자를 반환한다. FE는 이를 수집·준비·분석·입력 전 과정에 일관되게 사용하며, host·footer·불투명한 `routingContext`로부터 공급업체를 추정하지 않는다. 미지원 ID, 단계 불일치와 구형 클라이언트는 안전하게 중단한다.
5. 최초 일반 수집의 양성 판정 뒤 FE는 Greeting 어댑터로 구조와 registry를 다시 만든다. 준비 action이 있으면 실행 뒤 또 수집하고, fields에서 독립 fingerprint와 정적 매핑을 검증한다. 쓰기 직전 현재 DOM·행·기존 값을 다시 확인한다. 검증된 무준비 양식에만 빈 계획을 허용하며 전환 횟수를 제한한다.
6. 첫 양성 판정의 `routingContext`를 두 번째 준비 요청에도 전달하고, 갱신된 문맥을 fields까지 이어 간다. BE의 host/path 결합·10분 유효기간·발급 용량·이전 양성 유지 검증을 통과해야 한다. 만료·위변조·발급 불가·판정 충돌은 재분석 또는 차단으로 처리하고 조용히 범용으로 낮추지 않는다.
7. BE는 프로필 의미·정적 정책·준비 계획을, FE는 로컬 값 결합·검색/날짜/선택 실행과 최종 값 검증을 담당한다. 프로필 값, 현재 입력값과 세션 정보는 분석 API에 보내지 않는다. 기존 값 보호와 민감정보 개별 확인을 유지하고 검색어 입력이나 평점 단독 기입을 완료로 세지 않는다.
8. 카카오모빌리티에서 검증한 프로필 대응 항목을 구현하고 현대오토에버 공통 필드를 회귀 확인한다. 다른 Greeting 기업·양식의 무조건적 호환성, 운영 정책 배포, 데이터 마이그레이션, 지원서 저장·제출은 이 결정의 검증 범위가 아니다.

## 결과

Greeting 판정은 BE에 남고 FE는 BE가 선택한 어댑터로 특수 제어를 처리한다. 공통 정책을 재사용하되 DNS 별칭 은닉과 기업별 양식 차이를 명시적인 지원 경계로 둔다. 입력 성공은 자동 테스트와 설치 확장에서 확인한 필드별 최종 값·선택 상태로 구분해 기록한다.
