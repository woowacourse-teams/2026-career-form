# 릴리스 동기화 완료까지 원본 브랜치 유지

## 상태
승인됨

## 날짜
2026-10-03

## 관련 Issue
#155

## 배경
main 병합 후 자동 삭제가 배포 후 release → develop 동기화에 필요한 브랜치를 제거한다. 공용 릴리스 흐름에 지속적으로 적용되는 정책이므로 ADR로 남긴다.

## 검토한 대안
- 자동 삭제 유지 및 별도 sync 브랜치 생성: 기능 브랜치 정리는 편하지만 릴리스 추적용 브랜치가 추가된다.
- 원본 release 유지 및 동기화 완료 후 삭제: 기존 흐름과 완료 워크플로를 재사용하지만 저장소 전체 자동 삭제를 끄고 기능 브랜치를 직접 정리해야 한다.

## 결정
원본 release를 유지한다. 관리자가 저장소 자동 삭제를 끄고, develop 동기화 PR 병합 후 기존 완료 워크플로가 release를 정리한다. 미반영 커밋이 없으면 배포 성공과 develop 반영 완료를 확인한 뒤 PR 없이 release를 자동 삭제한다.

## 결과
삭제된 브랜치에 의존하는 PR 생성 실패를 예방한다. 일반 기능 브랜치의 수동 정리 비용이 생긴다. 과거에 삭제된 release는 별도 수동 복구 판단이 필요하다.

## 운영과 오류 처리

배포 후 미반영 release가 없으면 복구 안내로 실패한다. 이미 develop에 포함된 SHA라면 삭제 후 재실행도 정상 종료한다. 원격 접근·인증·fetch·push 오류를 브랜치 부재로 처리하지 않는다.

두 삭제 경로 모두 삭제 직전 원격 SHA를 확인하고 명시적 SHA lease와 삭제 refspec을 사용한다. 확인 후 추가된 커밋은 삭제하지 않는다. develop 반영은 커밋 조상 관계로 확인하며 release 동기화는 기존 Merge Commit 규약을 따른다.

관리자가 저장소의 Automatically delete head branches를 해제해야 main 병합 후 release가 유지된다. 일반 기능 브랜치도 자동 삭제되지 않으므로 PR 담당자가 정리한다. 실제 설정 변경, 운영 배포 및 수동 복구는 사람이 수행한다.
