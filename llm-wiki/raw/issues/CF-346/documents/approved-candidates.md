# CF-346 approved candidates (2026-10-25, [FE] Greeting 검색 칸에 정확한 목록 항목이 없을 때 직접 입력 선택지 미사용 문제 수정)

1. Greeting 검색 목록은 정확한 항목이 없으면 유사 이름 20개 뒤에 `직접 입력하기:“값”`(코드 `[[new]]`, 선택 뒤 `data-value`는 `[[new]]-값`)을 붙인다. 고교·대학·대학원 학교명, 전공명, 회사명, 자격증명이 같은 구조다. 시험명은 닫힌 목록이고 국적은 전체 250개를 먼저 그린 뒤 클라이언트 필터로 비우며, 둘 다 직접 입력 선택지가 없다. 직접 입력 허용은 정책 `componentPolicy.patterns.directSearch`가 정하고 v19부터 대학·대학원 학교명과 전공명이 들어간다. 카탈로그 신원이 확정된 학교는 계속 제외된다.
2. 검색 함수가 사유 없이 실패하면 기본 코드 `SEARCH_UNCONFIRMED`가 붙는다. CF-346부터 렌더된 목록에 고를 항목이 없으면 `SEARCH_NO_EXACT_MATCH`, 정확 항목이 여러 개면 `SEARCH_AMBIGUOUS`, 렌더된 목록이 필터로 비면 `SEARCH_NO_RESULTS`, 열린 목록에 항목이 끝내 없으면 `SEARCH_TIMEOUT`을 보고한다. 기본 코드는 팝업이 열리지 않은 경우에만 남는다.
3. 검색 종류별 "정확 일치 없음" 전수 조사 절차: 정확히 같은 항목이 없는 합성값 프로필을 `start --profile`로 심고, 읽기 전용 관찰기로 검색 칸의 목록(항목 수, 마지막 항목, `data-value`)을 기록해 종류별 직접 입력 제공 여부를 표로 확정한 뒤 기본 프로필을 다시 심는다. 새 정책 버전은 worktree별 compose 프로젝트의 새 볼륨 로컬 스택에서 `policy-versions`로 활성 버전을 확인하고 로컬 API 빌드로 검증한다. `localhost:8080` 빌드에 `VITE_LOCAL_WORKFLOW_DIAGNOSTICS=1`을 켜면 드라이버 단계 진단이 콘솔로 나오고, 디버그 표(`console.table`)는 관찰기가 JSON으로 받을 수 있다.
4. 마지막 기입 뒤 Greeting 페이지가 입력 노드를 다시 그려 재수집이 변경으로 판정되고, 재분석의 리뷰 계획이 현재값이 이미 프로필 값과 같은 칸도 `available`·선택 상태로 다시 승인해 같은 값을 다시 쓴다(회차당 3~5회, 구조 서명이 반복되면 멈춤). 상태 드라이버는 완료 키가 있어 다시 돌지 않는다. 범용 재분석·리뷰 계획 흐름의 별도 후보다.
5. 카카오게임즈 Greeting 양식의 기존 미해결 항목: 어학·자격 취득일 "선택값이 유지되지 않았어요" 5칸, 어학 등급/점수 선택지 불일치 1칸, 회화수준 2칸. 2026-10-24와 10-25 모두 같았고 검색 정확 일치와 무관하다. 동명 고교(세 지역)는 합성 프로필 한계로 v19 뒤 "여러 개"로 표시된다.
