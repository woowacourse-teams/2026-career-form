# PDF 조건 안내, 전송 안내 단계 제거, 실패 화면 통일

> Issue: [CF-480](https://github.com/woowacourse-teams/2026-career-form/issues/480)
> Collected: 2026-11-18
> Approval-Digest: b9ff638175d31eb6327967418852c23a9ebbcfaf808d26d479d77e6d4cab9f47
> Source-Revision: 7bdc957

[승인 후보 스냅샷](approved-candidates.md)의 후보 1·2를 적는다. 글자 추출, 서버 변환, 검토·병합의 나머지는 Supersedes가 가리키는 CF-470 근거를 따른다. 가져오기 출처가 이력서 파일 하나가 된 것은 CF-479 근거를 따른다.

## 결정 (사람 결정 2026-11-18, 시안 확인 뒤 진행)

- 진입 화면의 이력서 파일 줄에 "스캔 PDF 불가" 한 줄을 둔다. PDF는 글자를 선택할 수 있는 파일만 읽히고 OCR은 없다.
- 전송 안내 단계를 없앴다. 글자를 읽으면 확인 클릭 없이 바로 서버 변환을 시작하고, 진행 화면에 "글자만 전송 · 저장 안 함" 한 줄을 보인다.
- 모든 실패를 기존 미지원 화면의 카피바라 그림을 쓰는 한 화면으로 통일했다. 대상은 형식, 크기, 글자 수 초과, 읽기 실패, 글자 없음, 서버 초안 실패, 프로필 불러오기 실패다.
- 제목은 원인별 기존 문구를 쓴다. 글자를 못 읽은 PDF만 제목 "분석하지 못했어요"와 안내 두 줄(글자를 선택할 수 있는 PDF인지 확인, 스캔한 PDF(OCR)는 추후 지원 예정)을 쓴다.
- 버튼은 다시 보낼 수 있는 실패에 "다시 시도"(대기 시간 표시 유지), 그 밖에 "다른 파일", 공통 "닫기"다. "서버로 보내지 않았어요"와 "프로필은 그대로예요" 표시 조건은 그대로다.

## 이유

- 사용자는 파일 창에서 파일을 직접 고른다. 서버는 원문과 추출 값을 저장하지 않는다. 확인 클릭 한 번의 값어치가 작다.
- 글자는 서버를 거쳐 외부 모델로 전송된다. 그래서 전송 사실 표시는 한 줄로 남겼다.
- 잘못 고른 파일도 바로 전송되는 점은 감수했다. 진행 화면의 "취소"는 유지한다.
- 스캔 PDF를 고른 사람이 다음 행동을 알도록 실패 화면에 행동 안내 문장을 두었다. 화면 글자를 줄이는 기준의 예외다.

## 구현 사실 (후보 2)

- 변환은 글자 읽기가 끝난 직후 자동으로 시작된다. React StrictMode의 효과 재실행에서도 파일당 한 번만 시작된다.
- `ResumeImport`는 선택 prop `unsupportedImageUrl`을 받고 기본값은 확장 페이지 경로 `/unsupported-capybara.jpg`다. 사이드 패널과 온보딩은 확장 페이지라 기본값으로 보인다.
- 웹 페이지 안에 주입되는 패널은 `autofill.content`가 넘기는 `chrome-extension` 주소를 `InPageProfilePanel`이 `App`으로 전달한다. 이 그림은 이미 `web_accessible_resources`에 있어 매니페스트 변경이 없었다.
- 새 그림을 웹 페이지 안 패널에 쓰려면 같은 방식으로 주소를 전달하고 `web_accessible_resources`를 확인한다.
- 사용 통계 이벤트(`resume_import_viewed`, `resume_import_failed`, `resume_import_saved`)의 시점은 바뀌지 않았다.

## 검증과 한계

- 실패 우선 테스트 27건이 구현 전 실패하고 구현 뒤 31건이 통과했다.
- 합친 빌드를 Chrome에 로드해 합성 파일로 확인했다: 글자 PDF는 클릭 없이 검토 화면까지 진행, 글자 없는 PDF와 다른 형식 파일은 카피바라 실패 화면. 그림은 웹 페이지 안 패널에서 보였다.
- 크기 초과, 글자 수 초과, 서버 실패 화면은 실제 화면에서 보지 않았다. 테스트로만 확인했다.
