# CF-480 승인 후보 스냅샷

> Issue: [CF-480](https://github.com/woowacourse-teams/2026-career-form/issues/480)
> Collected: 2026-11-18
> Approval-Digest: b9ff638175d31eb6327967418852c23a9ebbcfaf808d26d479d77e6d4cab9f47

worktree 체크포인트에 기록한 후보 세 개의 원문이다. 사람이 2026-11-18 "승인"으로 확정했다.

1. 이력서 파일 가져오기 화면 결정(CF-480, 사람 결정 2026-11-18, 시안 확인 뒤 진행): (1) 진입 화면의 이력서 파일 줄에 '스캔 PDF 불가' 한 줄을 둔다. PDF는 글자를 선택할 수 있는 파일만 읽히고 OCR은 없다. (2) 전송 안내 단계를 없앴다. 글자를 읽으면 확인 클릭 없이 바로 서버 변환을 시작하고, 진행 화면에 '글자만 전송 · 저장 안 함' 한 줄을 보인다. 이유: 사용자가 파일 창에서 파일을 직접 골랐고 서버는 원문과 추출 값을 저장하지 않아 확인 클릭의 값어치가 작다. 글자는 서버를 거쳐 외부 모델로 전송되므로 전송 사실 표시는 남긴다. 잘못 고른 파일도 바로 전송되는 점은 감수하고 진행 화면의 취소를 유지한다. (3) 모든 실패(형식, 크기, 글자 수 초과, 읽기 실패, 글자 없음, 서버 초안 실패, 프로필 불러오기 실패)를 기존 미지원 화면의 카피바라 그림을 쓰는 한 화면으로 통일한다. 제목은 원인별 기존 문구를 쓰고, 글자를 못 읽은 PDF만 제목 '분석하지 못했어요'와 안내 두 줄(글자 선택 가능 여부 확인, 스캔 PDF(OCR) 추후 지원 예정)을 쓴다. 다시 보낼 수 있는 실패는 '다시 시도', 그 밖은 '다른 파일', 공통 '닫기'. '서버로 보내지 않았어요'와 '프로필은 그대로예요' 표시 조건은 그대로다.
2. 이력서 가져오기 실패 화면의 그림 주소 전달(CF-480): ResumeImport는 선택 prop unsupportedImageUrl을 받고 기본값은 확장 페이지 경로 '/unsupported-capybara.jpg'다. 사이드 패널과 온보딩은 확장 페이지라 기본값으로 보인다. 웹 페이지 안에 주입되는 패널은 autofill.content가 넘기는 chrome-extension 주소를 InPageProfilePanel이 App으로 전달한다. 이 그림은 이미 web_accessible_resources에 있어 매니페스트 변경이 없었다. 새 그림을 웹 페이지 안 패널에 쓰려면 같은 방식으로 주소를 전달하고 web_accessible_resources를 확인한다.
3. 프런트 단위 테스트 관찰(CF-480, 2026-11-18): `npm run test:unit -- src/autofill/policy`에서 native-form-exam.test.ts와 native-form-gpa.test.ts가 실패했다(판정 불일치 1~2건, 15초 시간 제한 1건). 같은 명령을 develop a258520 기준 clone에서 돌려도 같은 두 파일이 실패했고 이 브랜치는 src/autofill을 바꾸지 않았다. 이번 변경이 원인이 아니라는 것만 확인했고 실패 원인은 확인하지 않았다.
