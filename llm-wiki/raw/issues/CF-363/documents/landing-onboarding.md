# 설치 없이 체험하기와 기술 소개

> Collected: 2026-10-29

## 결정

랜딩 히어로의 행동 버튼은 `커리어폼 체험하기` 하나이며 `/try/`로 간다. 설치 버튼은 헤더, 하단 전환 섹션, 체험 완료 카드에 둔다. 내비에 `체험`과 `기술 소개`, 푸터에 사용 방법·체험·기술 소개 링크를 둔다. 700px 이하에서는 체험 대신 히어로에 설치 버튼을 보이고 `/try/`는 데스크톱 안내만 보여준다. 히어로의 자동 재생 시뮬레이션은 그대로 두고, 재생이 끝난 뒤 체험으로 안내하는 카드는 검토 후 넣지 않았다.

`/try/`는 패널 대기 화면 조사(`site/experiment/`)의 가상 지원서 27칸, 예시 프로필, 입력 시나리오와 `demo/PanelPreview`의 실제 사이드패널 UI를 설문 없이 재사용한다. 방문자가 패널의 `자동 기입`을 누르면 진행률(조사의 B 조건)이 표시되고, 완료 카드에서 설치 링크(새 탭)와 `다시 체험하기`로 이어진다. 누르기 전에는 자동 기입 버튼을 강조 애니메이션으로 표시하고 동작 줄이기 설정에서는 정적 테두리로 바꾼다. 패널의 `프로필 관리`와 `지원 공고 관리`는 확장 페이지를 열 수 없으므로 패널 안 안내 카드(설치 후에 열린다는 한 줄 설명, 설치 버튼, 체험으로 돌아가기)를 띄운다. `PanelPreview`는 `openOptions`·`openPostings` 콜백을 받고 기본값은 아무 일도 하지 않는다. 체험은 프로필을 저장하거나 서버에 요청하지 않는다.

`/tech/`는 자동 기입 칸 연결(문제·해결·결과 표·제품에 들어간 모습)과 공고 알림(문제·해결·기술 표·마감 알림·설계 원칙) 두 주제를 `site/tech.tsx` 데이터로 두고, 흐름도 3개는 사이트 색 토큰으로 그린 인라인 SVG(`site/TechFigures.tsx`), 마감 알림은 기존 `NotificationDemo`를 재사용한다. 공고 알림 절의 수치와 동작은 `backend/.../notification/**`과 ADR 348에서 확인한 것만 적는다. 자동 기입의 이전 수치는 `harness/fixtures/generic-autofill/*baseline-v1.json`과 일치하고, 이후 수치(4.2초·91.0%·0%)는 팀이 측정해 전달한 값으로 저장소에 산출물이 없어 출처 확인이 남아 있다.

허용 이벤트에 `trial_viewed`, `trial_started`, `trial_completed`를 더하고 `surface`만 기록한다. 사이트 빌드 진입점은 `tech`·`try`가 늘었고 `assert-site-build.mjs`가 둘을 검사한다.

## 검토한 배치와 근거

전용 페이지(A), 랜딩 안 인라인 섹션(B), 히어로 교체(C), 전체 화면 오버레이(D)를 프로토타입으로 비교해 전용 페이지를 택했다. 지원서와 패널을 넓게 둘 수 있고 랜딩 변경이 적으며 공유 가능한 URL이 생긴다. 근거로 삼은 자료는 자동 재생 미리보기 다음 단계로 설치 없는 체험을 두고 진입점을 첫 화면과 내비에 두라는 Navattic 2025 보고서와 Baymard SaaS UI 연구, 미리 채운 문서로 하면서 배우게 하는 Grammarly 데모 문서 분석이다.

## 유지되는 경계

CF-193의 확장 온보딩 단계형 프로필 등록 결정과 CF-96의 독립 웹 빌드, 가상 데이터 기반 시뮬레이션 경계는 그대로다. 체험과 기술 소개는 확장 프로그램 사이드패널 코드(`entrypoints/sidepanel/App.tsx`)를 바꾸지 않는다. 사이트 배포는 이 작업에 포함하지 않았고, 저장소에 연결된 Vercel 프로젝트는 모든 배포가 Preview이며 배포 보호가 켜져 있어 공개 주소가 없다. 정책 페이지는 기존 미시행 초안을 유지한다.
