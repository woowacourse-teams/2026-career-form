# SK 프론트 어댑터

## 구현 경계

`frontend/src/autofill/adapters/sk/collection.ts`는 필드 수집에서 숨김 템플릿 행을 제외하는 회사 규칙을 소유한다. 준비 단계와 일반 사이트에 같은 예외를 확대하지 않는다.

`frontend/src/autofill/adapters/sk/workflow.ts`는 학력 DOM 별칭, 신규 학력 행 기본값, 어학 선행 선택, 복수·부전공 선택과 후속 바인딩 판별을 소유한다. 교육 분류의 대학원·고등학교·대학 우선순위를 유지한다. 공통 워크플로가 로컬 프로필 값 해석, 분석 요청, 재수집과 최종 입력을 조정한다.

서버가 반환한 정확한 후속 프로필 바인딩과 text 입력 명령에 더해 `interactionStatus: READY`인 필드만 후속 입력한다. 여러 프로필 항목 중 하나를 유일하게 결정할 수 없으면 입력하지 않는다. 진단에는 값 대신 코드와 개수만 남긴다.

## 확인된 자동 검증 범위

- 숨김 템플릿 제외와 일반 사이트 행 개수 보존.
- 어학 선행 선택 성공 후 재수집·재분석, 실패 시 잘못된 후속 실행 방지.
- 신규 대학 행 기본값의 회사 한정 처리.
- 정확한 후속 바인딩, READY 상태와 단일 프로필 항목 검증.
- 차단된 분석과 비 READY 필드의 미입력.
- 실제 프로필 값이 진단 로그에 포함되지 않는지 비식별 값으로 검증.

초기 분리의 근거는 비식별 자동 테스트와 코드 조사이며, 이후 실제 SK 검증 범위는 아래 후속 검증 절과 구분한다.

## 제한

기존 자동 승인 및 문서 전체 첫 일치 라디오 선택 방식은 유지한다. 이번 분리를 반복 행별 검색·선택 안전성이 완성된 것으로 해석하지 않는다.

## SK 반복 행과 주소 검색 후속 검증

경력·자격증·시험·활용능력의 ID 없는 후속 버튼은 검증된 회사 root/행/제어/표시명 구조로 식별한다. 공통 실행기의 정확한 재식별과 행수 확인은 유지한다. 시험과 활용능력의 프로필 개수는 하위 section으로 분리한다.

SK 주소 검색은 기존 preparation API의 address-search-v1 capability 협상과 로컬 정책 v18을 사용한다. 구형 클라이언트에는 새 명령을 반환하지 않는다. 회사 어댑터는 주소 3개 필드의 정확한 바인딩·DOM·readonly 상태와 기존값을 검증한다. 카카오 전용 iframe에서 기본주소만 검색하고 주소·우편번호가 유일하게 일치하는 결과1/1만 선택한다. 상세주소는 검색 서비스에 보내지 않는다.

카카오 GET 검색은 같은 frame의 문서를 교체한다. 진행 중 검색만 같은 탭/출처/frame으로 최대1회 이어받고, 이미 로드된 결과를 다시 검색하지 않는다. 선택 직전 프로필·DOM·기존값을 재검증하며, 사이트 콜백으로 우편번호/기본주소가 반영된 후 상세주소를 입력한다. 중복 후보·다른 frame·취소·시간초과 등은 입력하지 않는다.

실제 Chrome 패널에서 전체 저장소 fixture와 공개 주소 fixture를 검증했다. 정확 일치 없음은 직접 확인으로 남고 공개 주소의 우편번호·기본주소·상세주소 일치, readonly 유지와 레이어 종료를 확인했다. 원래 프로필 복원과 시험 입력 정리를 확인했다. 주소 검증 당시에는 경력 미매핑, 대학 날짜 maxlength 초과, 시험 성적/선택 코드 미확정을 별도 제한으로 기록했으나, 아래 후속 절에서 경력·대학 년월·시험 성적/선택의 검증 범위를 갱신했다. 실제 저장 호환성과 범위 밖 필드는 별도 제한으로 유지한다.

## 경력·년월·국적 후속 규칙

SK 경력의 8개 필드는 exact DOM 식별과 프로필 키를 함께 확인한다. ID 없는 재직상태 select는 검증된 이름과 `SELECT` 제어 종류로 매핑하고, 선행 선택 후 퇴직사유를 다시 수집·분석한다. 새로 보인 필드도 서버의 `READY` 상태와 해당 경력 항목의 유일한 바인딩이 확인될 때만 입력한다. `DERIVED` 년월은 `YEAR_MONTH`로 처리하며 반복 행 수와 대응 프로필 항목 수가 일치하지 않으면 행 순서와 개수 보호를 우회하지 않는다.

이번 후속 매핑은 로컬 정책 v22에 반영된 범위에서 확인했으며 production 정책 배포 완료를 뜻하지 않는다.

국적은 정확한 select 매핑과 대한민국에 한정한 lookup을 사용한다. 실제 1개 필드의 일치와 다른 제어 불변을 확인했으며, 다른 국적 별칭까지 지원한 것으로 확대하지 않는다. 대학 입학·졸업일은 숫자 6자리 편집과 `YYYY-MM` 표시 계약을 따르고 전체 날짜 `DIRECT`로 우회하지 않는다. production writer의 두 필드에서 년월 유지와 전체 204개 제어 원복을 확인했지만 실제 저장 호환성은 미검증이다.

## 검색·성적 입력의 직렬 처리

학교·자격증·시험 검색은 `BODY`에 붙는 jQuery UI 메뉴 중 정확한 입력에 대응하는 widget만 대상으로 한다. MAIN world에서 새 검색 완료와 유일한 label/value 일치를 확인한다. 학교·자격증의 정상 결과는 id가 없을 수 있지만 시험은 비어 있지 않은 0 이외 id가 필요하다. id=0 직접 입력 결과, 부분 일치와 중복 결과는 자동 선택하지 않는다.

행과 검색 종류별 쓰기·확정은 직렬 처리하며 확정한 이름은 최종 단계에서 다시 쓰지 않는다. 시험 언어를 선택한 뒤 같은 행의 text 또는 select 성적란이 하나만 나타나는지 확인하고 다시 분석한다. `lngExamScoreSel`은 실제 ID가 없으므로 이름과 `SELECT` 제어로 매핑한다. 요청 marker를 제거하고 사용자 변경 뒤 늦은 선택·복원을 막지만, 전체 취소 UX가 구현된 것으로 주장하지 않는다.

## 전체 패널 검증 범위

저장소의 전체 공개 SK 검색 fixture를 실제 가져오기 UI로 적용하고 설치된 production 확장의 popup→사이드 패널→자동 기입을 실행했다. 준비 2회와 필드 분석 8회가 모두 HTTP 200, `ADAPTER`, `COMPLETE`였으며 시험 2행의 서로 다른 nonzero 선택 ID와 text/select 점수, 자격증 3행·대학 1행의 `confirmed`·`selectedItem`·프로필 일치를 확인했다. UI 집계 23개 기입 성공과 0개 직접 확인은 표시된 writer 결과이며 선행 선택과 미지원·미선택 항목 전체 성공을 뜻하지 않는다. 테스트 뒤 프로필 키 미존재와 지원서 204개 제어의 값·선택·disabled·readonly 상태를 복원하고 UUID 재생성만 정규화해 비교했다. 실제 저장·제출 호환성은 검증하지 않았다.

## CF-83 자동 기입 보완 (2026-09-09)

이 절은 앞선 CF-46 검증 기록 이후의 변경이다. 앞 절의 설치 smoke 결과는 CF-83 수정본의 실제 재기입 결과가 아니다.

SK 고교·대학 추가 버튼은 ID가 없는 후속 행에서도 회사 루트, 학력 종류, 행·버튼 조상 구조와 학교 입력칸을 검증해 안정적인 ID로 수집한다. 공통 반복 실행기의 재식별 및 정확히 1개 증가 조건은 유지한다.

SK 병역은 대상 라디오→군필/미필/면제/복무중 분류→노출된 상세 필드 순서로 처리하고, 보훈은 대상 여부·번호·관계를 연결한다. 기존 반대 선택과 다른 병역 분류는 보존하며, 이미 같은 선택에는 변경 이벤트를 다시 보내지 않는다. 보호 여부는 준비 계획과 실행 직전에 확인한다.

공개 fixture의 병역·보훈 정의 필드는 가상 값으로 채우고, 모순되는 상태는 별도 테스트로 분리한다. 현재 확인한 SK 화면에 없는 군별·계급·복무일자와 미검증 특기·전역구분·보훈구분은 실제 입력 지원으로 표시하지 않는다. 기존 다른 화면용 정책과 신규 미지원 필드를 구분한다.

로컬 정책 버전은 SK v23·현대 v5이며 프로필 스키마와 API DTO는 변경하지 않았다. 자동 테스트, 읽기 전용 실제 DOM 확인, 별도 가상 DB의 API 검증을 실제 설치 확장의 재기입 검증과 구분해 문서화한다. CF-83 설치 확장 재기입과 저장·제출 호환성 및 운영 정책 배포는 검증 완료로 표시하지 않는다.
