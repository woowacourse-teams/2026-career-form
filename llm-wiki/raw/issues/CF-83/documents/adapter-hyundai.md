# 현대 프론트 어댑터

## 구현 경계

`frontend/src/autofill/adapters/hyundai/collection.ts`는 현대 전용 섹션, 추가 제어 식별, 반복 행과 버튼형 입력 수집을 담당한다. 회사가 식별한 전용 반복 영역에만 가시성 예외를 적용한다. 일반 반복 영역으로 처리된 행에는 기존 일반 개수 계산을 유지한다.

`frontend/src/autofill/adapters/hyundai/write.ts`는 기존 버튼 선택 명령과 text 입력 후 라벨 보정을 담당한다. 검증된 코드와 표시명이 유일하게 일치해야 선택하고, 실패하면 일반 입력으로 우회하지 않는다. 승인되지 않았거나 stale인 후보는 공통 writer가 실행 전에 차단한다. 성공한 text 입력만 라벨 보정 대상이다.

## 확인된 자동 검증 범위

- 회사 밖에서 전용 버튼·추가 제어·반복 행 규칙 미적용.
- 회사 전용 반복 행의 독립 index/count 및 일반 반복 영역 개수 유지.
- 버튼 후보 0개·복수 후보에서 선택 실패와 기존 표시값 보존.
- 미승인·stale 후보의 메뉴 미실행.
- 성공 text 입력의 회사 한정 라벨 보정.

기존 버튼·반복 행 범위는 비식별 자동 테스트와 코드 조사에 근거하고, 최신 승인 범위에서는 수정 코드로 실제 설치된 production 확장의 고교·학사 2행 smoke를 추가 확인했다. 실제 저장·이동·미리보기·제출은 실행하지 않았다.

## 제한

회사 버튼 선택은 같은 select-wrap 메뉴로 한정하고 최종 표시명과 숨은 코드까지 확인한다. 어학 선행 선택은 완료 후 재실행하지 않으며 후속 메뉴 준비를 제한 시간 안에 확인한다. 별도 검색 팝업의 비동기 검색·취소 계약은 이번 범위에서 새로 제공하지 않는다.


## 같은 이름의 취득일 구분

현대의 어학 취득일과 자격증 취득일은 같은 DOM 이름을 사용한다. 이름만 연결하던 기존 정책에서는 어학 날짜가 자격증 취득일 규칙으로 연결될 수 있었다.

로컬 현대 정책 v3은 두 취득일에 `FieldRule.requiredDomName`을 명시한다. 이 조건이 있는 규칙은 반복 접미사를 제거한 DOM ID가 `structuralName`과 같고 DOM 이름이 `requiredDomName`과 정확히 같을 때만 후보가 된다. element/control 검증도 유지한다. 알려진 ID나 이름 중 일부만 맞으면 기존 이름 매핑으로 우회하지 않고 `NO_MATCH`로 남긴다. 이 속성이 없는 기존 정책은 기존 생성자와 저장 문서 역직렬화에서 null로 처리해 호환성을 유지한다.

두 날짜는 각각 어학·자격증 프로필의 취득일을 `DIRECT`로 연결한다. 회사 fingerprint와 API schemaVersion 2는 변경하지 않는다. 로컬 빌드와 서버를 갱신해 수정 정책을 적용했고 비식별 API 응답으로 확인했다. 실제 설치 smoke에서 검증한 범위와 자격증·어학 전체 재기입 미검증은 구분한다.

자동 회귀는 같은 이름의 어학·자격증 날짜 분리, 잘못된 ID/이름/제어 타입, 잘못된 반복 접미사, ID/이름 누락, 기존 문서 호환성을 확인한다. 프론트 회귀는 별도 반복 영역의 각 프로필 항목을 수집·리뷰·입력까지 연결하고, 프로필 값이 있어도 미매핑 후보는 입력하지 않는지 확인한다.

## 미입력 점검의 해석

초기 읽기 전용 점검 당시에는 국적·주소 매핑이 없다고 기록했지만, 승인된 최신 정책 v4에서는 국내 주소 검색과 국적1 대한민국 lookup을 검증 범위에 추가했다. 직장명은 `careers.career.companyName` 프로필 필드가 있지만 현대 매핑이 누락된 상태이고, 프로젝트 기관·해외경험 날짜는 대응 프로필 필드가 없다. 지원경로·자기소개서 등은 재사용 프로필 범위 밖이다. 병역·보훈·장애는 개별 확인 정책을 따른다.

자격증 날짜·등록번호·발급기관처럼 매핑이 있는 필드도 빈 화면만으로 로컬 값 부재나 입력 버그를 단정할 수 없다. 실행 당시 분석 결과와 반복 행 대응을 확인해야 한다. 검색 선택이나 필수 모델이 없는 항목을 텍스트 입력으로 우회하지 않는다. 최신 실제 설치 검증은 고교·학사 2행과 주소·국적1 범위이며 전체 재기입 결과로 확대하지 않는다.

## 반복 행 준비와 자격증명 보완

실제 페이지의 프로젝트·논문 영역에는 article ID가 없다. 기존 수집기는 ID로만 추가 버튼을 식별하여 두 동작을 누락했고, 필수 준비 fingerprint가 불일치해 자격증을 포함한 모든 반복 추가 계획이 차단됐다. 비식별 API 재현에서 누락 구조는 BLOCKED/0 plans, 완전한 구조는 COMPLETE/6 plans를 반환했다.

현대 어댑터는 같은 직접 반복 행의 검증된 프로젝트 또는 논문 제어 구조로 추가 동작 식별자를 복원한다. 불완전하거나 모호한 구조는 인식하지 않고 다른 사이트·해외경험에 규칙을 적용하지 않는다. fingerprint 자체는 약화하지 않는다.

준비 실행은 지원 섹션의 로컬 프로필 개수에서 현재 행 수를 뺀 만큼만 추가하고 매번 증가를 확인한다. 외국어시험은 languageTest, 외국어 활용능력은 languageSkill 개수를 각각 사용한다. 반복 추가 대상은 직장경력·프로젝트·외국어시험·외국어 활용능력·자격·논문/특허이며, 최신 정책 v4는 학력의 필요한 행 준비도 별도로 소유한다. 해외경험의 자동 추가는 미지원이다.

자격증명은 nationLicNm의 반복 접미사를 제외한 ID, 정확한 이름과 text 제어 검증 뒤 certifications.certificate.name에 DIRECT 연결한다. 기존 반복 리뷰는 화면 행 수와 프로필 개수가 다르면 입력을 차단한다. 비식별 통합 회귀에서 프로필 3개/화면 1행의 차단, 정확히 2회 추가, 서로 다른 3개 항목 입력, 재실행 시 중복 추가 없음을 확인했다. 수정 코드의 실제 채용 페이지 재기입은 여전히 미검증이다.

## 첫 실행 버튼 재탐색 보완

행 추가 후 임시 후보 번호가 바뀌면 제공된 DOM ID/이름을 정확히 확인해 같은 동작을 다시 찾는다. ID 없는 다른 영역의 동일 표시명 버튼으로 우회하지 않는다. 마지막 추가도 기존 필드가 보인다는 이유로 동작 재식별·행수 검증을 생략하지 않는다. 행 안의 버튼, footer 추가 버튼, 타 영역 추가 버튼을 포함한 비식별 구조로 첫 실행 회귀를 보강했다.

## 외국어시험·활용능력

현대 정책 v3에 확인된 시험 언어 13개, 영어 시험 11개, OPIc 계열 등급, 활용 언어 11개와 회화수준 4개를 BUTTON_OPTION으로 연결했다. 시험명·회화수준의 명확한 별칭은 같은 표시명으로 정규화한다. 미검증 시험·등급, 코드가 모호한 선택지는 추정하지 않는다. 활용능력의 작문·독해는 현재 대응 프로필 필드가 없으므로 회화수준으로 대신 채우지 않는다.

실제 버튼에는 name이 없고 숨은 입력이 같은 필드의 코드를 보관한다. 현대 워크플로는 버튼의 반복 접미사를 제외한 ID와 프로필 연결로 언어→시험 단계를 구분한다. 언어 선택 뒤 시험 메뉴, 시험 선택 뒤 등급 메뉴와 직접입력 상태를 같은 반복 행에서 제한 시간 안에 확인한 뒤 재수집·재분석한다. 정상 직접입력 버튼만 사용하며 성적 불러오기나 disabled 강제 해제는 실행하지 않는다. 선행 선택을 완료하면 최종 입력에서 다시 누르지 않고, 선택·준비 실패 시 후속 쓰기를 중단한다.

메뉴 선택은 같은 select-wrap의 유일한 표시명·코드에 한정한다. 선택 후 버튼 표시와 숨은 코드가 모두 맞아야 성공이다. 비식별 자동 회귀·로컬 서버 적용은 실제 페이지 재기입 검증과 구분한다.

구조·상태 전환 근거는 공개 사이트 스크립트 [common.js](https://talent.hyundai.com/static/js/common.js), [apply.js](https://talent.hyundai.com/static/js/apply.js), [common.api.js](https://talent.hyundai.com/static/js/common.api.js)와 비식별 UI 옵션 확인이다. 개인 입력값·계정·세션은 저장하지 않았다.

## 국내 주소·국적·학력 검증

국내 주소는 검증된 `postCd` readonly 입력의 정상 주소 검색 modal에서 유일한 우편번호·기본주소 정확 일치 결과만 선택한다. 정상 callback에서는 상세주소를 초기화한 뒤 기존 일치값을 복원하거나 빈 상세주소에 프로필 값을 연결한다. 해외 주소와 불명확한 결과는 자동 입력하지 않는다. 결과 없음·중복·취소 시 이번 실행이 연 modal·검색어·필드 상태만 정상 닫기 버튼으로 정리하고 사용자 변경과 기존 열린 modal은 보존한다. 실제 실패 fixture에서 modal과 가림막 닫힘을 확인했으나 주소는 입력하지 않았다.

국적1은 `nationCd1Nm`의 keyup 검색에서 해당 필드의 유일한 대한민국 결과를 선택하고 표시명, `data-search-result`, hidden `nationCd1=KR`를 함께 확인한다. 지원 범위는 대한민국이며 국적2는 변경하지 않는다.

학력은 프로필의 고교·대학·대학원 순서와 `degreeLevel`로 종류 3/4/5/6/7을 검증된 메뉴에서 선택한다. 필요한 행만 추가하고 소유 복제 행만 정상 reset 메뉴로 초기화하며 기존 값·선택·행 순서를 보호한다. 종류별 제한 초과나 불명확한 구조에서는 중단한다. 확정된 행은 `educationhighschool`, `educationuniversity`, `educationgraduateschool`의 `itemGroupId` 및 그룹 내 `index/count`로 바인딩하고, 종류 변경은 후보를 stale로 만든다. 준비와 학교·전공 검색 확정 뒤 재분석한다.

학교 `schNm`은 `data-auto-type=school`과 고교 `params0045`, 대학·대학원 `params0047` 검색에서 `schCd`를 확인한다. 전공 `majorNm`은 `data-auto-type=basic`, `params0015` 검색에서 hidden `major`를 확인한다. 새롭고 보이는 유일한 정확 결과이며 비어 있지 않은 `9999` 이외 코드인 경우만 허용한다. 기존값·사용자 변경·취소·stale을 보호한다. 학교를 `basic`으로 가정했던 fixture는 실제 설치 검증에서 실패를 재현한 뒤 교정했다.

정책 v4는 주소 검색과 academic 행 준비, 국적1, 학력 그룹별 날짜·학교·전공·GPA·졸업상태를 매핑한다. `rcd`는 대학·대학원 GPA이고 `rcdM`은 전공 GPA이므로 대학원 총 GPA로 매핑하지 않는다. 자동화는 고교·대학·대학원 및 복수행을 포함하고, 실제 설치 smoke는 고교·학사 2행까지 확인했다. 실제 대학원·전문학사·박사와 저장·제출 호환성으로 확대하지 않는다.

## 실제 설치 검증과 한계

승인된 Hyundai 검색 fixture는 전체 범주·항목 수를 유지하면서 공개 기관 학교·주소 및 실제 TOEIC 메뉴값만 조정했다. 설치된 정적 production 확장의 실제 popup→사이드 패널→자동 기입을 실행했고 API 7회가 모두 HTTP 200/`ADAPTER`/`COMPLETE`였다. 독립 대조에서 주소 우편번호·기본주소·상세주소 3값과 readonly, 국적1 표시명·hidden KR 및 국적2 불변, 고교·학사 2행의 학교명·코드·검색 marker와 입학·졸업 기간 4필드, 대학 전공명·hidden 코드·GPA·졸업 코드를 각각 fixture와 일치시켰다. UI의 기입 성공 38·직접 확인 0은 표시된 writer 집계이며 전체 필드 성공을 뜻하지 않는다. 실제 toolbar icon 클릭 자체는 검증하지 않았고 popup은 `chrome.action.openPopup`으로 열었다.

재실행에서 학력 2행과 전체 입력값·체크상태를 유지했으나 기존 어학 성적 버튼 1개의 disabled 상태가 달라졌다. 기본 fixture의 주소 실패에서 modal과 가림막 닫힘을 확인했다. 테스트 후 원래 프로필 키가 없는 상태와 지원서 1149개 input/select/textarea의 값·선택·readonly·disabled를 복원했으며 실제 입력값·원본 DOM·세션은 기록하지 않았다. 실제 저장·임시저장·페이지 이동·미리보기·제출은 실행하지 않았다.

## CF-83 자동 기입 보완 (2026-09-09)

이 절은 앞선 CF-46 검증 기록 이후의 변경이다. CF-83 설치 확장의 가상 전체 fixture 검증에서 현대 전공 표시명·코드·marker·라벨 상태와 만점기준을 확인했다. 수동 확인 항목은 별도로 남기며 전체 필드 성공으로 표현하지 않는다. 실제 툴바 아이콘 진입, 저장·제출 호환성과 운영 정책 배포는 미검증이다.

현대 대학 만점기준은 4.00→4.0/4, 4.30→4.3/4.3, 4.50→4.5/4.5, 100.00→100/100의 표시명/코드만 연결하고 정확한 hidden rcdPerf를 사용한다. directRcdperf 및 기타 직접입력은 제외한다. MongoDB 8의 정책 저장 시 소수점 Map 키를 보존하도록 변환기를 구성하고 SK·현대 정책의 BSON 왕복과 새 가상 DB의 실제 API 조회를 검증했다.

현대 대학 복수·부전공은 유무가 있음이고 이름이 있을 때만 같은 행의 basic/0200/0015 검색에서 유일한 정확 결과와 hidden 코드·marker를 확정한다. 성공 및 이미 확정된 학교·전공에는 exist 클래스를 반영하고 실패·취소 시 실행이 소유한 값과 라벨 상태만 복원한다. 프로필 조건 검증은 대학 범위로 한정한다.

복수·부전공 검색의 정확한 결과가 없으면 검증된 해당 검색 영역만 수동 확인으로 남기고 같은 행의 나머지 입력을 계속한다. 학교·주전공·언어의 실패 처리로 확대하지 않는다. 별도 전체 현대 fixture는 추가전공명만 유일한 정확 선택지로 바꿔 정상 경로를 확인했으며, 기본 fixture의 검색 불일치에서도 부전공·만점기준 입력과 결과 화면 도달을 확인했다. 페이지 자체 이벤트가 `directRcdperf`를 동기화하는 동작은 어댑터의 직접 쓰기와 구분한다. 추가전공 정확 결과가 0개인 negative fixture에서는 해당 항목을 수동 확인으로 남기고 같은 행의 minor/GPA는 계속해 40개 입력·2개 수동 확인 결과를 확인했다.

로컬 정책 버전은 SK v23·현대 v5이며 프로필 스키마와 API DTO는 변경하지 않았다. 자동 테스트, 읽기 전용 실제 DOM 확인, 별도 가상 DB의 API 검증을 실제 설치 확장의 재기입 검증과 구분해 문서화한다. 실제 툴바 아이콘 진입, 저장·제출 호환성과 운영 정책 배포는 미검증이다. 후속 SK 병역 동의어의 실제 재기입은 별도로 대기 중이다.
