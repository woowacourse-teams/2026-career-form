# CF-505 승인 후보 스냅샷

> Issue: [CF-505](https://github.com/woowacourse-teams/2026-career-form/issues/505)
> Collected: 2026-11-21
> Approval-Digest: 7036bd66de1e2c36d356b4a4084f8db93503281327322fad00b94f87deb3661b

worktree 체크포인트에 기록한 후보 다섯 개의 원문이다. 사람이 2026-11-19 "llm wiki 앞으로 잘 동작하는지 확인하고, 사람 승인 안받아도 되니 너가 알아서 기입해"라고 말해 에이전트가 자동 승인했다.

1. 에이치닷 v1 지원자 앱 1단계 지원 범위(#505): 경로 /v1/applicant/resume-form/<숫자>, 쿼리 step=1, v1 플랫폼 지문, 검증된 칸 1개 이상일 때만 지원 화면으로 본다. 대상은 영문이름·생년월일·성별·비상연락처, 병역 상태와 하위 6칸, 장애 여부와 하위 3칸, 보훈 여부와 하위 2칸, 국적의 19칸이다. 읽기 전용 칸, 사진, 지원 분야 묶음, 지원경로, 복무 기간, 편의 제공 여부, 보훈비율, 현주소, 취미, v1 2단계 이후, JOBDA·빌더는 다루지 않는다.
2. v1 1단계 화면 구조와 식별 기준(#505): 빌드 해시 클래스는 선택자로 쓰지 않고 고정 name, 행 제목(첫 자식 span[aria-hidden=true]), placeholder, 선택지 글자, 구조, ats 유틸리티 클래스만 쓴다. 상태 행 제목은 병역·장애여부·보훈여부다. 성별 라디오는 label 클릭으로만 선택된다. 상태 선택은 li > button 묶음이고 선택 표시는 클래스 두 개뿐이다. 드롭다운은 button과 열렸을 때만 있는 #dropdown-body의 ul > li > button[value]이며 Escape로 닫히지 않는다. 상태를 고르면 같은 행 하위 칸의 disabled가 풀린다. 입대일은 포커스를 잃으면 YYYY.MM으로 바뀐다. 자동 저장은 없다.
3. v1 정책 분리와 전송 계약(#505): 섹션 hplace-v1-basic, 칸 이름 hplace.v1.<key>. 버튼형 위젯은 전송에서 input/radio와 select/select로 표현하고 실제 조작은 프론트 v1 writer가 한다. 백엔드 v1 규칙은 저장하지 않는 v1 전용 정책 객체에 두어 MRS2 저장 문서 v3·v4, hplace-mrs2-v4.json, 활성 정책 버전 기본값을 바꾸지 않는다. 백엔드는 단계를 알 수 없어 섹션 ID와 칸 이름 허용 목록으로만 판정하고 step=1은 프론트가 확인한다. 상태 선택은 stage 1 driver이고 하위 칸은 다음 분석에서 기입한다. 선택지 불일치는 기입 단계에서 OPTION_UNMATCHED로 보고한다. 기존 값은 덮어쓰지 않고 기본값 비대상만 하위 칸이 비어 있을 때 바꾼다. 군별은 해병대→해병, 전투경찰→전경, 해양경찰→해경, 의무경찰→의경 대응표를 둔다.
4. v1 1단계 실측과 한계(#505, 2026-11-21): v1 테넌트 1곳에서 분석 ADAPTER·COMPLETE 2회(8칸, 19칸 모두 일치), 18칸 기입, 사이트로 가는 GET 이외 요청 0건, 읽기 전용·범위 밖 칸 불변, 2단계 미지원 유지. 남은 1칸은 프로필 값 없음으로 판단(추정). 같은 화면을 범용 경로로 보낸 실험은 16칸 수집, 14칸 연결, 2칸 기입이었다. 확인 테넌트는 1곳이고 미필·면제·복무중이 여는 칸과 제대일 정규화는 측정하지 않았다. 국적은 대한민국만 대응한다. 배포는 확장 먼저, 백엔드 다음 순서다.
5. 실행 정책 조회의 경로 검사(#505): 확장 백그라운드는 정책 조회 요청의 경로가 문서를 처음 연 주소의 경로와 같을 때만 받아들였다. sender.url은 같은 문서 안 주소 변경(SPA 라우팅)을 따라가지 않아, 새 로드 없이 경로가 바뀐 화면에서는 조회가 BAD_REQUEST로 끝나고 자동 기입이 시작되지 않았다. 호스트 일치 검사는 유지하고 경로는 형식만 검사하도록 바꿨다. 확장에 tabs 권한이 없어 탭의 현재 주소로 대조하는 방법은 쓰지 않았다. v1 로그인 화면에서 주소만 바꿔 수정 전 실패와 수정 후 정상을 확인했다. 로그인 뒤 지원서로 넘어가는 실제 경로는 확인하지 못했다.
