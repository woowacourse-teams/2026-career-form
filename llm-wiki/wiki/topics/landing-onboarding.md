## 현재 상태

랜딩은 히어로 뒤에 의사결정 AI(JEV)가 지원서를 채우는 과정을 7단계 화면 고정 스크롤 장면(자동 기입 누르기와 콘솔 전환, 묶음 나누기, 종류 판단, 후보 좁히기, 확신 재기, 채우기, 확인 요청)으로 보여주고, 바로 아래 10칸 가상 지원서와 간이 패널로 된 직접 체험, 마감 알림 장면(하루 전 알림, 지원 완료 시 남은 알림 취소), 안심 포인트·설치 버튼·FAQ 순서로 둔다. 신뢰도는 확실·애매·모름과 퍼센트로 보인다. 체험은 자동 기입을 누르기 전까지 아래 스크롤을 붙잡고 건너뛰기를 둔다. 700px 이하이거나 터치 전용 기기면 모바일로 보고 웹스토어 링크 대신 헤더·히어로·마무리에 `공유하기`를 두며, 체험 자리는 `공유하기`·`링크 복사` 두 버튼 카드로 바꾸고 스크롤을 붙잡지 않는다. 공유는 공유 시트, 거부되면 링크 복사 순이고 링크는 `/#try`다. 좁은 화면의 AI 장면은 상태 칩을 하단에 두고 행 높이를 화면 높이에 맞추며, 알림 장면은 캡션·공고·시간축·알림을 실측해 쌓는다. 모자라면 머리글·캡션 본문을 숨긴다. AI 장면과 마감 알림 장면(공고·타임라인 등장, 하루 전 알림, 지원 완료와 알림 취소의 3단계)은 스크롤이 단계만 고르고 장면은 시간 기준으로 그 단계 끝까지 재생된다. 위로 올리면 1.5배로 역재생하고, 재생 중 다음 구간에 들어가면 남은 부분을 3배로 끝내고 중간 단계를 건너뛴다. 멈춤 지점에서 단계가 완성돼 보이도록 퇴장 효과는 단계 경계 직후에 둔다. 연출은 미리 렌더한 클레이 webp와 transform/opacity만 쓰고 동작 줄이기 설정에서는 재생 없이 단계가 바로 바뀐다. 랜딩·기술 소개·정책은 `#B1E5FD` 기반 하늘색 전용 토큰을 쓰고 확장의 `theme.css`는 바꾸지 않는다. 정책의 문의 이메일은 `개설 후 기재`이며, 모든 사이트 페이지는 앵커가 없으면 맨 위에서 열린다.

`/try/`는 CF-363대로 실제 사이드패널 UI로 체험하는 페이지로 남고, 확장을 처음 설치하면 열리는 `onboarding.html`은 선택 화면 없이 이름, 이메일, 직무 선택, 알림 안내, Greeting, 사용법의 여섯 단계를 한 줄로 진행하고 입력 영역 위 진행 바에 전체 단계와 현재 위치를 보인다(CF-431). 현재 단계 이름만 `careerForm.onboarding.step`에 저장해 다시 열면 이어지고, 끝내지 않았으면 관리 페이지에 "시작 안내 이어하기" 링크가 보인다. Greeting 단계는 가져오기를 실행하지 않고 프로필 저장의 변경만 감지하며, Greeting과 사용법의 장면은 계속 반복되는 컴포넌트 애니메이션으로 일시정지할 수 있고 동작 줄이기 설정에서는 재생하지 않는다. CF-193의 단계형 프로필 등록은 사용법 단계의 "추가 정보 더 등록하기"에서 "저장한 정보" 화면으로 연다. 여섯 단계는 랜딩의 하늘색 값을 흐름 범위 안에서만 쓰고, `?page=`로 여는 소개·체험·정책 페이지와 웹 `/onboarding/` 4단계 사용 안내는 그대로다. 화면 검증은 빌드한 확장을 Chromium에 설치해 조작하고 설계를 모르는 검토자의 사용자 역할 점검을 함께 한다. 체험 시작·완료는 `trial_*` 이벤트로 `surface`만 기록한다. 장면의 분석 시간 수치는 출처 확인이 남아 있다. 독립 웹 빌드와 가상 데이터 경계를 유지하고, 정책 문서는 미시행 초안이며 사이트 공개 배포는 아직 없다.

## 변경 이유

문구와 장식 요소가 많아 핵심이 묻혔고, 의사결정 AI로 빠르고 정확하게 채운다는 점과 체험이 소개 흐름에 드러나지 않았다. 스크롤 장면으로 JEV의 동작을 단계별로 보여준 뒤 같은 지원서에서 바로 눌러보게 해 설치 결정으로 잇는다.

CF-424에서는 스크롤 진행률에 묶인 연출이 스크롤을 멈추면 중간에 멈춰 단계 설명이 끊겨 보여, 단계별로 끝까지 재생하는 방식으로 바꿨다.

CF-431에서는 설치 직후 선택 화면을 거쳐야 등록이 시작되고 등록이 알림 설정으로 이어지지 않아, 선택 화면을 없애고 등록, 알림, 사용법을 한 줄로 이었다. 긴 글로 설명하던 Greeting 가져오기는 사람들이 읽지 않을 것이라는 판단으로 반복 장면으로 바꿨다.

CF-427에서는 주 유입처인 스레드 모바일 방문자가 깨진 장면과 설치할 수 없는 웹스토어 링크를 만나, 좁은 화면 배치를 실측 기반으로 바꾸고 모바일 행동을 PC로 이어갈 공유하기로 바꿨다.
