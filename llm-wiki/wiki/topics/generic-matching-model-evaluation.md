## 현재 상태
범용 자동기입의 모델 정확도와 처리 성능은 사람이 검토한 비식별 화면으로 만든 버전 고정 데이터셋(저장소 파일, sha256)으로 잰다. 개발 서버의 비동기 실행 API가 제품 서비스를 그대로 호출한다. 결정 근거는 [CF-356 ADR](../../raw/issues/CF-356/documents/adr/356-versioned-model-evaluation.md)이다.
대표 점수인 자동기입 점수는 값을 실제로 넣는 칸 매핑만의 F0.5다. 준비 점수와 섹션 분류 점수는 섞지 않고 같은 식으로 따로 낸다. F0.5는 잘못 넣은 1칸을 놓친 4칸과 같게 치며, 제품이 확신도 0.8 이상만 자동으로 넣는 것과 같은 비율이다. 칸 매핑은 확신도 0.8 이상만 넣은 것으로 보고, 요청이 실패한 칸은 놓침으로 센다. 항목 단위 정확도(`item-weighted-exact-v2`)는 깎인 이유를 보는 진단 지표이고, 단계는 호출이 일어난 단계로 센다. 자동기입 1번은 같은 반복·같은 사이트에서 준비만 있는 처음 화면의 호출과 칸 매핑이 있는 화면 하나의 호출을 합친 것이다.
평가의 0.8 기준은 제품 등급 규칙을 단순화한 것이고(제품은 조건이 맞으면 0.35 이상도 넣고 범주 미확정 칸도 기본으로 넣는다), 후속 요청을 정답으로 만들어 섹션 분류 오답이 칸에 미치는 영향을 재지 않는다. 그래서 자동기입 점수는 프롬프트·모델·구조를 비교하는 값이고 실제 자동 입력률이 아니다.
정답은 칸 의미 기준이며 병역·보훈·장애도 포함한다. 요청은 제품 코드가 fixture에서 만들고 손으로 쓰지 않는다. 시간, 처리량, 토큰, 비용의 측정 범위와 프롬프트 버전 해시, 실행 운영 규칙은 [CF-356 근거](../../raw/issues/CF-356/documents/generic-matching-model-evaluation.md)를 따른다.
현재 데이터셋은 `catalog.json`의 현재 버전 generic-matching v4다. 우아한형제들 화면 4개와 NHN Careers 지원서 최초 화면 1개, 합성 프로필 1개다. 공고나 화면을 더할 때는 `catalog.json`과 새 버전 폴더만 고친다. 기준 기록(반복 3회, 2026-11-05, 칸 매핑 기준)은 저장소에 담아 평가를 켠 서버가 갖고 시작한다. 화면 전체를 한 번에 묻는 초기 호출 방식은 gpt-5.6-luna 88.1%, gpt-6-luna 85.9%, JEV 83.5%(입력 토큰 초과 72번)이고, 섹션별로 5칸씩 묻는 현재 구조는 JEV 87.3%, gpt-5.6-luna 81.8%, gpt-6-luna 87.0%다. 호출 방식만 재현한 측정이고, 구조 변경은 JEV의 점수·시간·토큰 초과를 개선했지만 OpenAI 정확도에는 이득이 없었다. 공고 둘의 합성 프로필 기준이라 일반 성능의 근거는 아니다.
프롬프트·모델·설정이 같아도 실행마다 점수가 몇 %p 움직이므로(관측 4.7%p) 전후 비교는 둘 다 반복 3회 이상으로 하고, 반복 1회이거나 범위가 겹치면 구분 불가로 표시한다.
같은 조건을 다른 시각에 재면 4점 안팎으로 움직인 관측이 있어, 4점 이내 차이는 범위가 겹치지 않아도 근거로 쓰지 않고 틀린 칸이 반복마다 같은지를 항목별 비교로 확인한다.
로컬은 `scripts/evaluation_local.py`로 고칠 때마다 재고, 개발서버는 AI 호출 없이 계산한 평가 입력(동작 지문, 프롬프트, 설정, 공급자 연결 코드, 데이터셋)이 바뀐 배포에서만 자동 평가를 돌린다. 공급자가 같은 이름으로 바꾼 모델과 속도만 바뀐 변경은 직접 돌린다. 기록 삭제는 로컬에서는 비밀번호 없이 되고, 함께 쓰는 서버에서는 로그인 비밀번호를 다시 입력해야 된다.
OpenAI 엄격 스키마의 enum은 합쳐 1,000개까지라, 한 요청의 선택지가 이를 넘으면 같은 선택지를 쓰는 질문이 정의 하나를 공유한다. 범주가 확정된 섹션은 그 범주의 항목만 선택지로 주는데, 해당 없음(`NONE`) 섹션에는 건강 항목만 주어져 약한 모델이 관계없는 칸을 건강 항목으로 채우는 약점이 있다(CF-356에서는 고치지 않음).
이 평가는 모델 응답의 정확도와 성능만 잰다. [오프라인 기입 정확도](offline-write-accuracy.md)나 [실사이트 평가 기준선](generic-autofill-evaluation-baselines.md)과 분모가 다르므로 합산하거나 직접 비교하지 않는다.
## 변경 이유
실사이트 반복 측정은 공고 마감과 화면 변경 때문에 같은 입력으로 다시 잴 수 없고, 모델·프롬프트·배치 설정을 같은 분모로 비교할 방법이 없었다.
