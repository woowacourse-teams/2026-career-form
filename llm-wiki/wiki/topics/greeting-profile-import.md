## 현재 상태

Greeting 가져오기는 기본 인적사항·연락처·주소, 고등학교·대학교·대학원, 경력·프로젝트, 어학·자격증, 처우·병역·보훈·장애에서 정확한 경로와 기존 프로필 목적지가 확인된 필드 전반을 지원한다. 한 화면에서 범주별 기존값을 비교하고 범주, 항목, 값 단위로 고른 뒤 저장 버튼 한 번으로 선택한 필드만 로컬에 저장한다.

비어 있던 칸을 채우는 확인된 값만 미리 선택하고, 기존 값을 바꾸는 값과 병역, 보훈, 장애 범주는 가져오기 전용 목록으로 꺼진 채로 시작한다. 이름 분리, 연월 날짜의 일자, 같은 이름의 기존 반복 항목 연결은 확인 카드로 하나씩 묻고 미룰 수 있으며, 확인하지 않은 값만 저장에서 빠진다. 중복 저장 행은 앞선 행을 남기고 개수를 안내하며, 값이나 카드에 마우스를 두거나 포커스하면 원본 칸을 강조한다. 화면 문구에는 가운데 점을 쓰지 않고 theme 토큰을 따른다.

#212 이후 가져오기는 자동 기입과 같은 실행 정책 API에 host와 pathname만 보내 Greeting 정책을 설치한 뒤 읽고, 정책이 없으면 읽지 않는다. 대학교와 대학원의 추가 전공은 보이는 구분값 하나로만 연결한다.

회사별 추가·생략 필드와 비연속 반복 인덱스를 허용하며 개별 읽기 오류·알 수 없는 필드·모호한 원본 또는 목적지는 값 없이 제외하고 정상 필드 수집을 계속한다. 제외 원인을 화면에 표시하고, 기존 자동 기입 어댑터의 안전 경계는 변경하지 않는다.

국문·영문 전체 이름은 사용자가 성·이름을 확인하고 월 단위 날짜에는 없는 일자를 만들지 않는다. 표준 옵션과 조건부 전공 상태를 검증하며, 반복 항목은 대표 이름과 새 ID로 추가하거나 같은 종류의 기존 ID에 명시적으로 연결한다. 미선택 정보와 background 단일 비교·저장 큐의 충돌 보호를 유지한다.

합성 Chromium의 다중 범주·부분 실패 흐름과 Aside 실사이트를 구분해 검증했다. 최신 LF 빌드에서 56개 원본 후보를 이름 확인 후 58개 프로필 필드로 저장·대조했고 대응 목적지가 없는 21개 제어는 제외했다. HLB에서도 기본정보 3종과 이메일만 저장 시 다른 정보 보존을 확인했다. 실제 지원서 제출·동의·인증·업로드는 실행하지 않았고 모든 Greeting 사이트 호환성이나 클릭률 개선을 입증한 것은 아니다.

## 변경 이유

실사이트에서 확인한 6종 제한을 제거하고 기존 프로필 목적지가 확인되는 범주 전반으로 확장했다. 회사별 커스텀 필드가 정상 항목 수집을 막지 않도록 읽기 실패를 격리하며, 합성 테스트와 관측한 두 실사이트의 검증 범위를 구분한다.

단계별 확인과 일괄 선택은 사용자가 다 가져오려 해도 값마다 체크하고 같은 값을 두 번 검토해야 했다. 2026-10-15 사용자 요청으로 Issue 192에 추가한 범위에 따라 한 화면 검토와 새 값 미리 선택으로 바꾸고, 기존 값 덮어쓰기와 민감 정보는 직접 켜게 해 사용자 통제를 유지했다. 저장 뒤 되돌리기는 저장 큐 변경이 필요해 범위에서 뺐다.

2026-10-15 최신 develop 병합에서 #212가 Greeting 정적 어댑터를 지우고 실행 정책을 DB로 옮겨, reader를 정책 컴포넌트로 전환하고 field-definitions에서 사라진 민감 표시를 가져오기 전용 목록으로 대신했다.
