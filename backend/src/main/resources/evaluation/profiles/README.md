# 합성 평가 프로필 v1

세 프로필은 평가를 위해 새로 작성한 가상 인물이며 실제 지원자 자료에서 추출하지 않았다.
각 JSON은 현재 확장의 `ProfileEnvelope` 형식(`schemaVersion: 1`)으로 가져올 수 있다.
프로필 ID는 파일명에서 `.json`을 뺀 값이며, 데이터셋에는 이 ID와 아래 버전, 파일 해시를 함께 고정한다.

| ID | 가상 이름 | 학력 | 어학 / 자격증 / 프로젝트 | 평가할 차이 |
| --- | --- | --- | --- | --- |
| synthetic-01-basic | 김가온 | 고등학교, 학사 졸업 | 1 / 1 / 2 | 기본 매핑, 숫자 점수, 완료한 활동, 군필 세부 정보 |
| synthetic-02-multi-entry | 이여울 | 고등학교, 전문학사, 편입 학사·복수전공, 석사 졸업예정 | 3 / 2 / 3 | 반복 행 추가, 학위·학교 구분, 문자열 어학 등급, 진행 중 활동, 민감 선택 정보 |
| synthetic-03-sparse | 박새봄 | 대입 검정고시 | 0 / 0 / 1 | 대학 이력 없음, 어학·자격증 없음, 선택 정보 미제공, 준비 동작 생략 |

## 값의 의미

- JSON에는 프로필 내용만 담는다. 평가 설명을 제품 입력 필드에 끼워 넣지 않는다.
- 비어 있는 객체와 배열은 **미제공**이다. 비대상이나 없음이라는 답으로 추정하지 않는다.
- 01은 보훈·장애 비대상을 명시하고, 02는 대상을 명시한다. 03은 병역·보훈·장애를 제공하지 않는다.
- 02의 면제 사유와 보훈번호·장애등록번호는 제공하지 않는다. 상태만 보고 세부 값을 만들어 내지 않아야 한다.
- 02·03의 진행 중 프로젝트에는 종료일이 없다. 02의 대학원 졸업일은 예상일이다.
- 모든 이메일은 `example.com` 예시 주소다. 전화번호, 집 주소, 등록번호, 계정, 증빙 파일 경로는 넣지 않았다.
- 학교·자격증·시험은 실존 명칭을 사용한다. 해당 인물의 재학·취득 이력과 성적·날짜는 합성 값이다. 고등학교는 대전고등학교와 인천고등학교를 사용한다.
- `identity`의 카탈로그 선택 인증값은 만들지 않았다. 학교 검색이 필요한 화면은 사람이 준비하고, 실제 선택 결과와 후속 입력을 별도로 수집한다. 학교명 검색 결과와 카탈로그 일치는 수집 시 별도로 확인한다.
- `careers`, `publications`, `compensation`, `health`는 비워 두었다. 초기 평가의 프로필 범위를 확장하지 않는다.

## 다음 수집에 사용할 때

1. 세 파일의 내용과 다양성을 사람이 검토한다. 현재는 **프로필 초안**이며 데이터셋 정답 검토나 입력 동일성 검토를 통과한 자료가 아니다.
2. 처음에는 01로 우아한형제들 양식 하나의 요청 수집 경로를 확인한다. 이후 동일 양식에 02·03을 적용해 반복 개수와 누락 정보에 따른 요청 차이를 수집한다.
3. 실제 기입 없이 제품이 생성하는 준비·매핑 요청을 확보한다. 필요한 화면 선택·행 추가는 사람이 수행한다.
4. 프로필에 값이 없는 필드와 양식에서 지원하지 않는 필드를 구별해 정답 라벨을 작성한다. 민감 항목의 제품 동의·확인 절차도 유지한다.
5. 이 세 개는 우선 튜닝용 후보로 취급한다. 최종 평가용으로 같은 인물과 값을 중복 사용하면 튜닝용과 독립된 평가라고 보고하지 않는다.

파일은 `v1/`에 보존한다. 평가에 사용한 뒤 값을 변경할 필요가 있으면 새 버전 디렉터리와 해시로 관리한다.
