# CF-98 실제 확장 실행 확인

- 확인일: 2026-09-23
- 범위: CF-98 worktree의 최신 로컬 백엔드와 실제 설치 확장, 공개 합성 양식
- 결론: **로컬 합성 양식에서 세 검색 표면의 입력과 재실행 동일값 유지가 작동했다. 실제 채용 사이트 전체 또는 Jev 검증 완료를 뜻하지 않는다.**
- 사용자 지시에 따라 추가 커버리지 실행은 중단하고 실제 동작 확인과 이 문서로 이번 작업을 마무리했다. Issue 전체 인수 완료, 커밋 또는 PR 완료 기록이 아니다.

## 실행 연결

- `python3 scripts/local.py up`으로 현재 코드의 bootJar와 로컬 이미지를 다시 빌드했다. backend와 MongoDB가 healthy 상태인 것을 확인했다. 데이터 볼륨 삭제나 마이그레이션은 실행하지 않았다.
- 서버는 기존 enable 설정이 true이고 공급자 미지정 기본값인 OpenAI를 사용하는 구성이다. 모델 설정은 `gpt-5.6-luna`였다. 키 값은 읽거나 출력하지 않았다.
- 프론트는 `VITE_API_BASE_URL=http://localhost:8080`으로 production build했다. 기존 확장 로드 경로의 생성물을 백업하고 새 산출물을 반영한 뒤 확장 관리 UI에서 다시 로드했다. 확장 ID와 프로필 저장 공간은 유지했다.
- production 산출물과 실제 로드 경로의 `content-scripts/autofill.js` SHA-256이 일치했다: `a42d01da1bc167a7a942fd186e877ec54fb543def10a8a30f448a2d9151b382b`.
- 지원서 패널은 합성 페이지의 실제 확장 플로팅 버튼으로 열었다. 확장 메시지/API 직접 호출, storage 주입, readonly 값 직접 쓰기로 성공을 만들지 않았다. Aside 브라우저 도구로 UI를 조작했고, Aside CLI `repl`에서도 최종 결과를 다시 읽었다.

## 정상 입력과 재실행

대상은 `frontend/fixtures/generic-search/surfaces.html?apply=1`이다. `apply` 쿼리는 기존 확장 플로팅 버튼의 표시 조건을 만족시키기 위한 로컬 URL이며 정책 host를 위조하지 않는다.

실제 프로필 관리 UI에서 `profile-export.generic-search.single-university.json`을 가져왔다. 화면과 프로필은 학력 한 건으로 일치하고, 소재지는 지원 표준값 `region:seoul`이다.

| --- | --- | --- |
| 학교명 | modal dialog 안의 동일 출처 iframe, 검색어와 비제출 검색 버튼 | 결과 선택 후 readonly 표시값 반영, dialog 종료 |

## 실제로 확인한 보류 사례

1. 기존 예시 프로필의 전공명과 합성 목록의 전공명이 정확히 일치하지 않은 실행은 결과를 임의 선택하지 않았다. 소재지 한 건 성공, 학교명 한 건 동일값 유지, 전공 한 건 확인 필요로 표시됐다. 정확히 일치하는 검색 결과가 없다는 이유가 나타났다.
2. 학력 두 건짜리 프로필을 한 행 화면에 사용한 실행은 새 입력 없이 입력 불가로 남았다. 행 연결 안전장치를 완화하지 않았다.
3. 기존 합성 프로필의 `가상지역`은 지원 표준값이 아니어서 소재지 입력이 보류됐다. 단일 행 검증용 프로필을 별도로 만들고 지원 표준값으로 명시했다. 실제 사용자 값을 추정하거나 기존 프로필을 영구 수정한 것이 아니다.

## 실제 CJ 작성 화면 부분 관측 (2026-09-23)

- 대상: 사용자가 이미 열어 둔 CJ 작성 화면. 기존 입력을 지우거나 저장·임시저장·제출·다음 단계·미리보기·새로고침하지 않았다. 사용자가 확장 사이드패널을 열고 자동 기입 흐름을 진행했으며, Aside는 실제 설치 확장의 Shadow DOM 결과와 원래 양식 상태를 읽었다. 직접 API 호출이나 DOM 값 주입을 성공 근거로 사용하지 않았다.
- 실행 연결: 활성 Career Form 확장은 CF-98 worktree의 `frontend/.output/chrome-mv3-dev`에서 로드됐고, 이 경로와 production 산출물의 content script SHA-256은 기존 기록의 `a42d01da...`와 일치했다. 실행 중인 backend 컨테이너는 healthy이고 현재 worktree bootJar 빌드 직후 생성된 이미지다. backend 소스에 해당 JAR보다 새 파일은 없었다. 이는 코드/이미지 연결의 정황이며 요청별 외부 공급자 호출 계측은 아니다.
- 경로: 패널은 `범용` 필드 분석으로 표시됐다. 프로필은 실제 인적 정보로 간주할 수 없는 예시 데이터였다. 이번 관측에서 프로필 가져오기/변경은 하지 않았으므로 새 프로필 백업·복원도 수행하지 않았다. 이 실행은 예시 프로필을 실제 지원서에 적용해도 된다는 승인이나 권장 사례가 아니다.
- 패널 집계: 분석 표시 시간 5.6초, 탐지 112개 / 프로필 연결 35개, 기입 성공 3개 / 기입 실패 0개 / 직접 확인 필요 24개 / 입력 불가 85개. 성공 3개가 어느 필드의 최종 선택 상태와 대응하는지 개별 확인되지 않아 실제 기입 성공 3건으로 확정하지 않는다.
- 우선 필드: 고등학교와 대학교 학교명은 관측 시작 전에 이미 값이 있었고 실행 후 동일했다. 고등학교·대학교 학교소재지와 대학교 전공의 표시 입력칸은 관측 전후 빈 상태로 동일했다. 검색형 세 범주의 신규 기입 성공은 확인하지 못했다. 고등학교 소재지 검색 iframe은 열린 채였고, 패널은 검색 팝업의 입력칸을 확인할 수 없어 중단했다고 보고했다. 이후 대학교 학교명·소재지·전공을 포함한 후속 항목은 `이전 검색을 확인할 수 없어 후속 자동 기입을 중단`으로 표시됐다. 이미 채워진 학교명을 동일값 재실행 성공으로 해석하지 않는다.
- 일반/반복 항목: 시작 전후 접근성 트리에서 공통으로 추적된 80개 명명된 입력/선택 control의 표시·checked 상태와 9개 `항목추가` 버튼 수는 동일했다. 다만 비노출 code, 모든 native select 실제 선택값, 성공으로 집계된 세 항목의 필드별 반영·유지는 확인하지 못했다. UI 성공 집계와 실제 선택 상태가 완전히 대조된 결과가 아니다.
- 실패 단계: 검색 opener 이후 고등학교 소재지의 검색 입력칸 인식 단계에서 멈췄다. 추가 확인에서 국가 선택은 한국이었고, 검색 입력칸 없는 지역 목록에 17개 선택 링크가 보였다. 목록에는 generic 결과 표면 판정에 쓰는 접근성 label이 없어 `existing-options`에 진입하지 못했고, UI에는 입력칸 없음으로 표시됐다. 별도로 결과 전체 개수·완료 표지도 없었다. `서울`과 `서울특별시`의 학교 소재지 별칭은 코드에 정의돼 있으나, 지역 링크 17개 모두 `javascript:` callback 방식이므로 표면 인식만 고쳐도 현행 안전 정책상 선택할 수 없다. 회사 callback/JavaScript URL을 실행하거나 직접 값을 쓰지 않았다. 후속 쓰기 중단 경계를 보존했으며 버그 수정·추가 검사·재빌드는 하지 않았다.
- 재실행/복원: 열린 검색 화면의 미확정 상태와 예시 프로필 때문에 재실행하지 않았다. 프로필은 이번 작업에서 변경하지 않았으며, 비교 가능한 표시 입력과 반복 control 수는 유지됐다. 검색 화면은 자동으로 닫거나 되돌리지 않았고, 비노출 상태의 원상복구까지 확인된 것은 아니다. 사용자 확인 없이 시험 입력을 강제로 복원하거나 기존 값을 덮어쓰지 않았다.

이 절은 앞선 `남은 범위`의 CJ 전체 미검증 문구를 **부분 관측**으로 갱신할 뿐, 합성 화면의 세 필드 성공을 CJ 성공으로 옮기지 않는다. CJ 검색형 성공, 안전한 재실행, 완전한 복원은 미검증이다.
## 공통 검색 결과 링크 보완 및 합성 확장 검증 (2026-09-23)

- 앞 절의 CJ 관측 이후 별도 작업이다. CJ host·callback 이름을 하드코딩하지 않고, 검색 표면의 소유 관계와 결과 유일성·현재 필드 재확인·반영값 및 팝업 종료 검증을 유지했다. `javascript:` 결과는 표시 라벨과 동일한 리터럴을 포함하는 **단일 함수 호출 링크**만 후보로 인정한다. 검증 직전 링크를 일회용 표지로 묶고, 해당 프레임의 페이지 실행 영역에서 같은 원래 링크를 한 번 `.click()`한다. 주소 문자열을 평가하거나 회사 함수를 직접 호출하지 않는다. 변경된 href/라벨, 중복 표지, 위험 동작 또는 반영 실패는 중단한다.
- 검색어 없는 국내 학교 소재지 목록은 같은 출처 iframe, 한국 국가 선택, 정확히 17개 국내 지역 전체, 단일 결과라는 증거가 있을 때만 취급한다. `서울`/`서울특별시` 및 `경기`/`경기도`처럼 표준값의 명시적 별칭만 사용한다. 모든 사이트의 임의 JavaScript 링크를 허용하는 일반 우회가 아니다.
- 합성 fixture `frontend/fixtures/generic-search/queryless-region.html`에는 저장·제출 기능이 없다. 기존 예시 프로필의 고등학교·대학교 두 행과 화면을 맞췄고, 프로필을 가져오거나 변경하지 않았다. 브라우저에 활성화된 실제 확장은 `.output/chrome-mv3-dev`에서 로드됐으며 production 산출물을 그 경로에 반영한 뒤 확장 관리 UI에서 다시 로드했다. 두 경로의 `autofill.js` SHA-256은 `c18cbfafc4029c8f25ce359e96945adf533fa7ab5f4b5968987649c695ef9e18`로 동일하다.
- 진단 코드를 제거한 fixture에서 확장 플로팅 버튼을 열어 실행했다. 처음 빈 소재지 두 개가 각각 `서울특별시`, `경기도`로 반영됐고, 열린 dialog는 0개였다. 패널은 탐지 6 / 연결 4, 신규 성공 2 / 실패 0 / 확인 필요 0 / 입력 불가 2를 표시했다. 기존 학교명 두 값은 변경하지 않았다. 검색 결과 링크의 일반 UI 클릭 외에 readonly 값이나 hidden 값을 직접 쓰지 않았다.
- 같은 로컬 양식을 재실행했을 때 소재지 두 값과 닫힌 팝업 상태는 유지됐지만, 패널은 소재지 두 항목을 `승인하지 않아 건너뜀`으로 직접 확인 필요에 넣었다. 따라서 재실행을 완전한 UI 성공으로 기록하지 않는다. 실제 CJ 작성 화면의 신규 선택·저장·제출·완전 복원은 **미검증**이며, 예시 프로필을 실제 지원서에 쓰지 않았다.
- `frontend/src/autofill/interaction` 157개 테스트 통과, 수정된 주변 API·쓰기 테스트 84개 통과, 프론트 typecheck 및 `VITE_API_BASE_URL=http://localhost:8080` production build 통과. 타입 검사를 막던 기존 테스트 fixture의 필드명·필수 메타데이터·결과 식별자 타입만 현재 계약에 맞췄다. 전체 프론트/백엔드 테스트나 실제 CJ 성공을 이 수치로 대체하지 않는다. 커밋·push·PR은 하지 않았다.

## CJ 자동 기입 재실행 및 새 빌드 확인 (2026-09-23, 후속 관측)

이 절은 위의 과거 관측 이후 사용자가 실제 자동 기입과 새로고침을 별도로 승인한 실행 결과다. 위 절의 당시 `실제 CJ 값 수정 없음`, `신규 선택 미검증` 서술을 현재 상태로 확장해서 읽지 않는다. 프로필은 비식별 예시였고, 값·계정·세션 URL·실행 selector는 기록하지 않는다.

- 이전 개발 산출물로 실행한 검색에서는 고교 또는 대학 소재지의 표시값이 실제 양식에 반영된 경우가 있었으나 확장은 iframe 종료를 `surface_navigation_unsafe`로 판정하고 후속 쓰기를 중단했다. 값 반영만으로 성공을 인정하지 않았다.
- 수정된 소스를 개발 산출물로 다시 빌드하고 Chrome 확장을 재로드했다. 사용자가 미저장 입력의 처리 여부를 결정하고 CJ 작성 화면을 직접 새로고침했다. 재실행 시작 전 두 소재지 칸은 공란이었다.
- 새 빌드의 실제 확장 버튼 실행은 범용 분석에서 112개 탐지·37개 프로필 연결, 3개 성공·0개 실패·26개 직접 확인 필요·82개 입력 불가로 표시됐다. 고교 소재지의 결과 활성화가 `result_activation_unsafe`로 중단돼 검색 화면이 열린 채 남았고, 고교·대학 소재지 값은 모두 공란이었다. 대학 검색과 후속 쓰기는 진행되지 않았다. UI의 3개 성공을 학교 소재지 성공으로 취급하지 않는다.
- 별도 비식별 localhost iframe에서는 동일한 MAIN-world 요청/응답 브리지의 원본 링크 클릭을 관측했다. 이는 실제 CJ 실패 원인을 규명하거나 격리된 content-script 요청 경로의 사이트별 성공을 증명하지 않는다. 임의 callback 직접 호출, readonly/hidden 값 강제 입력, 재클릭은 하지 않았다.
- 프론트 기본 병렬 테스트는 부하 상황에서 14개 파일이 실패했으나 `npm --prefix frontend test -- --maxWorkers=2 --testTimeout=10000` 재실행에서 1,198개 통과·19개 건너뜀으로 끝났다. 백엔드 `./gradlew --no-daemon --max-workers=2 check`도 통과했다. CJ 검색 실패와 Jev 실제 공급자 호출 미검증은 그대로 남는다.
- 사용자 요청에 따라 Issue #98은 검증된 동일 출처 원본 JavaScript 링크의 제한적 MAIN-world 1회 클릭을 허용하도록 수정됐다. 이 계약 변경 자체가 실제 CJ 성공의 근거는 아니다. 이번 후속 관측에서도 AI는 실제 지원서 저장·제출·다음 단계·미리보기를 실행하지 않았다.

### 같은 CJ 화면의 이후 상태 확인 (2026-09-23)

사용자가 실제 CJ 화면에서 소재지 입력이 잘 됐다고 알린 뒤, 같은 열린 탭을 읽기 전용으로 다시 확인했다. 앞서 공란으로 기록한 고교·대학 소재지 표시칸은 **둘 다 채워져 있었고** 학교소재지 검색 iframe은 남아 있지 않았다. 따라서 바로 앞 절의 `두 값 공란` 및 `검색 화면 열림`은 이전 실행 시점의 기록일 뿐 현재 화면 상태가 아니다. 이번 상태 확인만으로 어떤 중간 실행이 각 값을 넣었는지, 확장 패널이 두 항목을 성공으로 판정했는지, 숨은 코드나 서버 저장값까지 맞는지 독립 검증하지 못했다. 실제 저장·제출·다음 단계·미리보기는 AI가 실행하지 않았다.
