# 자동 입력 품질 관측과 필드 수 확인

CF-164는 기존 분석 API의 schemaVersion 2 응답을 유지하면서 요청 관측, 브라우저 결과 보고, 사람 확인 목록과 일별 집계를 추가한다. 기능은 기본으로 꺼져 있다. 운영 설정과 배포는 사람이 수행한다.

## 수집과 해석

서버는 실제 라우터 선택을 STATIC, GREETING, GENERIC과 차단 사유로 기록한다. 실제 외부 호출은 별도로 센다. 범용 경로를 선택했지만 AI를 호출하지 못한 요청은 AI 호출 수를 증가시키지 않는다.

요청 수집 후보와 실행의 고유 칸 수를 구분한다. 재분석 후보는 브라우저가 같은 DOM 제어에 부여한 실행 내 임의 식별자를 보고한 경우에만 합친다. 서버는 이미 분석한 snapshot과 candidate 소속을 검사하고 식별자는 해시로 저장한다. 여러 snapshot의 대응이 미확인인 실행은 `DEDUPLICATION_UNOBSERVED`로 표시하고 고유 칸 비율에서 제외한다. 클라이언트 보고는 실제 입력이나 정답을 인증하는 증거가 아니다.

| 지표 | 분자와 분모 |
|---|---|
| 매핑률 | 서버 매핑 후보 / 요청 수집 후보 |
| 값 준비율 | 보고된 값 준비 칸 / 보고된 매핑 칸 |
| 입력 성공률 | 값 반영 확인 칸 / 입력 시도 칸 |
| 1초 유지율 | 1초 뒤 유지 확인 칸 / 값 반영 확인 칸 |
| 수집 대비 유지율 | 유지 확인 칸 / 보고된 수집 칸 |
| 사람 기준 커버리지 | 범위가 대응되는 실행의 각 단계 칸 수 / 사람 확인 분모 합 |

비율은 건수를 합산해서 계산한다. 분모가 0이면 null이다. 필요한 입력·유지 결과나 중복 제거 대응이 미관측이면 전체 비율은 null이며, 실제 관측 결과만의 비율을 별도로 제공한다. 결과 보고가 없는 실행은 마지막 관측 후 30분까지 진행 중이고 이후 미관측으로 판정한다. 늦은 보고는 이전 실행 기여분을 교체한다.

원문 라벨, DOM ID와 name, 원본 경로, 입력값과 프로필 값은 품질 데이터에 저장하지 않는다. 화면 구조는 제어 종류, 제한, 반복 관계와 정제된 의미 구조의 해시다. 버전은 백엔드, 확장, 정책, 실제 관측된 모델과 관측 계약 정보를 포함한다. 없는 정보는 UNKNOWN으로 남는다.

## 관리 화면

HTTPS의 `/quality/`에서 공용 비밀번호로 로그인한다. 회원가입과 개인 계정은 없다. 담당 별칭은 개인 인증을 뜻하지 않는다. 인증 설정이 없으면 화면을 공개하지 않는다.

TLS 종료 프록시를 사용하는 경우 운영자가 신뢰할 프록시의 전달 헤더만 백엔드에 도달하도록 구성한다. 백엔드 포트의 직접 외부 접근을 막고 원래 HTTPS 주소와 포트가 전달되는지 확인한다. 프록시 설정과 외부 주소 공개는 이 변경에서 배포하지 않는다.

- 서버 세션은 8시간이며 로그아웃과 비밀번호 검증 설정 변경으로 무효화된다. 인증과 담당 쿠키는 Secure, HttpOnly, SameSite=Strict다. CSRF 쿠키는 새 탭에서도 쓰기 요청을 할 수 있도록 자바스크립트가 읽을 수 있으며 인증에는 사용하지 않는다.
- 쓰기 요청은 서버 세션과 CSRF를 검사한다. 비밀번호 실패는 출처별 10분 동안 5회까지 허용하며 출처 원문은 저장하지 않는다.
- 담당 식별자는 서버가 별도로 발급하고 24시간 유지한다. 다른 팀원이 담당 중인 후보는 수정할 수 없다. 만료, 담당 해제와 보류 재개 후 다시 담당할 수 있다.
- 전체 미확인 목록에서 오늘 선정 외 후보도 완료할 수 있다. 완료 목록에는 필드 수, 확인일과 수정 이력이 남는다. Discord의 후보 링크는 목록 페이지 밖의 후보도 직접 연다.
- 공개 작성 링크를 모르면 사이트 홈을 연다. 작성 링크는 같은 호스트의 HTTPS 주소만 허용하고 query, fragment, 계정 정보와 토큰 형태의 경로는 거부한다.

같은 화면에서 프로필 값이 준비되어 있고 자동 입력을 허용할 수 있는 칸을 센다. 잠긴 칸, 파일 업로드와 동의 항목은 제외한다. 연·월·일 제어는 각각 센다. 한 답을 받는 radio 또는 checkbox 그룹은 한 칸이다. 반복 행의 현재 개수도 같아야 한다.

사람 등록은 필드 수만 확인하므로 **사람 확인 분모, 정확도 미검증**으로 표시한다. 정답 매핑, 정확도, 재현율이나 오입력률로 해석하지 않는다. 100%를 넘거나 화면 범위가 다르면 범위 불일치다. 같은 구조에서 확인 이후 시작한 실행에만 분모를 적용하며 과거 실행을 소급 평가하지 않는다. 앱 버전만 바뀌고 구조가 같으면 재사용할 수 있다.

공유 ATS 호스트의 기업 소속이 미확인인 요청은 임의로 합치지 않는다. 회사 정책이나 Greeting tenant로 구분하거나, 사람이 해당 호스트와 화면 구조가 한 기업을 구분한다고 확인한 이후 재사용한다. 구조가 바뀌면 새 재확인 후보를 만들고 완료 이력을 보존한다.

## 평일 확인 요청

Asia/Seoul 평일 09:20에 당일 batch를 저장한다. 재시작 시 당일 09:20 이후의 미처리 batch만 복구하고 주말이나 지난날 알림을 따라 보내지 않는다. 공휴일 달력은 적용하지 않는다.

활성 미완료와 자발적 담당을 포함해 신규 선정 여력은 최대 5개다. 오래된 대기를 최대 2개 먼저 배정하면서 STATIC → GREETING → GENERIC 순환 위치를 보존한다. 나머지는 최근 데이터에서 낮은 입력 성공률, 낮은 매핑률, 사용량 순으로 고른다. 미관측 입력 결과를 실패율 선정 근거로 쓰지 않는다. 동률은 관련 표본 수 내림차순, 첫 대기일과 후보 ID 오름차순이다.

새 후보가 없어도 미완료 목록을 안내한다. 처리 가능한 후보가 없으면 `오늘 확인할 사이트가 없습니다.`와 전체 목록 링크를 보낸다. 보류 후보는 따로 표시하며 기본 보류는 7일이다.

전용 Discord 웹훅만 사용한다. `wait=true`의 성공 응답에서 메시지 ID를 받은 경우만 SENT다. 명확한 429는 최대 3회 재시도하며 개별 대기는 최대 10초다. timeout, 전송 결과가 불명확한 오류와 전송 중 중단은 UNKNOWN이며 자동 재전송하지 않는다. 정확히 한 번 전달됐다고 보장하지 않는다. 미설정과 전송 거부는 성공이나 후보 완료로 처리하지 않는다.

일반 메시지 2000자를 넘으면 한 개의 embed 설명으로 동일한 목록을 보낸다. 최대 4096자를 넘는 메시지는 거부하고 모든 알림에서 자동 멘션을 끈다. 잘못된 웹훅 설정 오류에는 원본 URL을 포함하지 않는다.

## 사람이 설정할 값

| 환경변수 | 기본값과 역할 |
|---|---|
| `CAREER_FORM_QUALITY_ENABLED` | false, 수집·관리 기능 활성화 |
| `CAREER_FORM_QUALITY_VERSION` | UNKNOWN, 배포한 백엔드 버전 |
| `CAREER_FORM_QUALITY_PASSWORD_HASH` | 공용 비밀번호 검증용 PBKDF2 설정 |
| `CAREER_FORM_QUALITY_QUERY_TOKEN_HASH` | Grafana 전용 조회 토큰의 SHA-256 hex |
| `CAREER_FORM_QUALITY_MANAGEMENT_URL` | 외부 HTTPS 관리 화면의 `/quality/` 주소 |
| `CAREER_FORM_QUALITY_DISCORD_ENABLED` | false, 전용 확인 요청 활성화 |
| `CAREER_FORM_QUALITY_DISCORD_ENVIRONMENT` | prod, 알림을 보내는 환경 하나 |
| `CAREER_FORM_QUALITY_DISCORD_WEBHOOK` | 새 채널의 전용 Discord 웹훅 |
| `CAREER_FORM_QUALITY_SELECTION_DAYS` | 7, 후보 선정에 사용하는 최근 일수 |
| `CAREER_FORM_QUALITY_SELECTION_MINIMUM_SAMPLE` | 20, 비율 선정의 최소 분모 |

비밀번호 검증 형식은 `pbkdf2-sha256$반복수$base64 salt$base64 digest`다. PBKDF2-HMAC-SHA256, 반복수 600000~2000000, salt 16~64바이트, digest 32바이트를 사용한다. 실제 비밀번호, 검증 설정, 조회 토큰과 웹훅은 저장소와 문서에 적지 않는다. 확장에는 관리 비밀번호나 Grafana 조회 토큰을 넣지 않는다.

확장은 분석 헤더의 `quality-v1` 기능 협상을 사용한다. 서버가 발급한 보고 토큰은 백그라운드의 해당 문서·실행에만 보관하며 관리 API에 사용할 수 없다. 유효 기간은 24시간이고 원문은 저장하지 않는다. 실행당 200개 이벤트, snapshot당 최대 2000개 후보와 보고당 128KiB를 검사한다. 보고는 여러 칸을 묶어서 보내며 같은 이벤트 재전송은 멱등이다. 구형 서버·확장과 계측 실패는 기존 입력 흐름을 유지한다.

## 보존과 집계 조회

상세 요청·실행은 생성 후 30일, KST 일별 집계는 기준일 후 90일까지만 조회한다. TTL 정리가 늦어져도 만료 자료는 조회에서 제외한다. 사람 확인과 후보 및 발송 이력은 자동 만료하지 않는다. 상세가 남아 있는 동안 시간별 복구 작업이 누락된 후보·집계를 멱등 반영한다. 기존 Loki 7일과 Prometheus 14일 설정은 유지한다.

`GET /api/v1/quality/stats`는 관리 세션 또는 집계 전용 Bearer 토큰으로 조회한다. `site`, `structure`, `route`, `version`, `from`, `to`와 `groupBy=ROUTE|FULL|SITE_ROUTE_VERSION|VERSION_TREND`를 지원한다. 기간은 KST 일별 범위로 반올림하고 최대 90일이다. 500개 그룹을 넘으면 필터를 좁히라는 오류를 반환한다. 상세 실행과 보고 토큰은 제공하지 않는다.

P95는 고정 버킷의 근사 상한값이다. 버킷은 50, 100, 250, 500, 1000, 2500, 5000, 10000, 20000, 30000, 60000, 120000ms와 상한 초과다. 시간 표본과 상한 초과 수를 함께 제공하며 P95 위치가 상한을 넘으면 null이다.

## 검증 범위

자동 검증은 합성 MongoDB, 합성 페이지, 통제된 시계와 모의 응답을 사용한다. 실제 지원서나 운영 Discord를 호출하지 않는다. 운영 담당자는 HTTPS와 프록시 설정, 새 채널의 메시지 수신, 링크 접근과 없음 안내를 실제 환경에서 별도로 확인한다.
