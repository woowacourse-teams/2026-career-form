# DOM Snapshot Collection

실제 실패 페이지의 최소 구조를 정제해 오프라인 재현에 사용하는 절차다.
범용 자동 수집기나 제품 버그 수정 기능은 아니다.

## 기준 문서

실행 전에 아래 두 파일을 읽는다. 보존·제거 기준과 메타데이터의 정본은 정책이며,
이 스킬은 그 절차를 실행하는 진입점이다.

- [비식별 DOM 스냅샷 수집 정책](../../../harness/policies/dom-snapshot-fixtures.md)
- [수집·검토 기록 양식](../../../harness/templates/dom-snapshot-review.md)

## 시작과 재개

1. 사람이 준비한 회사·플랫폼, 실패 영역, 기대 결과·관찰 결과와 이번 수집 의사를
   확인한다. 실제 값이나 계정·지원서 URL을 요청하지 않는다.
2. 대상이 없으면 사이트와 실패한 필드만 질문하고 멈춘다. 열린 탭만 보고
   대상을 고르거나 전체 페이지를 먼저 수집하지 않는다.
3. 기존 검토 기록이 있으면 마지막으로 확인된 단계부터 재개한다.
   미수집·미검토·미재현 상태를 완료로 바꾸지 않는다.
4. 재현에 필요한 최소 control·라벨·소유 컨테이너·반복 행을 정한다.
   필요한 화면 상태는 사람이 직접 준비한다.
5. 설치본 revision을 확인할 수 없으면 `UNVERIFIED`로 기록한다.
   작업 디렉터리 HEAD나 버전 문자열로 설치본 증명을 대신하지 않는다.

평가 실행 승인은 수집 승인이 아니다. 수집 요청도 자동 입력 평가, 페이지 이동,
저장·제출·미리보기·파일 첨부·동의 또는 브라우저 저장소 접근을 승인하지 않는다.

## 출력 전 비식별화

1. 사용할 브라우저 도구가 원본 DOM·접근성 트리·화면·Console·네트워크를
   자동 저장하지 않는지 연결 전에 확인한다. 보장할 수 없으면 연결하거나
   원본을 반환하지 않고 수집을 중단한다.
2. 사람이 페이지 안에서 공통 양식 텍스트와 최소 범위를 검토한다.
   이번 대상의 허용 목록과 일회성 추출 코드·도구 동작도 실행 전에 검토받는다.
3. 원본 DOM을 변경하거나 통째로 복사하지 않는다. 브라우저 안의 새 비활성
   문서에 검토된 태그·속성·텍스트만 옮긴다.
4. 실제 값·선택 상태·개인화 문구·숨김 데이터·URL·스크립트·외부 리소스는
   정책에 따라 제거한다. ID를 치환하면 참조 관계도 함께 치환하고 대응표는
   브라우저 메모리에만 둔다. 필요한 상태는 명시적인 합성 상태로 넣는다.
5. 브라우저 안에서 금지 정보 부재와 control 수·종류·라벨·소유·참조 관계를
   검사한다. 실패하면 종류만 반환하고 원본 문자열이나 예외 객체는 출력하지 않는다.
6. 통과한 정제 결과만 Git 비추적 임시 위치로 출력한다. 원본 반환 후 정제,
   원본 화면 촬영, Console 복사로 대체하지 않는다.

## 사람 검토와 오프라인 재현

1. 검토 양식에 정제한 범위, 제거·치환한 정보 종류, 합성 상태와 누락 동작을
   기록한다. 실제 원문·URL·식별자 대응표는 넣지 않는다.
2. 정제 결과의 개인정보 잔존 여부와 실패 조건의 구조 보존을 사람이 각각
   검토한다. 자동 검사 결과만으로 승인 처리하지 않는다.
3. 정제 샘플을 네트워크가 차단된 로컬 브라우저에서 열어 외부 요청 시도
   0건을 확인한다. 실제 계정·회사 서버·외부 LLM에 의존하지 않는다.
4. 실패 단계의 기존 제품 함수와 테스트 체계를 사용해 현재 처리 결과를
   재현한다. 기대 동작과 현재 실패를 구분하며 제품 코드를 여기서 수정하지 않는다.
5. 테스트는 구조·관계·처리 결과를 검사한다. HTML 전체나 문서 문구를 고정하지
   않는다. 필요한 구조를 일시적으로 변경했을 때 검사가 실패하는지 확인하고 복원한다.
6. 정적 샘플로 재현할 수 없으면 누락된 동작과 이유를 적고 등록을 보류한다.
   원본에 없던 관계·marker·이벤트를 추가해 실제 구조라고 주장하지 않는다.
   별도 합성 동작은 출처와 한계를 명시한다.

## 등록과 종료

1. 사람 검토와 오프라인 재현이 모두 끝난 경우에만
   `frontend/fixtures/dom-snapshots/<fixture-id>/`에 정제 HTML,
   정책의 `metadata.json`, 검토 기록을 등록하고 관련 테스트에서 사용한다.
2. 직접 정제한 `SANITIZED_SNAPSHOT`과 관찰 후 재작성한
   `SYNTHETIC_REPRODUCTION`을 구분한다. 합성 재현만으로 실제 스냅샷 수집을
   완료했다고 기록하지 않는다.
3. 관련 테스트와 현재 Issue가 요구하는 검증을 실행한다. 단계별 관측 결과,
   실행 명령·제품 코드 revision, 변이 검사와 미재현 범위를 기록한다.
4. 원본 대응표와 페이지 내부 임시 참조를 폐기하고 작업 소유 서버·브라우저와
   임시 검토 파일만 정리한다. 사용자가 연 원본 페이지는 닫거나 변경하지 않는다.
5. 최종 판정을 `등록 가능`, `보류`, `수집 중단`으로 구분해 보고한다.
   `FIXTURE` 결과를 `LIVE_SITE` 성공률이나 저장·제출 호환성으로 확대하지 않는다.

수집 승인, 출력 전 허용 검토, 등록 전 사람 검토, Wiki 지식 후보 승인은 별개다.
이 스킬 실행만으로 커밋·push·PR 게시 또는 Wiki 기록을 승인받았다고 간주하지 않는다.
