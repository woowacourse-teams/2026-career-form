# LLM Wiki Query

프로젝트에 축적된 지식에서 질문과 관련된 현재 근거를 찾아 읽기 전용으로 답한다.
Wiki 검색 결과는 후보이며, 현재 정답 여부는 topic 상태와 연결 raw로 판단한다.

## 라우팅

질문의 답이 이 저장소의 제품 기준, 결정, 정책, 용어 또는 누적 작업 맥락에 따라
달라질 때 사용한다. 현재와 과거 결정의 비교, 변경 이유와 특정 Issue, ADR, 회사
어댑터 식별자 조회도 포함한다.

다음 요청에는 사용하지 않는다.

- 프로젝트 결정과 무관한 일반 기술 지식
- 최신 외부 정보
- 사용자가 지정한 파일의 일회성 요약
- 현재 코드 상태만 조사하면 되는 질문
- Wiki 지식의 수집, 갱신 또는 구조 점검

질문의 일부만 프로젝트 의존적이면 그 부분에만 Wiki 근거를 사용하고 일반 설명과
구분한다.

## 근거 우선순위

현재 작업에 확정된 Issue 계약이 있으면 그 범위와 완료 기준을 먼저 따른다. 위치에
의존하는 `AGENTS.md`와 하네스 정책은 해당 파일의 현재본이 우선한다. 그 밖의 제품,
기술, ADR과 컨벤션 지식은 다음 순서로 확인한다.

1. `llm-wiki/wiki/index.md`와 `llm-wiki/wiki/topics/`에서 관련 topic 후보를 찾는다.
2. topic의 `Status`와 `Current`를 확인한다.
3. `Current`가 연결한 raw 원문을 읽고 답변 근거로 사용한다.
4. 과거 상태나 변경 이유를 묻는 경우에만 `History`와 관련 raw를 읽는다.
5. 현재와 과거의 관계가 불분명하면 Issue manifest의 `Supersedes`를 확인한다.

topic 요약만으로 답을 확정하거나 검색 순위를 정본 순위로 해석하지 않는다.

## 탐색

처음부터 Wiki 전체를 읽지 않는다. 질문에서 핵심 개념과 정확 식별자를 나눈 뒤
`rg`로 index와 topic을 좁힌다. Issue 번호, ADR 이름, 회사명, 파일명 같은 식별자는
정확 검색하고, 일반 개념은 관련 표현을 추가해 후보를 찾는다. 후보 topic과 연결된
raw만 읽는다.

후보가 여러 개면 질문의 의도, topic 상태, `Current`와 `Supersedes` 관계로 좁힌다.
벡터 검색, 임베딩과 FTS 인프라가 있다고 가정하지 않는다.

## 상태별 답변

- `Current`: 연결된 current raw를 확인한 뒤 현재 기준으로 답한다.
- 과거 질문: 현재 기준과 과거 기준을 시점 및 근거별로 나누고 변경 이유를 표시한다.
- `Disputed`: 대체되지 않은 근거를 각각 제시하고 하나를 임의로 선택하지 않는다.
- 근거 공백: 검색한 범위와 확인하지 못한 내용을 밝히고 프로젝트 결정을 추측하지 않는다.
- Wiki 비대상: Wiki를 억지로 조회하지 않고 요청에 맞는 일반 조사 방식으로 처리한다.

근거끼리 충돌하는데 topic 상태가 `Current`라면 current raw와 충돌 근거를 함께
밝히고 topic 또는 manifest의 계약 위반 가능성을 보고한다. 파일을 고쳐 충돌을
숨기지 않는다.

## 출력과 안전 경계

핵심 답을 먼저 제시하고 각 프로젝트 고유 주장 가까이에 실제로 읽은 topic과 raw의
저장소 상대 경로를 적는다. 확인된 현재 기준, 과거 결정, 충돌과 근거 공백을 서로
구분한다.

이 스킬은 읽기 전용이다. raw, topic, index와 log를 수정하지 않는다. 지식 보강이
필요해도 자동으로 수집하거나 `cf-karpathy-llm-wiki`를 실행하지 않고 공백과 필요한
후속 작업만 제안한다. 실제 지원 정보, 계정, 세션과 시크릿을 읽거나 답변 근거로
기록하지 않는다.
