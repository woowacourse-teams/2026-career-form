# 프론트 회사 어댑터

백엔드 정책은 **어떤 프로필 항목을 연결하고 어떤 입력 명령을 허용할지** 결정한다.
프론트 회사 어댑터는 **해당 회사 화면을 수집하고 특수한 입력을 실행하는 방법**을 제공한다.
실제 프로필 값은 브라우저 안에서 결합한다.

## 코드 읽는 순서

1. `workflow/execution-policy.ts`: 서버에서 받은 실행 정책을 현재 문서에 연결한다.
2. `company.ts`: DB 실행 정책의 종류에 따라 `policy` 또는 `components` 실행기를 선택한다. 도메인으로 프론트 실행기를 고르지 않는다.
3. `collection.ts`, `workflow.ts`, `write.ts`: DB 정책에 맞는 실행기를 선택한다.
4. `../policy/`: 라디오·선택·검색 등의 정책 실행기다. `components/`는 ARIA 컴포넌트 실행기이며 그리팅 필드명·선택지·행 규칙은 DB에서 받는다.
5. `../policy/hidden-code/`: 숨은 코드와 화면 선택값을 함께 검증하는 실행기다. 현대차에서 사용하는 선택자, 코드 표, 프로필 연결, 전환 규칙은 서버의 `hyundai-browser-v1.json`에서 초기화된 DB 데이터로 받는다.

`sk/`, `hyundai/`에는 회사별 테스트와 fixture만 남아 있다. 실제 수집·기입은 DB 정책 기반 공통 실행기로 연결하며, 테스트도 공통 진입점을 사용한다.

공통 DOM 수집은 snapshot과 후보 registry를 만들고 워크플로는 API 호출과 실행 순서를 관리한다. 실제 프로필 값은 브라우저 안에서 결합한다.

## 정책 추가와 변경

- 회사 식별, fingerprint, 준비 동작, 필드 매핑과 실행 정책을 백엔드 DB에 등록한다.
- 기존 실행기가 지원하는 선택자·코드·전환 값은 DB 데이터로 바꾼다. 새로운 종류의 위젯 동작은 공통 실행기에 기능을 추가해야 한다.
- hidden-code 계약은 실행 가능한 스크립트가 아니다. `contract.ts`가 검증·복원하는 Map, Set, 정규식, 문자열 템플릿과 데이터로 구성된다.
- 계약 v2는 `contract-schema.json`으로 데이터 타입을 검사한다. 규칙 목록·코드 표·조건 목록의 길이는 고정하지 않는다. 지원하는 연산 안에서 항목과 조건을 추가하는 것은 DB 변경으로 처리한다. 새로운 연산 종류는 실행기와 스키마를 함께 확장한다.
- 서버 시작은 없는 정책만 삽입한다. 기존 정책 변경과 활성 버전 전환은 명시적 마이그레이션으로 수행한다.
- 회사 문서와 지원 현황표 갱신은 Wiki 지식 승인 절차를 따른다.

## 특수 입력의 실패

`CompanyWriteAttempt`의 `handled: true, written: false`는 해당 회사 입력을 인식했지만 실행에 실패했다는 뜻이다.
이 결과에 일반 writer를 다시 적용하면 안 된다. 미등록 회사에서 특수 명령을 받는 경우에도 입력하지 않는다.

현재 현대 버튼 선택은 기존 동기 메뉴 동작을 이동한 구현이다. 검색 결과를 기다리거나 최종 선택 코드를 검증하는 범용 검색 기능은 아니다.
LG 학교 검색을 추가하려면 별도 계약에서 비동기 대기·취소·같은 학력 행의 대상 식별·후보의 유일성·선택 반영 확인을 정의하고 검증해야 한다.
학교명만 같은 결과 중 첫 번째를 임의로 선택하거나 검색 실패를 text 입력으로 우회하지 않는다.

## 유지한 동작과 제한

이번 분리는 기존 자동 실행 및 승인 화면 정책을 재설계하지 않는다. SK의 기존 선행 라디오 탐색과 현대 메뉴의 검색 범위·재실행 방식도 별도 개선 대상이다.
학교 검색, LG 실제 지원, 실제 페이지 수동 검증이 완료된 것으로 해석하지 않는다.

## 회귀 검증

`frontend/`에서 실행한다.

```sh
npm test -- src/autofill src/autofill-demo/AutofillOverlay.test.tsx
npm run typecheck
npm run coverage
npm run build
```

전체 검증과 최신 기록은 Issue 작업 계획을 따른다. 실제 지원서 값, 계정, 세션 및 시크릿은 테스트와 진단 로그에 넣지 않는다.
