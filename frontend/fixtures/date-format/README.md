# Synthetic date-format fixture

All markup, employer-shaped names, values and profile entries in this fixture are fabricated. It is a synthetic CJ-shaped test page only, not a real-provider page or compatibility check. Never use real profile data or submit an application.

## Automated integration (Vitest/jsdom)

`../../src/autofill/workflow/date-format.integration.test.ts` imports this HTML as raw fixture content and exercises `collectFieldsSnapshot`/`CandidateRegistry`, `buildReviewPlan`, and the approved write executors using a deterministic synthetic analysis response and synthetic profile. The automated test does not call a backend or provider. This injected analysis response is test scaffolding only, not an installed-extension offline mode.

Run from the repository root in WSL:

`PATH=/root/.nvm/versions/node/v24.15.0/bin:/usr/local/bin:/usr/bin:/bin npm --prefix frontend test -- src/autofill/workflow/date-format.integration.test.ts --maxWorkers=2`

Most recent phase-2 run: 19 cases passed. On equivalent rerun, the executor reports `written`, but the DOM value stays equivalent and no duplicate `input`/`change` events are emitted; the assertion checks those observable DOM/event behaviors. The adjacent static `DERIVED`/`YEAR_MONTH` regression, `src/autofill/adapters/sk/university-date-write.test.ts`, also passed (1 test).

## Manual installed-extension check: NOT RUN / BLOCKED

`frontend/entrypoints/background.ts` configures analysis with `import.meta.env.VITE_API_BASE_URL`; normal installed-extension analysis routes to that configured backend. A manual run requires all of these prerequisites:

- A separate CF-101 extension build (the existing installed browser extension points to CF-98 and must not be replaced, reloaded or overwritten).
- A disposable Chromium profile and synthetic-only profile context with source dates in strict `YYYY-MM-DD` form, for example `2016-03-02` and `2020-02-01`. Dotted dates shown by target fields are outputs, not source profile values.
- A reachable localhost backend/mapping service configured for the synthetic page, or a documented local substitute implementing the same analysis contract. A mocked `AnalysisApiClient` inside Vitest is not an installed-extension backend and cannot substitute for this prerequisite.

If any prerequisite is unavailable, leave the manual check **NOT RUN** and report it **BLOCKED**, naming the missing prerequisite. Do not add a runtime test bypass or use a real provider.

When unblocked and after phase 2/D are complete: build CF-101 with `VITE_API_BASE_URL=http://localhost:8080 npm --prefix frontend run build`, confirm the output directory in the build log (expected `frontend/.output/chrome-mv3`), and load it unpacked in the separate disposable profile via `chrome://extensions`. Open `synthetic-cj-shaped.html` locally, run the normal workflow against the configured local analysis service, and separately inspect review preview, pre-approval DOM, post-approval DOM/events, changed-attribute and same-id replacement rejection, and site reversion/rerun. Record only synthetic outcomes and browser/build version. Never navigate to a real application or save/submit.

## Fixture map

`synthetic-cj-shaped.html` contains repeated high-school and university rows, dotted month/full-date targets, native date/month controls, empty/equal/different current values, ambiguous and length/pattern conflicts, invalid source-date controls, post-review mutation/replacement controls, site-reversion control and one sensitive health-date field. Candidate IDs are generated by the real collector at runtime; tests identify the candidates by fixture `name` plus their collected repeated-row index.
