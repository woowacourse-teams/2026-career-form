ARCHITECTURE UPDATE

직무별 지원서 변형에도
공통 정보를 안전하게 기입하도록 바꿨음

SK Careers는 같은 회사 안에서도 공고·직무마다 조건부 영역과 필드 구성이 달랐음. 이번 변경에서는 한 조건부 영역이 달라도 전체 자동 기입이 멈추지 않게 바꿨음.

원칙: 구조가 정확히 확인된 공통 정보만 기입했고, 확인되지 않은 조건부 정보는 건너뛰게 했음.
BEFORE

기존 구조: 조건부 한 곳의 불일치가 전체를 차단했음

지원서 구조 수집
→
조건부 영역 준비
행 추가·라디오 선택
→
예상 필드명 확인 실패
→
전체 예외 처리
문제

정책이 너무 강하게 결합돼 있었음

자격·어학·학력처럼 선택적으로 나타나는 영역에서 정책의 예상 필드명이 실제 직무별 폼과 다르면, 공통 필드까지 기입하지 못했음.

사용자 증상

첫 클릭은 예외, 두 번째 클릭은 성공했음

첫 클릭에서 조건 선택 또는 행 추가는 이미 반영됐지만, 사후 검증 실패로 중단됐음. 두 번째 클릭은 변경된 상태에서 다시 시작해 기입 단계로 넘어갔음.

DIAGNOSIS

문제의 핵심은 지연이 아니라 검증 범위였음

검증 대상으로 유지했음

  • 버튼·라디오·선택값이 정책과 정확히 일치하는지 확인했음
  • 실제 선택 또는 행 추가가 수행됐는지 확인했음
  • 기입하려는 필드가 현재 화면에서 정확히 식별되는지 확인했음

전체 실패 사유에서는 뺐음

  • 직무별 폼에서 생략된 선택 영역
  • 동일한 의미지만 다른 세부 필드명으로 구성된 영역
  • 공통 필드와 독립적인 선택 정보의 미노출
“조건부 필드가 없음”을 “지원서 전체를 분석할 수 없음”으로 처리하지 않게 했음.
AFTER

변경 구조: 조건부는 부분 제외하고 공통 정보는 계속 진행했음

지원서 구조 수집
→
조건부 영역 준비
→
불일치 조건부 영역 제외
→
공통 필드 재수집·자동 기입
변경 1

부분 실패를 전체 실패로 올리지 않게 했음

조건부 예상 필드가 없으면 해당 영역만 자동 기입 대상에서 제외했고, 이미 검증된 공통 필드 분석은 계속하게 했음.

변경 2

빠르게 즉시 판정하게 했음

조건부 필드가 클릭 직후 보이지 않으면 기다리지 않게 했음. 해당 영역을 제외하고 바로 공통 필드 분석으로 전환했음.

SAFETY & RESULT

기입 대상과 제외 대상을 분리했음

자동 기입 대상으로 유지했음

  • 현재 페이지에서 정확히 식별된 필드
  • 프로필 값과 행 개수가 안전하게 대응되는 반복 항목
  • 기존 입력값과 충돌하지 않는 값
  • 정책이 허용한 텍스트·선택·라디오 입력

자동 기입 대상에서 제외했음

  • 직무별 폼에 없는 조건부 영역
  • 필드명·컨트롤 구조가 정책과 다른 항목
  • 기존 값 충돌 또는 민감정보 확인이 필요한 항목
  • 읽기 전용·시스템 계산 필드
결과 UI는 중간 1/3·2/3·3/3 화면 대신 최종 기입 결과만 보여주게 했음. 저장·이동·제출은 자동으로 실행하지 않았음.
VERIFICATION

검증과 운영 기준을 정리했음

자동 검증을 추가했음

  • 조건부 예상 필드가 없을 때 공통 흐름을 계속하는 실행기 테스트
  • 즉시 판정(대기 없음) 테스트
  • 프런트 전체 테스트, 타입 검사, 확장프로그램 빌드

운영 원칙을 유지했음

  • 구조가 다른 필드는 추정 기입하지 않음
  • 공고별 변형은 정책의 선택 영역으로 격리
  • 지원서 저장·제출은 사용자만 수행
결론: “완벽히 같은 폼일 때만 작동”하던 구조에서, “안전하게 공통인 정보는 기입하고 나머지는 제외”하는 구조로 전환했음.
