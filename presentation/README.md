# 프로젝트 발표 자료

Career Form을 처음 접하는 크루에게 제품, 기술 책임과 팀의 작업 방식을 소개하는
20분 발표 자료다. 제품, 백엔드, 클라이언트와 소프트스킬을 네 발표자가 순서대로
담당한다. LLM 책임은 백엔드 구간에서 클라이언트와 백엔드의 경계와 함께 설명한다.

## 실행

`index.html`을 데스크톱 브라우저에서 연다. 화면 아래 제어를 사용해 발표한다.

- `←`, `→`: 이전 슬라이드와 다음 슬라이드
- `N 노트`: 현재 슬라이드의 발표자, 예상 시간, 대본과 근거 표시
- `F 전체화면`: 발표 모드 진입과 종료

## 발표 구간

| 구간 | 슬라이드 | 대본 시간 |
| --- | ---: | ---: |
| 제품 | 1-5 | 4분 55초 |
| 백엔드와 LLM | 6-9 | 4분 35초 |
| 클라이언트 | 10-13 | 4분 40초 |
| 소프트스킬과 AX | 14-17 | 4분 35초 |
| 합계 | 17장 | 18분 45초 |

남은 1분 15초는 발표자 전환과 화면 조작에 사용한다.

## 자동 검증

```bash
node --check presentation/deck.js
node --test presentation/deck.test.mjs
git diff --check
.venv/bin/python harness/scripts/verify.py
```

전용 테스트는 발표자 구간 순서, 대본 시간, 발표자 노트와 근거, 책임 주제 메타데이터,
슬라이드 이동 경계를 검증한다. 책임 주제 메타데이터는 발표에 필요한 내용이 어느
슬라이드에 배치됐는지 확인하는 지표이며, 문구의 정확성이나 청중의 이해를 증명하지
않는다.

## 사람 검증

- 16:9 전체화면에서 17장을 한 장씩 확인
- 의도하지 않은 겹침, 잘림, 넘침과 비정상 줄바꿈 확인
- 이전, 다음, 발표자 노트와 전체화면 제어 확인
- 네 발표자의 20분 리허설
- 발표 직전 구현 상태와 Wiki 정본의 변경 여부 확인
- 제품을 모르는 크루가 문제와 사용자 흐름을 이해하는지 확인

렌더링 검사용 이미지와 실제 지원서 정보, 계정 정보, 브라우저 상태는 저장소에
기록하지 않는다.
